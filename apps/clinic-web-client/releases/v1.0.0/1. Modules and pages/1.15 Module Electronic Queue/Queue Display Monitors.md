# Мониторы отображения электронной очереди

## Спецификация страницы интерфейса

* **Название:** Мониторы электронной очереди (табло)
* **Модуль:** Электронная очередь (Electronic Queue Module)
* **Тип:** публичные/полуслужебные экраны на физических устройствах, без обычного пользователя за клавиатурой
* **Маршрут:** `/electronic-queue` — экран ввода одноразового кода привязки, затем сразу отображение панелей, набор которых заранее задал администратор, см. ниже
* **Статус документа:** Актуализировано (**состав монитора ограничен тремя режимами — одна точка на стенде / один или несколько кабинетов / одно окно, смешивать нельзя; макет — основная область «номер → окно/кабинет» + правая боковая панель ожидающих; добавлен сквозной путь устройства от создания записи до работы**; ранее: привязка устройства и выбор отображаемых панелей перенесены на `1.9.7. Reception and Queues Page` — на самом устройстве остался только ввод одноразового кода; статический общеклиничный код доступа и выбор точек/окон на экране монитора упразднены)

> Талоны, которые появляются на этих мониторах, выдаёт `Kiosk Ticket Issue Page.md` (в этой же папке) — оба документа вместе покрывают весь путь номера-бюллетеня. Создание записи монитора, состав отображаемых панелей и получение кода привязки — на `1.9.7. Reception and Queues Page`, раздел «Мониторы» (Flow 8, Flow 9); этот документ описывает только экран самого физического устройства.

## Общий принцип: одна панель = одна подписка, состав монитора — один из трёх режимов

Единица подписки — как и раньше, одна из двух:

| Единица подписки | Что показывает | Где физически применяется |
|---|---|---|
| **Точка очереди целиком** | Все активные талоны точки — кто вызван (на какое окно/в какую комнату) и кто ещё ждёт | Общая панель зоны ожидания регистратуры |
| **Одно окно** | Только то, что вызвано на это конкретное окно | Панель у конкретного окна регистратуры **или** у двери кабинета врача |

Но состав монитора — не произвольный набор: он должен соответствовать **одному из трёх режимов**, смешивать режимы на одном мониторе нельзя (режим определяется автоматически по составу панелей):

| Режим | Состав | Типичное место |
|---|---|---|
| **Точка очереди (стенд)** | ровно **одна** точка очереди на стенде целиком | зона ожидания регистратуры (общее табло на все окна точки) |
| **Кабинеты** — `rooms` | **одна или несколько** точек очереди в кабинетах | коридор с несколькими кабинетами врачей и одним монитором |
| **Одно окно** | ровно **одно** окно (любой точки) | экранчик у конкретного окна регистратуры или у двери кабинета |

**Нельзя:** точку на стенде вместе с кабинетами; точку целиком вместе с отдельным окном; несколько точек на стендах; несколько окон. (Кабинеты с кабинетами — можно.) Если нужно показывать и регистратуру, и кабинеты — это два разных монитора. Отдельный механизм «табло кабинета врача» по-прежнему не нужен: приём врача — это точка очереди в кабинете с единственным окном.

Панель точки-кабинета технически ничем не отличается от панели точки на стенде, кроме того, **что** и **как** она показывает (см. «Словесная форма и имя сотрудника»).

Общее для всех мониторов и панелей:

- крупная, читаемая издалека типографика — уличная/холльная, а не интерфейс рабочего стола;
- живое обновление без перезагрузки страницы и без действий пользователя;
- устройство работает без единого простоя месяцами — экран должен быть устойчив к разрывам сети и не «зависать» в устаревшем состоянии (см. «Состояния и edge cases»).

## Табло очереди

**Путь устройства от коробки до работы** (одинаков для монитора и киоска):

1. Администратор на `1.9.7` создаёт запись монитора, **задаёт состав панелей** (точки и/или окна/кабинеты) и получает **одноразовый 4-значный код привязки** (Flow 8). Пока устройство не привязано, запись в статусе «Ожидает привязки».
2. На физическом устройстве открывается `/electronic-queue` → экран ввода кода (см. ниже).
3. Верный код → статус записи «Подключено», устройство сразу показывает все назначенные панели. Дальнейшие перезагрузки экран кода пропускают.
4. Состав панелей правится на `1.9.7` в любой момент без повторной привязки; замена устройства или отзыв доступа — перевыпуск кода (Flow 9), и устройство снова показывает экран ввода кода.

Устройство — обычно старый монитор/планшет, один раз настроенный и годами висящий на стене без участия сотрудника, поэтому у страницы нет привычного логина сотрудника: она настраивается один раз при первой привязке и дальше запоминает себя сама.

### Привязка при первом включении

Один экран-шаг показывается только один раз (до отзыва доступа администратором) — дальше страница сразу открывает табло с уже готовым набором панелей. Страница сама не знает, привязано ли устройство: при каждой загрузке она пробует открыть табло и, только если доступа нет, показывает экран ввода кода.

**Экран ввода кода привязки.** Один крупный элемент по центру: поле ввода 4-значного кода (буквы и цифры, регистр важен) + кнопка «Подтвердить». Заголовок поясняет: «Введите код, полученный от администратора клиники». Код — не пароль сотрудника и не общий код на всю клинику: это одноразовый код, привязанный к конкретной, заранее созданной записи монитора на `1.9.7` — тот, кто настраивает физическое устройство, получает этот код от администратора клиники (экран показывает его на `1.9.7` при создании/перевыпуске). Экран монитора код не подсказывает и не имеет ссылки «забыли код» — новый код можно получить только на `1.9.7`.

- Верный код → устройство получает доступ и сразу показывает весь набор панелей, заранее назначенный этой записи монитора администратором. **Набор панелей на этом экране не выбирается** — в отличие от ревизии до этой, где после кода шёл отдельный шаг с деревом чекбоксов; теперь состав отображаемых точек/окон полностью задаётся на `1.9.7` (Flow 8) и редактируется там же в любой момент, без повторной привязки устройства.
- Неверный код → инлайн-ошибка «Код неверный», попытку можно повторить сразу; после нескольких быстрых неудачных попыток подряд — короткая задержка перед следующей попыткой (клиентская защита поверх серверного rate limiting).
- Истёкший код → отдельная инлайн-подсказка «Код истёк — обратитесь к администратору клиники за новым кодом»; монитор не может запросить новый код сам.

При следующих перезагрузках устройства страница сразу открывает табло, минуя экран ввода кода. Если администратор отзывает доступ (перевыпуском кода той же записи монитора или её удалением, `1.9.7` Flow 9) — устройство теряет доступ, и страница возвращается к экрану ввода кода.

### Словесная форма и имя сотрудника

То, как панель называет место вызова, и показывает ли она имя сотрудника, определяется **не настройкой монитора**, а тем, к чему привязана конкретная точка очереди этой панели — готовые значения определяются для каждой панели отдельно, монитор их не вычисляет:

- точка на **стенде** → «Окно N» (пример: «Номер 40, подойдите к окну 2»), имя сотрудника **не** показывается;
- точка в **кабинете** → «Комната N» (пример: «Номер 40, пройдите в комнату 201»), **дополнительно** показывается имя и должность сотрудника, занявшего окно (обычно единственное) этой точки — например, «Иванов И. И., терапевт»; если окно сейчас никем не занято — блок с именем скрыт, показывается только «Комната 201».

Панели одного монитора могут свободно смешивать оба варианта — например, общая панель регистратуры (стенд, «окно») рядом с выделенной панелью кабинета врача (кабинет, «комната» + имя).

### Панель в масштабе «точка очереди целиком»

Содержимое панели точки: кто уже вызван (и на какое окно/в какую комнату) и кто ещё ждёт; на экране вызванные попадают в основную область, ожидающие — в правую боковую панель (см. «Макет экрана по режимам»). Самый свежий вызов выделен крупнее остальных (размер, цвет, короткая анимация появления), чтобы его было легко заметить боковым зрением; формат — «номер талона → окно/комната». Ниже — остальные активные талоны (история из нескольких предыдущих вызовов и текущие ожидающие).

**Из списка исчезают** номера уже вызванных (обслуживающихся) и уже обслуженных талонов — на панели всегда видно только то, что ещё актуально: кто вызван прямо сейчас (в списке последних вызовов) и кто продолжает ждать. Это отражает то, как несколько окон одной точки разбирают общую очередь — талон, который уже взяло любое из окон, не показывается как «ожидающий».

**Повторный вызов.** Если пациент не подошёл и его вызывают повторно — визуальный акцент на повторном вызове (например, пульсация номера), чтобы отличить от первого появления.

### Панель в масштабе «одно окно»

**Пусто (окно ожидает вызова).** Нейтральное состояние: место (окно/комната) и, если это комната, имя сотрудника — плюс надпись вроде «Ожидание вызова» — не пустая панель, чтобы она не выглядела выключенной или сломанной.

**Талон вызван.** Крупно — номер талона, вызванного именно на это окно/в эту комнату («Талон A-014»). Появление номера — тот же акцентный эффект, что и на панели точки очереди.

**Обслуживание завершено.** Как только сотрудник закрывает визит по этому талону (или отмечает неявку), панель автоматически возвращается в состояние «Ожидание вызова» — без действия со стороны самого монитора.

**Смена сотрудника (масштаб «комната»).** Если сотрудник, занимавший окно, освободил его (закончил приём/смену) и на его место заступил другой (или окно временно осталось никем не занято) — имя на панели обновляется автоматически, тем же плавным переходом, что и смена статуса (см. «Взаимодействие и анимация»); монитору не нужно ничего запрашивать заново — обновление приходит тем же SSE-потоком.

### Макет экрана по режимам

Макет определяется режимом монитора, а не числом панелей. Во всех режимах с очередью принцип один: **основная область — кто куда вызван; правая боковая панель — ожидающие.** Боковая панель занимает около четверти–трети ширины экрана и всегда справа; основная область — всё остальное. На портретно ориентированном мониторе боковая панель переезжает вниз узкой полосой (та же логика, другая ось).

**Режим «Точка очереди (стенд)»**

```
┌──────────────────────────────────────────────┬─────────────────┐
│  ВЫЗЫВАЕТСЯ                                  │  ОЖИДАЮТ  (7)   │
│                                              │                 │
│    A-014   →   ОКНО 2          ← крупно,     │   A-016         │
│                                  акцент      │   A-017         │
│  Недавние вызовы                             │   A-018         │
│    A-013   →   Окно 1                        │   A-019         │
│    A-012   →   Окно 3                        │   A-020         │
│                                              │   … ещё 2       │
└──────────────────────────────────────────────┴─────────────────┘
```

- **Основная область.** Вверху — самый свежий вызов, крупно, в формате «номер → окно» с акцентной анимацией появления; ниже — предыдущие вызовы (3–5 строк, «номер → окно»), которые ещё актуальны: талон исчезает из списка, как только он обслужен или отмечен неявкой. Повторный вызов — пульсация номера.
- **Боковая панель «Ожидают».** Номера талонов со статусом «Ожидает» в порядке очереди (FIFO — как они будут вызываться). Без указания окна: окно назначается в момент вызова. Заголовок — «Ожидают» и счётчик всех ожидающих; если номера не помещаются — последняя строка «… ещё N». Первый в очереди может быть выделен слегка (следующий на вызов), но без конкуренции с акцентом основной области.
- Источник данных — панель точки: все ожидающие и вызванные талоны точки; у вызванных показано окно, у ожидающих — нет.

**Режим «Кабинеты» — `rooms`** (один или несколько кабинетов на одном мониторе)

```
┌──────────────────────────────────────────────┬──────────────────────────┐
│ ┌───────────────────┐ ┌───────────────────┐  │  ОЖИДАЮТ  (5)            │
│ │ КОМНАТА 201       │ │ КОМНАТА 203       │  │                          │
│ │ Иванов И. И.,     │ │ Петрова А. С.,    │  │  A-016 → Комната 201     │
│ │ терапевт          │ │ невролог          │  │         Иванов И. И.     │
│ │                   │ │                   │  │  B-004 → Комната 203     │
│ │     A-014         │ │ Ожидание вызова   │  │         Петрова А. С.    │
│ └───────────────────┘ └───────────────────┘  │  A-017 → Комната 201     │
│ ┌───────────────────┐                        │         Иванов И. И.     │
│ │ КОМНАТА 205 …     │                        │  …                       │
│ └───────────────────┘                        │                          │
└──────────────────────────────────────────────┴──────────────────────────┘
```

- **Основная область — карточки кабинетов, по одной на кабинет.** В карточке: «Комната N» и по строке на каждого врача, занявшего окно кабинета: имя и должность врача и **номер, вызванный к нему**, либо «Ожидание вызова». Если в кабинете работают несколько врачей, строк несколько, каждый номер подписан своим врачом. Сетка карточек: 1 кабинет — карточка во весь экран; 2 — рядом; 3–4 — 2×2; 5–6 — 3×2; порядок — тот, в котором администратор отметил кабинеты на `1.9.7`. Кабинет без врача не исчезает с экрана — показывается «Комната N — Ожидание вызова».
- **Боковая панель «Ожидают» — единый список «номер → кабинет / врач».** Каждая строка — один ожидающий талон: номер, затем кабинет («Комната 201») и врач, к которому идёт пациент («Иванов И. И.»; для талона без врача — без имени). Порядок строк — общий по времени выдачи талонов; талоны разных кабинетов и врачей перемешаны, различаются подписью. Заголовок — «Ожидают» и счётчик всех ожидающих; если строки не помещаются — последняя строка «… ещё N». Нет ожидающих — «Нет ожидающих».
- Очереди кабинетов независимы: номер принадлежит одному кабинету и появляется ровно в его карточке (когда вызван) и в одной строке списка (пока ожидает).
- Источник данных — панели точек-кабинетов (место и сотрудник кабинета, ожидающие и вызванные талоны); список «Ожидают» собирается из ожидающих талонов всех панелей и сортируется по времени выдачи.
- Более ~6 кабинетов — допустимо, но кегль уменьшается; тогда администратору имеет смысл разнести кабинеты на два монитора.

**Режим «Одно окно»**

Один крупный номер на весь экран, без боковой панели (окно не несёт списка ожидающих — только текущий вызванный номер): сверху место («Окно 2» / «Комната 201» с именем и должностью, если кабинет), по центру — вызванный номер или «Ожидание вызова». После завершения обслуживания — плавный возврат в «Ожидание вызова».

**Режим «Пусто» — `empty`:** «Нет панелей для отображения» на весь экран.

Общее для всех режимов:

- обновление живое; каждый блок (вызов, карточка кабинета, группа ожидающих) обновляется независимо — вызов не перерисовывает соседей;
- звуковой сигнал (если включён на устройстве) — один на любое новое событие `ticket.called`, без отдельных звуков по кабинетам;
- перетаскивание/произвольная расстановка на устройстве вне рамок; состав и порядок задаются только на `1.9.7`;
- **смесь режимов невозможна по построению:** система не сохранит монитор, состав которого не укладывается в режим (форма `1.9.7` блокирует несовместимый выбор заранее, Flow 8).

### Сброс привязки устройства

Отдельного видимого элемента интерфейса для сброса нет — экран не должен провоцировать случайные нажатия проходящих мимо людей. Сброс (например, при физической замене устройства) — скрытое действие (долгое нажатие в углу экрана или комбинация клавиш), которое показывает экран ввода кода привязки. Сама запись монитора и назначенный ей набор панелей при этом не меняются — новое физическое устройство привязывается к той же записи тем же кодом (после перевыпуска на `1.9.7`, если прежний код уже был погашен) и сразу получает тот же набор панелей, без необходимости настраивать их заново.

**Изменить набор отображаемых панелей** (без замены устройства) — не действие на этой странице вовсе: администратор редактирует состав на `1.9.7` (Flow 8, п.4), уже привязанное устройство подхватывает новый набор само при следующем переподключении потока (см. «Технические детали» ниже) — специально ради этого на экране монитора нет и не должно быть отдельного пункта «изменить панели».

## Состояния и edge cases

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | Скелетон на месте всех панелей, пока данные подгружаются |
| Пусто (боковая панель «Ожидают») | «Нет ожидающих» — не путать с ошибкой |
| Пусто (основная область / карточка кабинета / окно) | «Ожидание вызова» |
| Ошибка загрузки | Сообщение об ошибке с возможностью повторить (для всего экрана — соединение общее на все панели) |
| Нет связи | Экран-заглушка «Сервис временно недоступен» поверх всех панелей — монитор не должен молча зависать на устаревших данных ни на одной из них |
| Повторный вызов (панель точки) | Визуальный акцент, отличающий от первого появления номера |
| Смена сотрудника (панель окна, точка-кабинет) | Имя на панели обновляется плавным переходом, не должно выглядеть сбоем |
| Первый запуск / сброс / отзыв доступа | Один экран — ввод кода привязки; после успеха сразу обычный показ, без отдельного шага выбора панелей |
| Код неверный | Инлайн-ошибка «Код неверный», без раскрытия причины сверх этого |
| Код истёк | Отдельная инлайн-подсказка «Код истёк — обратитесь к администратору клиники за новым кодом» |
| Администратор сменил состав так, что изменился режим (например, был один кабинет, стало несколько; или со стенда на кабинеты) | После переподключения потока (`state` с новым `mode`) экран перестраивается целиком под новый макет — без действий на устройстве |
| Монитор привязан, но панели ещё не назначены администратором | «Нет панелей для отображения» на весь экран — не ошибка привязки/соединения, а состояние конфигурации |
| Одна из назначенных точек/окон удалена администратором | Эта конкретная панель показывает «Точка/окно больше не существует», остальные панели продолжают работать как обычно |

## Interaction & Animation

- Все панели обновляются сами, без перезагрузки экрана; обновление одной панели не затрагивает соседние.
- Новый вызов появляется с коротким акцентным эффектом (увеличение/цвет) и держится заметным дольше, чем остальные строки истории (панель точки) или до следующего события (панель окна).
- Переход «вызван → ожидание» на панели окна — плавное затухание, без резкого исчезновения.
- Смена имени сотрудника на панели-«комнате» — плавный переход между значениями, без резкой смены (тот же паттерн, что смена статуса/карточки).

## Зависимости и ограничения

- Табло очереди (в любом из трёх режимов, включая кабинеты врачей) — единственный клиент Electronic Queue Module среди мониторов; отдельного клиента для «приёма врача» не существует.
- Запись монитора, код привязки и состав отображаемых панелей администрируются на `1.9.7. Reception and Queues Page` — не на самом устройстве.
- Физическое размещение точки очереди на карте клиники (стенд или кабинет, `1.9.7`) не связано с этой страницей и не влияет на её работу напрямую — карта только определяет, где стоит монитор и какую словесную форму использовать (см. «Словесная форма и имя сотрудника»). Отдельно от этого, сам монитор как устройство тоже может быть размещён на карте (`1.9.7`, Flow 8) — это два независимых размещения: точки очереди (влияет на словесную форму вызова) и монитора (чисто навигационное, для администратора).
- Состав монитора задаётся администратором на `1.9.7`, не на самом устройстве, и ограничен тремя режимами: точка на стенде / кабинеты / одно окно; смесь режимов сервер не сохранит. Число кабинетов в режиме «Кабинеты» интерфейсом не ограничено, но при большом числе кегль уменьшается — макет не должен рассчитывать на бесконечно малый размер карточки (ориентир — не более 6).

## Acceptance criteria

1. Состав монитора — один из режимов: одна точка на стенде, один или несколько кабинетов, одно окно; смешивать нельзя (точка на стенде + кабинет, точка + окно, несколько точек на стендах, несколько окон). Состав назначен администратором на `1.9.7`, не выбирается на самом устройстве.
1a. Режим «Кабинеты»: основная область — карточка на каждый кабинет («Комната N» и строки по врачам: имя, должность, вызванный к врачу номер либо «Ожидание вызова»); кабинет без врача остаётся на экране.
1b. Макет режимов «Точка (стенд)» и «Кабинеты»: основная область — какой номер вызван к какому окну/в какой кабинет; правая боковая панель — ожидающие (в режиме «Кабинеты» — единый список «номер → кабинет / врач»). Режим «Одно окно» — один номер на весь экран без боковой панели.
2. Основная область показывает вызванные талоны (самый свежий — крупно, с акцентом; повторный вызов отличим от первого), боковая панель — ожидающие в порядке очереди; уже вызванные/обслуженные номера не остаются в списке ожидающих.
3. Панель окна показывает только вызовы своего окна; словесная форма («окно»/«комната») и имя сотрудника (только для «комнаты») приходят готовыми полями с сервера на каждую панель отдельно, фронт их не вычисляет.
4. При первом запуске (после сброса или отзыва доступа) устройство показывает единственный экран — ввод кода привязки; после успеха сразу отображаются все назначенные панели, без промежуточного шага выбора; при повторных запусках экран кода пропускается.
5. Неверный и истёкший код дают разные, понятные инлайн-сообщения; сразу после успешной привязки все панели немедленно показывают текущее состояние, не дожидаясь следующего события; вызовы, завершение обслуживания и смена занявшего окно сотрудника отражаются автоматически и независимо по каждой панели.
6. Разрыв единого соединения не оставляет ни одну панель в замороженном/устаревшем состоянии — либо восстановление автоматически, либо явное «Нет связи» поверх всех панелей.
7. Удаление одной из назначенных точек/окон администратором не ломает остальные панели монитора.
8. Изменение состава панелей администратором на `1.9.7` отражается на уже привязанном устройстве без каких-либо действий на самом устройстве — самое позднее при следующем автоматическом переподключении потока.
9. Отзыв доступа администратором (перевыпуск кода/удаление монитора) возвращает устройство к экрану ввода кода при следующем обращении к серверу.
