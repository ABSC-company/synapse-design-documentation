# Global Header

## Описание компонента

**Global Header** — глобальная панель навигации системы, расположенная в верхней части интерфейса и отображаемая на всех страницах приложения.

Компонент предназначен для:

- отображения текущего местоположения пользователя в системе;
- быстрого поиска ЭМК пациентов;
- доступа к уведомлениям;
- перехода в профиль пользователя;
- управления боковым меню приложения.

---

## Структура компонента

Компонент состоит из следующих элементов:

---

## Кнопка управления Sidebar

Расположена в левой части Header рядом с логотипом системы.

### Поведение

1. При нажатии открывает Sidebar, если он скрыт.
2. При повторном нажатии сворачивает Sidebar.
3. Состояние Sidebar сохраняется до изменения пользователем.

---

## Breadcrumb Navigation

Расположена после кнопки Sidebar.

Предназначена для отображения текущего пути пользователя внутри системы.

### Формат отображения

Главная → Раздел → Подраздел → Текущая страница

### Поведение

1. Все промежуточные элементы являются ссылками.
2. Текущая страница отображается как активный элемент.
3. При переходе между страницами Breadcrumb обновляется автоматически.

### Пример

Главная → Регистратура → Визиты

---

## Глобальный поиск ЭМК

Расположен в правой части Header.

Предназначен для быстрого поиска пациентов и перехода в их ЭМК.

### Task Flow

#### Этап 1. Ввод поискового запроса

Пользователь вводит поисковый запрос.

Поддерживаемые типы поиска:

- Ф.И.О пациента
- ID пациента
- PINFL
- номер телефона
- номер документа
- FaceID
- MRZ

---

#### Этап 2. Выполнение поиска

Поиск выполняется автоматически с использованием дебаунсинга.

---

#### Этап 3. Отображение результатов

Отображается выпадающий список найденных пациентов.

Для каждого результата:

- Ф.И.О пациента
- идентификатор пациента
- дата рождения
- фотография пациента (если есть)

---

#### Этап 4. Переход в ЭМК

При выборе пациента открывается его электронная медицинская карта.

---

## Центр уведомлений

Расположен справа от строки поиска.

Предназначен для отображения уведомлений пользователя (сотрудника), связанных с бизнес-процессами клиники и работой самой системы: задачи, документы, визиты, исследования, электронная очередь, файлы, действия других пользователей. Пароли, коды подтверждения и уведомления пациентов в Центре уведомлений не показываются — они приходят вне приложения.

---

## Индикатор непрочитанных уведомлений

- Если есть непрочитанные уведомления, в иконке отображается **красный кружок** (без числа)
- Индикатор исчезает, когда все уведомления прочитаны
- Индикатор появляется сразу, как только приходит новое уведомление — без перезагрузки страницы

---

## Дропдаун уведомлений

Открывается при клике на иконку уведомлений.

### Структура

#### Список уведомлений

Отображает последние уведомления пользователя.

Каждое уведомление содержит:

- тип уведомления
- краткое описание
- дата и время
- статус (прочитано / не прочитано)
- ссылка на связанный объект (если есть)

Непрочитанные уведомления визуально выделяются.

---

### Поведение

- Список подгружается порциями по мере прокрутки вниз
- Непрочитанное уведомление становится прочитанным, когда пользователь пролистал список и оно попало в видимую область (выделение непрочитанного плавно гаснет); если до него не дошли прокруткой — оно остаётся непрочитанным
- При клике на уведомление выполняется переход к связанному объекту, уведомление сразу помечается прочитанным
- Изменения статуса происходят без перезагрузки

---

### Кнопка «Отметить все как прочитанные»

Расположена в шапке дропдауна (справа от заголовка «Уведомления»), текстовая кнопка.

#### Поведение

- Нажатие помечает прочитанными **все** непрочитанные уведомления пользователя сразу, не только загруженные в список
- Выделение непрочитанных гаснет у всех строк, красный кружок на колокольчике скрывается
- Кнопка неактивна (disabled), если непрочитанных уведомлений нет, и во время выполнения действия
- Подтверждение не запрашивается; при ошибке показывается сообщение «Не удалось отметить уведомления», статусы возвращаются как были

---

### Нижняя кнопка drop down

Содержит кнопку:

- **Посмотреть все уведомления**

#### Поведение

- Открывает driver-компонент (drawer)
- Закрывает dropdown

---

## Driver-компонент уведомлений

Выезжающая панель со всеми уведомлениями и фильтрацией.

---

### Заголовок

- Уведомления
- Справа — кнопка **«Отметить все как прочитанные»**: помечает прочитанными все непрочитанные уведомления **выбранной вкладки** (на вкладке «Все уведомления» — все). Поведение и состояния — как у кнопки в дропдауне

---

### Tabs (вкладки)

- Все уведомления
- Системные
- Файлы
- Исследования
- Электронная очередь

---

### Поведение tabs

- Фильтрация уведомлений по типу
- «Все уведомления» показывает полный список
- Переключение вкладок не сбрасывает статус прочитанности
- Обновление данных без перезагрузки

---

## Общая логика уведомлений

- Непрочитанные уведомления сохраняют статус, пока пользователь не увидел их при прокрутке списка или не перешёл по ним
- Просмотр уведомления в списке или переход по нему делает его прочитанным
- После прочтения всех уведомлений индикатор скрывается
- Статус синхронизируется между dropdown, driver-компонентом и другими открытыми вкладками
- Если новые уведомления приходят, пока пользователь прокрутил список вниз, сверху появляется плашка «Новые уведомления»; список при этом не «прыгает»

|---|---|
| Загрузка | Заглушки (skeleton) строк списка; при подгрузке следующей порции — индикатор внизу списка |

## Профиль пользователя

Расположен справа в Header.

Отображает:

- аватар пользователя (фотография сотрудника; если фото нет — круг с инициалами)
- статус присутствия

### Поведение

- Клик по аватару открывает меню пользователя (дропдаун под аватаром)
- Повторный клик, клик вне меню или `Esc` закрывают меню

---

## Меню пользователя

В верхней части — карточка: аватар, ФИО, должность и отдел.

Пункты меню:

- **Профиль** — открывает модальное окно «Профиль» (личные данные)
- **Настройки** — открывает модальное окно «Настройки» (вкладки «Уведомления» и «Вход в систему»)
- **Язык** — переключение языка интерфейса
- **Выйти** — выход из системы

Пункты «Профиль» и «Настройки» доступны любому авторизованному сотруднику; отдельных прав не требуется.

---

## Модальное окно «Профиль» (личные данные)

Открывается из меню пользователя. Заголовок «Профиль», кнопка закрытия (✕) справа.

### Структура

Две зоны:

1. **Только для просмотра** (поля серые, без возможности правки; подсказка «Эти данные изменяет отдел кадров»):
   - фотография (только отображение; сотрудник сам фото не меняет)
   - ФИО
   - дата рождения
   - пол
   - гражданство
   - филиал, отдел, должность
   - тип занятости (сотрудник / врач)
2. **Редактируемые поля**:
   - контакты: список «тип — значение» (телефон, email) с кнопками «Изменить» / «Удалить» и «+ Добавить контакт»; обязателен минимум один телефон
   - страна проживания, регион, адрес
   - семейное положение

```

│ Профиль                                    ✕ │
├──────────────────────────────────────────────┤
│  (фото)  Иванов Иван Иванович                │
│          Врач · Терапия · Терапевт           │
│                                              │
│  Только для просмотра (изменяет отдел кадров)│
│  Дата рождения  12.03.1985   Пол  Мужской    │
│  Гражданство    UZB          Филиал  Главный │
│                                              │
│  Контакты                       [+ Добавить] │
│  Телефон   +998 90 123 45 67      ✎  🗑      │
│  Email     ivanov@clinic.uz       ✎  🗑      │
│                                              │
│  Страна [Узбекистан ▾]  Регион [Ташкент ▾]   │
│  Адрес  [__________________________________] │
│  Семейное положение [Женат ▾]                │
├──────────────────────────────────────────────┤
│                      [Отмена]  [Сохранить]   │
└──────────────────────────────────────────────┘
```

### Поведение

- «Сохранить» активна, только если что-то изменилось и все поля валидны; после сохранения окно закрывается, показывается «Данные профиля сохранены»
- Изменение контактов применяется вместе с остальными полями по кнопке «Сохранить»
- «Отмена» и ✕ при несохранённых изменениях спрашивают «Закрыть без сохранения?»
- Валидация: телефон — международный формат, email — корректный адрес, последний телефон удалить нельзя (подсказка «Должен остаться хотя бы один номер телефона»); ошибки показываются под полем

### Состояния

| Состояние | Что видит пользователь |
|---|---|
| Загрузка данных | Заглушки (skeleton) вместо полей |
| Ошибка загрузки | «Не удалось загрузить профиль» и кнопка «Повторить» |
| Сохранение | Кнопка «Сохранить» с индикатором, поля недоступны |
| Ошибка сохранения | Сообщение под соответствующим полем или общее «Не удалось сохранить», введённые данные не теряются |

## Модальное окно «Настройки»

Открывается из меню пользователя. Заголовок «Настройки». Вверху — вкладки (tabs), содержимое переключается без закрытия окна:

- **Уведомления**
- **Вход в систему**

### Вкладка «Уведомления»

Назначение: выбрать, по каким каналам получать **важные системные уведомления** (новый пароль, коды подтверждения). Уведомления о работе в системе (задачи, документы, визиты и т. д.) приходят в Центр уведомлений (колокольчик в Header) всегда — отключить их нельзя; на вкладке это поясняется текстом.

Элементы:

- переключатели (чекбоксы) каналов: **SMS**, **Email**, **Telegram** — можно выбрать один или несколько; по умолчанию SMS; хотя бы один канал должен быть выбран
- рядом с каждым каналом — адрес доставки: номер телефона, email (из контактов профиля), статус Telegram
- **Email** недоступен, если в профиле нет email: переключатель неактивен, подсказка «Добавьте email в профиле» (ссылка открывает окно «Профиль»)
- **Telegram**: если не привязан — переключатель неактивен, показаны статус «Не привязан», кнопка «Открыть бота» и краткая инструкция («Откройте бота и отправьте свой номер телефона»); после привязки статус меняется на «Привязан» без перезагрузки страницы
- кнопка «Сохранить»

```
│  [ Уведомления ]  Вход в систему             │
│                                              │
│  Уведомления о работе в системе приходят в   │
│  Центр уведомлений (🔔) — отключить нельзя.  │
│                                              │
│  Важные уведомления (пароли, коды) получать: │
│  ☑ SMS       +998 90 123 45 67               │

│  ☐ Telegram  Не привязан   [Открыть бота]    │
├──────────────────────────────────────────────┤
│                              [Сохранить]     │
└──────────────────────────────────────────────┘
```

### Вкладка «Вход в систему»

Назначение: смена пароля.

Элементы:

- «Текущий пароль»
- «Новый пароль» (показывается подсказка с требованиями политики паролей)
- «Подтвердите новый пароль»
- у каждого поля — кнопка показать/скрыть пароль
- кнопка «Сменить пароль» (неактивна, пока поля не заполнены корректно)

Поведение:

- новый пароль не должен совпадать с текущим; подтверждение должно совпадать с новым
- при неверном текущем пароле ошибка показывается под полем «Текущий пароль»
- при успехе — сообщение «Пароль изменён», поля очищаются; если система завершила текущую сессию, пользователь возвращается на страницу входа

### Состояния

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | Заглушки вместо переключателей каналов |
| Ошибка загрузки | «Не удалось загрузить настройки» и кнопка «Повторить» |
| Сохранение | Индикатор на кнопке, элементы недоступны |
| Ошибка сохранения | Сообщение над кнопкой; выбранные значения не сбрасываются |

## Сценарии блокировки

### Отсутствие доступа к ЭМК

1. Поиск показывает пациента
2. При попытке открытия отображается ошибка прав доступа
3. Переход в ЭМК не выполняется

---

### Отсутствие соединения

1. Поиск блокируется
2. Показывается ошибка соединения
3. После восстановления доступ возвращается автоматически
