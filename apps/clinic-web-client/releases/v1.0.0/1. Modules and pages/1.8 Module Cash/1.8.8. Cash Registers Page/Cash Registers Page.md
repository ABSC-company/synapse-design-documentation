# 1.8.8 Cash Registers Page (Кассы)

## Спецификация страницы интерфейса

* **Название страницы:** Кассы
* **Модуль:** Cash Register
* **Тип страницы:** Реестр (таблица)
* **Основные роли:** Старший кассир/Администратор
* **Маршрут:** `/cash-register/registers`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Общие паттерны (реестр, статус-бейдж, состояния) — см. `1.8.0.3. Cash Register Overview`. Техническая реализация — во frontend-документе `1.8.1. Cash Registers Page`.

---

## Назначение страницы и сценарии использования

Простой реестр физических касс клиники (кассовых мест, за которыми открываются смены). CRUD без сложной бизнес-логики — единственное содержательное правило: кассу с открытой сменой удалить нельзя.

С помощью страницы пользователь может:

1. Просматривать список касс с признаком, открыта ли по ней сейчас смена.
2. Создавать/переименовывать/удалять кассы.
3. Переходить к сменам конкретной кассы (на `1.8.9`, предзафильтровано).

---

## User Flows / Task Flows

### Flow 1. Просмотр списка

1. Пользователь открывает «Кассы».
2. Таблица показывает все кассы; строки с открытой сменой помечены бейджем «Смена открыта».

### Flow 2. Создание кассы

1. Пользователь нажимает «+ Добавить кассу».
2. Вводит название.
3. Сохраняет → касса появляется в списке без открытой смены.

### Flow 3. Переименование

1. Пользователь нажимает «✏» в строке.
2. Меняет название инлайн или в модалке.
3. Сохраняет.

### Flow 4. Удаление

1. Пользователь нажимает «✕»/«Удалить» в строке.
2. Если по кассе открыта смена — действие недоступно (disabled, тултип «Нельзя удалить кассу с открытой сменой»), запрос не отправляется.
3. Если смены нет — подтверждающее окно → удаление.

### Flow 5. Переход к сменам кассы

1. Клик по строке (вне действий) → переход на `1.8.9` с фильтром по этой кассе.

## Визуал: High-Fidelity mockups

1. Компактная таблица, без лишних колонок — на странице только то, что нужно для управления кассами как физическими точками.
2. Disabled-кнопка удаления визуально приглушена, но не скрыта — пользователь должен видеть, что действие существует, но недоступно, и почему (тултип).
3. Единая дизайн-система модуля.

## Состояния и edge cases

### Empty

«Касс пока нет» + «+ Добавить кассу».

### Loading

Скелетон строк таблицы.

### Error

Блок ошибки + «Повторить» (список); toast (действия).

### Permissions

Нет `CASH_REGISTER_GET` — раздел недоступен. Нет `CASH_REGISTER_MANAGE` — кнопки создания/редактирования/удаления скрыты, таблица read-only.

### Edge cases

* Попытка удалить кассу с открытой сменой — заблокирована на UI (disabled) и дополнительно отклоняется сервером (`409 CASH_REGISTER_HAS_OPEN_SHIFT`) — защитный второй рубеж, не основной путь.
* Название кассы не уникально на уровне UI-валидации (бэкенд не описывает ограничение уникальности) — дублирующиеся названия допустимы, различать кассы можно по факту открытой смены/истории.

## Interaction & Animation

* Открытие модалки создания/редактирования — fade+scale.
* Удаление — подтверждение, затем fade-out строки.
* Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Кассы не привязаны к филиалу/отделу на уровне модели (см. `CashRegisterModule.md` §4.1) — реестр общий для всей клиники, без фильтра по филиалу.
* Удаление — только без активной смены.

### Роли / права

| Действие | Право |
|---|---|
| Просмотр реестра | `CASH_REGISTER_GET` |
| Создание/редактирование/удаление | `CASH_REGISTER_MANAGE` |

---

## Acceptance criteria

* Таблица показывает название и статус (открыта/свободна) каждой кассы.
* Создание/переименование кассы — через модалку с обязательным названием.
* Удаление недоступно (disabled + тултип), пока по кассе открыта смена.
* Клик по строке ведёт на «Смены и отчёты» с фильтром по этой кассе.
* Состояния empty/loading/error/permissions обработаны.
