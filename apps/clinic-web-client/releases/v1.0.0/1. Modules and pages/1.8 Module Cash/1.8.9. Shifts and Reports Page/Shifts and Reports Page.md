# 1.8.9 Shifts and Reports Page (Смены и отчёты)

## Спецификация страницы интерфейса

* **Название страницы:** Смены и отчёты
* **Модуль:** Cash Register
* **Тип страницы:** Реестр + карточка смены
* **Основные роли:** Кассир, Старший кассир/Администратор
* **Маршрут:** `/cash-register/shifts` (карточка — `/cash-register/shifts/:id`)
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.8.0.3. Cash Register Overview`, включая паттерн «Право кассира из регистратуры». Техническая реализация — во frontend-документе `1.8.2. Shifts and Reports Page`.

---

## Назначение страницы и сценарии использования

Реестр смен всех касс клиники и карточка отдельной смены со счетами/оплатами (только для чтения — сами счета и оплаты ведёт Payments module) и историей X/Z-отчётов. Отсюда же кассир открывает свою смену, передаёт её другому кассиру или закрывает.

С помощью страницы пользователь может:

1. Видеть список смен (текущих и исторических) по всем кассам.
2. Открыть смену на свободной кассе.
3. Передать открытую смену другому кассиру (с автоматическим X-отчётом).
4. Сформировать X-отчёт самостоятельно, без передачи.
5. Закрыть смену (с автоматическим Z-отчётом).
6. Просмотреть и скачать X/Z-отчёт (Excel/PDF).

---

## User Flows / Task Flows

### Flow 1. Открытие смены

1. Кассир нажимает «Открыть смену».
2. Выбирает свободную кассу (кассы с уже открытой сменой в списке выбора не показываются или помечены как занятые).
3. Подтверждает → смена создаётся в статусе «Открыта», кассир — текущий пользователь.
4. Если сервер отклонил с `403 CASHIER_NOT_ALLOWED` (сотрудник регистратуры без разрешённой настройки) — инлайн-ошибка «Недоступно для сотрудников регистратуры», модалка остаётся открытой.

### Flow 2. Передача смены

1. Кассир на открытой смене нажимает «Передать смену».
2. Выбирает нового кассира (поиск по ФИО среди сотрудников с правом быть кассиром).
3. Подтверждает → система формирует X-отчёт от имени прежнего кассира и сразу показывает его (не отдельным действием), затем `employee` смены меняется на нового кассира.

### Flow 3. Формирование X-отчёта без передачи

1. Кассир на открытой смене нажимает «Сформировать X-отчёт».
2. Подтверждает (без дополнительных полей) → отчёт формируется и открывается для просмотра/скачивания; смена остаётся открытой на том же кассире.

### Flow 4. Закрытие смены

1. Кассир нажимает «Закрыть смену».
2. Предупреждение: «После закрытия автоматически будет сформирован Z-отчёт. Действие необратимо».
3. Подтверждает → смена переходит в «Закрыта», Z-отчёт формируется автоматически и открывается для просмотра/скачивания.

### Flow 5. Просмотр карточки смены

1. Клик по строке смены → карточка: касса, кассир(ы), период, список счетов/оплат (read-only, из Payments module), список X/Z-отчётов смены.
2. Клик по отчёту в списке → открывает отчёт (просмотр сводки + кнопка «Скачать»).

## Состояния и edge cases

### Empty

Реестр смен — «Смен пока нет». Вкладка «Отчёты» карточки смены — «Отчётов пока нет» (возможно для только что открытой смены до первого X/Z).

### Loading

Скелетон таблицы/карточки; спиннер на кнопках действий (открытие/передача/закрытие/формирование отчёта); спиннер на «Скачать» на время подготовки файла.

### Error

Блок ошибки + «Повторить» (списки); toast (действия) — включая `403 CASHIER_NOT_ALLOWED` с явным текстом причины.

### Permissions

Нет `WORK_SHIFT_GET` — раздел недоступен. Нет `WORK_SHIFT_OPEN`/`TRANSFER`/`CLOSE` — соответствующие кнопки скрыты. Нет `CASH_REPORT_CREATE` — «Сформировать X-отчёт» скрыта. Нет `CASH_REPORT_DOWNLOAD` — «Скачать» скрыта, отчёт доступен только для просмотра сводки.

### Edge cases

* Попытка открыть смену на кассе, где уже есть открытая смена, — касса не предлагается в списке выбора (клиентское упреждение); сервер дополнительно отклоняет с `409 SHIFT_ALREADY_OPEN_ON_REGISTER`.
* Закрытие/передача/формирование X-отчёта для уже закрытой смены — кнопки недоступны на закрытой смене (сервер дополнительно отклоняет `409 SHIFT_NOT_OPEN`).
* Скачивание отчёта в неподдерживаемом формате — сервер отклоняет (`400 UNSUPPORTED_REPORT_FORMAT`); на UI выбор формата — фиксированный список из двух опций, ошибка практически недостижима штатным путём.

## Interaction & Animation

* Модалки действий — fade+scale.
* Переключение вкладок карточки смены — fade ~150 мс.
* Формирование отчёта — спиннер на кнопке, затем немедленное открытие карточки отчёта (не toast с последующим переходом).
* Toast — выезд, авто-скрытие 3–5 с.

## Зависимости и ограничения

* Счета/оплаты на карточке смены — read-only проекция из Payments module (сам модуль их не редактирует и не создаёт).
* Кассир — сотрудник HR Module; право быть кассиром для отдела «Регистратура» зависит от настройки Management Module (см. `1.8.0.3`).
* Экспорт отчёта — File Module, сервер отдаёт готовый бинарный файл напрямую (без base64, без промежуточного JSON с ссылкой).

### Роли / права

| Действие | Право |
|---|---|
| Просмотр смен/отчётов | `WORK_SHIFT_GET` / `CASH_REPORT_GET` |
| Открытие смены | `WORK_SHIFT_OPEN` |
| Передача смены | `WORK_SHIFT_TRANSFER` |
| Закрытие смены | `WORK_SHIFT_CLOSE` |
| Формирование X-отчёта | `CASH_REPORT_CREATE` |
| Скачивание отчёта | `CASH_REPORT_DOWNLOAD` |

## Acceptance criteria

* Реестр смен показывает кассу, кассира, время открытия/закрытия, статус; фильтруется по кассе/кассиру/периоду/статусу.
* Открытие смены доступно только на свободной кассе; сервер дополнительно защищает от гонки (`409 SHIFT_ALREADY_OPEN_ON_REGISTER`).
* Передача смены явно предупреждает об автоформировании X-отчёта и показывает его сразу после передачи.
* Закрытие смены явно предупреждает об автоформировании Z-отчёта и необратимости действия.
* Карточка смены показывает счета/оплаты (read-only) и список отчётов смены.
* Отчёт открывается со сводкой по методам оплаты и итогом; скачивается в Excel или PDF.
* `403 CASHIER_NOT_ALLOWED` при открытии/приёме смены сотрудником регистратуры без разрешения показывает понятную причину, а не общую ошибку.
* Состояния empty/loading/error/permissions обработаны на реестре и на карточке.
