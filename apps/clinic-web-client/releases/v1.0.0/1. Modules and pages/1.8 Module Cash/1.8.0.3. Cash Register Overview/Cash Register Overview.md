# 1.8.0.3 Cash Register Module — Обзор и навигация

## Спецификация модуля

* **Модуль:** Cash Register Module (кассы и смены)
* **Тип:** раздел внутренней админки клиники
* **Платформа:** веб-приложение медицинской системы
* **Основные роли:** Кассир (сотрудник со сменой), Старший кассир/Администратор (управление кассами, просмотр отчётов по всей клинике)
* **Статус документа:** Актуализировано

> **Важно.** Остальное содержимое папки `1.8 Module Cash` (`Data model.md`, `Public interface.md`, `Functional requirements.md`, `Business rules and validations.md`, `Roles and permissions.md`, `Statuses and transitions.md`, `User scenarios.md`, страницы `1.8.0.1`, `1.8.0.2`, `1.8.1`–`1.8.7`) — дизайн **до** разделения кассы и Payments module: описывает наличность/сверку смены, фискальную интеграцию с ККМ и весь платёжный флоу (очередь на оплату, оплата визита, отложенные платежи, возврат). Всё это по актуальному `CashRegisterModule.md` больше не относится к Cash Register Module — деньги, счета и возвраты теперь ведёт Payments module (отдельная, ещё не спроектированная задача на фронт/дизайн). Этот документ и две страницы ниже (`1.8.8`, `1.8.9`) — единственный актуальный источник по Cash Register Module; остальное содержимое папки сохранено, но не используется.

## Что НЕ входит в модуль (точки интеграции)

* **Счета и оплаты** (`invoices`, `payments`, интернет-эквайринг Uzum/Payme/Click) — Payments module. Смена — лишь операционный контекст, в рамках которого кассир регистрирует оплату; сама оплата, её отмена/возврат — не здесь.
* **Сотрудники-кассиры** — HR Module; отдел/шаблон отдела (регистратура) — Structure Module.
* **Глобальная настройка**, разрешающая сотруднику регистратуры быть кассиром — Management Module.
* **Формирование файлов отчётов** (Excel/PDF) — File Module (сервер отдаёт готовый файл, фронт не генерирует).

## Общие UI-паттерны

Зафиксированы один раз; страницы ссылаются на них без повторного описания.

### Паттерн «Реестр» (список сущностей)

Тот же паттерн, что и в HR Module (`1.6.0. Overview`, раздел «Паттерн "Реестр"») — заголовок с кнопкой создания, поиск/фильтр, таблица, пагинация.

### Паттерн «Статус-бейдж»

| Семантика | Где используется | Цвет |
|-----------|-------------------|------|
| Открыта / активна | Смена в статусе `open`, касса без ограничений | Зелёный |
| Закрыта / неактивна | Смена в статусе `close` | Серый |
| Заблокировано действие | Касса с открытой сменой — недоступна для удаления | Жёлтый/янтарный (тултип с причиной) |

### Паттерн «Пустое / Загрузка / Ошибка»

Тот же паттерн, что и в HR Module (`1.6.0. Overview`).

### Паттерн «Право кассира из регистратуры»

Сотрудник, привязанный к отделу с шаблоном «Регистратура» (Structure Module), может открывать/принимать смену, только если в настройках клиники включено «Сотрудник регистратуры может быть кассиром» (Management Module, по умолчанию выключено). Для остальных отделов это ограничение не действует — их право на кассу определяется обычной ролью. Фронт не проверяет это условие сам (нет доступа к шаблону отдела текущего пользователя в надёжном виде на клиенте) — полагается на ответ сервера:

* Кнопки «Открыть смену»/«Принять смену» показываются, если у пользователя вообще есть право `WORK_SHIFT_OPEN`/`WORK_SHIFT_TRANSFER` (обычная проверка прав).
* Если сервер всё же отклоняет действие с `403 CASHIER_NOT_ALLOWED` — инлайн-ошибка/toast «Сотрудникам регистратуры недоступно без разрешения в настройках клиники», без падения формы.

## Права доступа — общий принцип

Видимость и доступность элементов интерфейса модуля определяется правами пользователя: `CASH_REGISTER_GET`/`MANAGE` — реестр касс и CRUD; `WORK_SHIFT_GET`/`OPEN`/`TRANSFER`/`CLOSE` — смены; `CASH_REPORT_CREATE`/`GET`/`DOWNLOAD` — отчёты. Полная сводная таблица — во frontend-документе `1.8.0. Overview` (Frontend).

## Acceptance criteria — общие (для всех экранов модуля)

* Навигация раздела «Касса» содержит два активных пункта: «Кассы», «Смены и отчёты».
* Реестры поддерживают поиск/фильтрацию, пагинацию и состояния пусто/загрузка/ошибка.
* Статус-бейджи используют единую цветовую семантику раздела.
* Касса с открытой сменой не может быть удалена — действие скрыто/disabled с тултипом, а не просто отклоняется сервером без объяснения.
* Ни на одном экране модуля нет наличности/сверки денежного ящика, фискальных чеков, оплаты визита или возврата — эти сценарии не входят в Cash Register Module.
