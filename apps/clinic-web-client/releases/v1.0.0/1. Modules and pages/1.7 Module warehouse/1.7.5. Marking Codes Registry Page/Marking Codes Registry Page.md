# 1.7.5 Marking Codes Registry Page (Реестр маркировки)

## Спецификация страницы интерфейса

* **Название страницы:** Реестр маркировки
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка с историей
* **Основные роли:** Кладовщик / сотрудник склада, Заведующий складом
* **Маршрут:** `/warehouse/marking-codes`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.5. Marking Codes Registry`.

---

## Назначение страницы и сценарии использования

Единый реестр всех кодов маркировки клиники (единиц/партий товара, прошедших приёмку) — источник истины по остаткам и движению каждого конкретного кода, независимо от того, где он физически создан (приёмка, разделение при выдаче, ревизия).

С помощью страницы пользователь может:

1. Искать код по номеру, товару, складу, статусу.
2. Просматривать карточку кода с полной историей движения (`marking_code_events`) — от регистрации до текущего состояния.
3. Вручную списать код (частично или полностью) вне обычного цикла реализации/приёмки.

---

## User Flows / Task Flows

### Flow 1. Поиск и просмотр
1. Пользователь ищет код по номеру или фильтрует по товару/складу/статусу.
2. Открывает карточку — видит текущее состояние и хронологическую ленту событий.

### Flow 2. Ручное списание
1. В карточке кода — «Списать».
2. Модалка: причина (обязательна), количество (по умолчанию — весь остаток; для частичного списания агрегатного кода можно указать меньше).
3. Подтверждение → код (или его часть — создаётся дочерний код) переходит в `written_off`, событие добавляется в ленту.

## Визуал: High-Fidelity mockups

1. Лента истории — вертикальный таймлайн с иконкой по типу события (регистрация/перемещение/разделение/резерв/реализация/списание/брак/возврат/корректировка ревизии).
2. Каждое событие ленты показывает ссылку на источник (`reference_type`/`reference_id`) — клик ведёт на соответствующую сущность (приёмка/запрос на пополнение/ревизия/бронирование/оплата), если применимо.
3. Статус-бейджи — единая семантика модуля.

---

## Состояния и edge cases

### Empty
Нет кодов по фильтру — «Ничего не найдено» + «Сбросить фильтры».

### Loading / Error
Скелетон таблицы/ленты; toast при сбое списания.

### Permissions
`WAREHOUSE_MARKING_CODE_GET` — просмотр; `WAREHOUSE_MARKING_CODE_MANAGE` — списание.

### Edge cases
* Списание терминального кода (`written_off`/`dispensed`/`returned_to_supplier`) — кнопка скрыта, сервер всё равно отклонит `409`.
* Частичное списание агрегатного кода создаёт дочерний код (аналогично `split`) — в ленте родителя появляется событие, у дочернего кода — своя лента с единственной записью.
* Событие `reference_type: null` (например, ручное списание) — ссылка на источник не показывается.

---

## Interaction & Animation

Раскрытие ленты истории — плавное появление узлов сверху вниз. Списание — модалка fade+scale, подтверждение с toast.

## Зависимости и ограничения

Коды создаются на `1.7.4` (приёмка) и `1.7.9` (корректировка ревизии); перемещаются через `1.7.7` (выдача по запросу). Эта страница — только чтение истории + точечное ручное списание, не общий редактор движения.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр реестра/карточки | `WAREHOUSE_MARKING_CODE_GET` |
| Ручное списание | `WAREHOUSE_MARKING_CODE_MANAGE` |

---

## Acceptance criteria

* Реестр поддерживает поиск по номеру и фильтры по товару/складу/статусу.
* Карточка кода показывает полную историю движения в хронологическом порядке со ссылками на источники событий.
* Ручное списание требует причины, поддерживает частичное количество, недоступно для терминальных статусов.
* Состояния empty/loading/error/permissions обработаны.
