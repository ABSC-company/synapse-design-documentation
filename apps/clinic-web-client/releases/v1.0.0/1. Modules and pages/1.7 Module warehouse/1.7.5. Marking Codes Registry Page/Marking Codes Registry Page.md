# 1.7.5 Stock & Batches Page (Остатки и партии)

## Спецификация страницы интерфейса

* **Название страницы:** Остатки и партии
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка с историей движения
* **Основные роли:** Кладовщик / сотрудник склада, Заведующий складом
* **Маршрут:** `/warehouse/stock`
* **Статус документа:** Актуализировано (переименовано из «Реестр маркировки» — см. `1.7.0. Warehouse Overview`, ревизия 29.09.2026)

> Общие паттерны — см. `1.7.0. Warehouse Overview`, в т.ч. «Паттерн «Списание по FIFO»». Техническая реализация — `1.7.5. Stock & Batches` (frontend).

---

## Назначение страницы и сценарии использования

Единый реестр остатков товара клиники **в разрезе партии** — источник истины по тому, сколько товара и с каким сроком годности лежит на каждом складе, и в каком порядке это будет списано. Товар в системе не маркируется индивидуально (см. «Изменено» в `WarehouseModule.md` §1) — учёт количественный, но **партионный**, чтобы поддерживать списание по FIFO (партия с ближайшим сроком годности расходуется первой).

С помощью страницы пользователь может:

1. Просматривать остатки, сгруппированные по товару и складу, с раскрытием по партиям.
2. Видеть, в каком порядке партии будут расходоваться (сортировка по сроку годности).
3. Просматривать историю движения (леджер) по конкретной партии на конкретном складе.
4. Вручную списать остаток **конкретной** партии — единственное место в модуле, где партия выбирается вручную, а не автоматически по FIFO.

---

## User Flows / Task Flows

### Flow 1. Поиск и просмотр остатков
1. Пользователь фильтрует по товару и/или складу.
2. Таблица показывает партии этого товара на этом складе, **отсортированные по сроку годности по возрастанию** — верхняя строка спишется первой.
3. Раскрытие строки — лента движения (`stock_movements`) для пары товар+склад+партия.

### Flow 2. Ручное списание партии
1. В строке партии — «Списать».
2. Модалка: причина (обязательна), количество (по умолчанию — весь остаток этой партии).
3. Подтверждение → `quantity_in_stock` этой партии уменьшается, движение `written_off` добавляется в ленту. Другие партии этого товара не затрагиваются.

## Визуал: High-Fidelity mockups

1. Строки таблицы одного товара визуально сгруппированы (лёгкая подложка/группа), сортировка внутри группы — по возрастанию срока годности; первая строка группы помечена меткой «Спишется первой» (tooltip или иконка ⏱) — делает FIFO-порядок явным для оператора, а не подразумеваемым.
2. Партия, срок годности которой истекает в ближайшие 30 дней — жёлтый бейдж «Истекает» рядом с датой; истёкшая (`status: expired`) — красный бейдж «Просрочено», строка визуально приглушена, кнопка «Списать» — единственное доступное действие (такая партия исключена из автоматического FIFO-расходования, см. `1.7.0. Warehouse Overview`).
3. Лента истории — вертикальный таймлайн с иконкой по типу движения (приход/перемещение/резерв/реализация/списание/возврат/корректировка ревизии), каждое событие — ссылка на источник (`reference_type`/`reference_id`), если применимо.
4. Статус-бейджи — единая семантика модуля.

## Состояния и edge cases

### Empty
Нет остатков по фильтру — «Ничего не найдено» + «Сбросить фильтры».

### Loading / Error
Скелетон таблицы/ленты; toast при сбое списания.

### Permissions
`WAREHOUSE_STOCK_GET` — просмотр; `WAREHOUSE_STOCK_MANAGE` — списание.

### Edge cases
* Списание партии с нулевым остатком — кнопка скрыта, сервер всё равно отклонит `409`.
* Партия просрочена (`expired`) — недоступна для автоматического резервирования/выдачи ни в одном из других сценариев модуля, видна здесь только для ручного списания.
* Две партии одного товара с одинаковым сроком годности — вторичная сортировка по дате прихода (более старая партия — первой), чтобы порядок FIFO был детерминирован.
* Событие `reference_type: null` (например, ручное списание) — ссылка на источник не показывается.

## Interaction & Animation

Раскрытие ленты истории — плавное появление узлов сверху вниз. Списание — модалка fade+scale, подтверждение с toast.

## Зависимости и ограничения

Остатки создаются на `1.7.4` (приёмка, шаг «Размещение на склад») и корректируются на `1.7.9` (ревизия). Расходуются автоматически по FIFO при резервировании/реализации расходников (Payments/Booking, вне этого модуля) и при выдаче по запросу на пополнение (`1.7.7`) — эта страница показывает результат, а не инициирует расход, кроме ручного списания.

## Acceptance criteria

* Реестр поддерживает поиск по товару и фильтр по складу, группирует партии по товару.
* Партии одного товара отсортированы по сроку годности по возрастанию — порядок совпадает с порядком автоматического списания (FIFO).
* Партия с истекающим (≤30 дней) или истёкшим сроком визуально выделена отдельными бейджами.
* Карточка партии показывает полную историю движения в хронологическом порядке со ссылками на источники событий.
* Ручное списание требует причины, поддерживает частичное количество, затрагивает только выбранную партию.
* Состояния empty/loading/error/permissions обработаны.
