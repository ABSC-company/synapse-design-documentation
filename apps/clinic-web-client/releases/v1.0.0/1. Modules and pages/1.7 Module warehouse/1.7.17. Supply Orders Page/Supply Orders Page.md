# 1.7.17 Supply Orders Page (Заказы на поставку)

## Спецификация страницы интерфейса

* **Название страницы:** Заказы на поставку
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + точка входа в приёмку
* **Маршрут:** `/warehouse/supply-orders`
* **Статус документа:** Актуализировано

> Общие паттерны, включая «Сопроводительный документ»/«Связанные документы» — см. `1.7.0.2. Warehouse Overview`. Техническая реализация — `1.7.3. Supply Orders`.

---

## Назначение страницы и сценарии использования

Реестр заказов на поставку — по одной позиции товара каждый. Отсюда заказ создаётся, подтверждается (гейтуется сопроводительным документом) или отменяется, и отсюда же инициируется приёмка по подтверждённому заказу.

С помощью страницы пользователь может:

1. Просматривать заказы, фильтровать по поставщику/статусу.
2. Создавать заказ (поставщик, товар, количество).
3. Подтверждать или отменять заказ.
4. Переходить к приёмке подтверждённого заказа.

---

## User Flows / Task Flows

### Flow 1. Создание заказа
1. «+ Создать заказ» → выбор поставщика (влияет на список доступных товаров — только позиции с активным договором этого поставщика) → товар → количество.
2. Сохранение → заказ в статусе «Черновик».

### Flow 2. Подтверждение заказа (гейтуемое действие)
1. Пользователь нажимает «Подтвердить» на заказе в статусе «Черновик».
2. Если сопроводительный документ обязателен (настройка Management Module) — открывается модалка «Сопроводительный документ» (паттерн `1.7.0.2`).
3. Без документа/при выключенной настройке — статус меняется сразу на «Подтверждён».
4. С документом, ожидающим подписания — заказ остаётся «Черновик», в блоке «Связанные документы» появляется запись «Ожидает подписания»; статус сменится на «Подтверждён» автоматически после подписания.

### Flow 3. Отмена заказа
1. «Отменить» доступно для «Черновик»/«Подтверждён» — не гейтуется документом.
2. Подтверждение → статус «Отменён», причина опциональна.

### Flow 4. Переход к приёмке
1. На подтверждённом заказе — кнопка «Инициировать приёмку» → переход на `1.7.18. Receiving Page` с предзаполненным `supply_order_id`.

## Состояния и edge cases

### Empty
Нет заказов — «Заказов пока нет» + «+ Создать заказ».

### Loading / Error
Скелетон таблицы/карточки; toast при сбое действия.

### Permissions
`WAREHOUSE_SUPPLY_ORDER_GET` — просмотр; `CREATE`/`UPDATE` — создание/подтверждение/отмена.

### Edge cases
* Товар в форме создания заказа ограничен номенклатурой, привязанной к выбранному поставщику активным договором (`supplier_products`, §1.7.15).
* Повторное подтверждение уже подтверждённого заказа — кнопка скрыта/disabled по статусу, не полагается только на серверную ошибку `409`.
* Заказ можно перевести в «Выполнен»/«Частично выполнен» только автоматически (по закрытию связанной приёмки) — ручного действия нет.

## Interaction & Animation

Стандартные для реестра/модалки. Смена статуса после подписания документа (если пользователь остаётся на странице) — плавная замена бейджа, не резкий скачок.

## Зависимости и ограничения

Список товаров при создании заказа зависит от `1.7.15. Suppliers Page` (договоры). Приёмка — отдельный экран `1.7.18`.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр | `WAREHOUSE_SUPPLY_ORDER_GET` |
| Создание | `WAREHOUSE_SUPPLY_ORDER_CREATE` |
| Подтверждение/отмена | `WAREHOUSE_SUPPLY_ORDER_UPDATE` |

---

## Acceptance criteria

* Реестр фильтруется по статусу и поставщику, поддерживает поиск и пагинацию.
* Форма создания ограничивает товары номенклатурой выбранного поставщика.
* Подтверждение корректно ведёт себя в обоих случаях обязательности документа (сразу/через блок «Связанные документы»).
* Отмена не гейтуется документом.
* «Инициировать приёмку» доступно только для подтверждённых заказов.
* Состояния empty/loading/error/permissions обработаны.
