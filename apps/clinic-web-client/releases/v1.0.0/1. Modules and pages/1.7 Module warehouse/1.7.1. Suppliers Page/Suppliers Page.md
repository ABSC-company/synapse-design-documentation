# 1.7.1 Suppliers Page (Поставщики)

## Спецификация страницы интерфейса

* **Название страницы:** Поставщики
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка с вкладками
* **Основные роли:** Заведующий складом, Кладовщик
* **Маршрут:** `/warehouse/suppliers`
* **Статус документа:** Актуализировано

> Общие паттерны (реестр, форма, статус-бейдж, права) — см. `1.7.0. Warehouse Overview`. Техническая реализация — во frontend-документе `1.7.1. Suppliers`.

---

## Назначение страницы и сценарии использования

Реестр поставщиков (контрагентов) с карточкой, объединяющей контакты, заключённые договоры, привязанную номенклатуру и долги по браку. Точка входа для регистрации нового поставщика и заключения договора на поставку конкретных товарных позиций.

С помощью страницы пользователь может:

1. Просматривать и искать поставщиков, фильтровать по статусу.
2. Регистрировать нового поставщика с контактами.
3. Заключать договор с поставщиком, прикрепляя файл договора и список поставляемых позиций.
4. Просматривать долги поставщика по браку и закрывать их (возврат/списание).
5. Упразднять поставщика (при отсутствии активных поставок/договоров).

---

## User Flows / Task Flows

### Flow 1. Регистрация поставщика
1. Пользователь нажимает «+ Добавить поставщика».
2. Заполняет название, ИНН (опционально), минимум один контакт.
3. Сохраняет → поставщик появляется в реестре, открывается его карточка.

### Flow 2. Заключение договора и привязка номенклатуры
1. В карточке поставщика — вкладка «Договоры» → «+ Заключить договор».
2. Загружает файл договора, указывает даты начала/окончания действия.
3. На той же форме выбирает одну или несколько позиций из каталога товаров и договорную цену.
4. Сохранение создаёт договор (`supplier_documents`) и привязки (`supplier_products`) одной операцией.

### Flow 3. Работа с долгами по браку
1. Вкладка «Долги» карточки поставщика показывает список открытых долгов (созданы автоматически при приёмке с браком, `resolution: recorded_as_debt` — см. `1.7.4. Receiving Page`).
2. Пользователь закрывает долг: «Возвращён» (поставщик вернул товар/деньги) или «Списан».

### Flow 4. Упразднение поставщика
1. Пользователь выбирает «Упразднить» из карточки/контекстного меню.
2. Если есть активные поставки или незавершённые договоры — действие заблокировано с пояснением, какие записи мешают.
3. Иначе — подтверждение → поставщик переходит в `suspended`, скрывается из активного списка (доступен через фильтр «Все»/«Упразднённые»).

## Состояния и edge cases

### Empty
Нет поставщиков — «Пока нет поставщиков» + «+ Добавить поставщика». Вкладка «Договоры» пуста — «Договоров пока нет» + «Заключить договор». Вкладка «Долги» пуста — «Долгов нет».

### Loading
Скелетон таблицы/карточки; спиннер на «Сохранить» форм.

### Error
Сбой загрузки — блок ошибки + «Повторить»; сбой сохранения — toast, форма остаётся открытой.

### Permissions
Нет права на просмотр — раздел недоступен. Нет прав на управление — кнопки создания/редактирования скрыты, карточка доступна только на чтение.

### Edge cases
* Упразднение поставщика с активными поставками/договорами заблокировано с явным списком причин.
* Один договор может покрывать несколько товарных позиций с разными ценами.
* Договор с истёкшим `valid_until` не блокирует просмотр истории и не отвязывает автоматически номенклатуру — требует ручного продления новым договором.

## Interaction & Animation

* Переключение вкладок карточки — fade ~150 мс.
* Открытие форм — fade+scale; закрытие модалки — fade-out.
* Добавление позиции в форму договора — плавное появление новой строки.

## Зависимости и ограничения

* Товарные позиции для договора — из каталога Warehouse (`1.7.2`). Файлы договоров — File Module напрямую (не через ЭДО, см. `WarehouseModule.md` §6.2).
* Упразднение — soft-статус (`suspended`), не физическое удаление.

## Acceptance criteria

* Реестр показывает название/ИНН/кол-во товаров/статус, поддерживает поиск, фильтр по статусу, пагинацию.
* Карточка поставщика — три вкладки (Основное/Договоры/Долги) со счётчиками.
* Договор заключается с прикреплением файла, датами действия и списком позиций с ценой — одной формой.
* Долги отображают статус и позволяют перевести в «Возвращён»/«Списан».
* Упразднение заблокировано при активных связях, с пояснением.
* Состояния empty/loading/error/permissions обработаны для всех блоков.
