# 1.7.9 Revisions Page (Ревизии)

## Спецификация страницы интерфейса

* **Название страницы:** Ревизии
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка процесса
* **Основные роли:** Заведующий складом, Кладовщик
* **Маршрут:** `/warehouse/revisions`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.9. Revisions`.

---

## Назначение страницы и сценарии использования

Инвентаризация остатков товара или ТМЦ по складу: сравнение ожидаемого (учётного) и фактического количества, фиксация расхождений и завершение с автоматическим списанием/корректировкой.

С помощью страницы пользователь может:

1. Просматривать список ревизий (плановые и неплановые) и цепочки плановых ревизий.
2. Инициировать неплановую либо плановую ревизию (с повторением).
3. Вносить строки результата по позициям (ожидаемое/фактическое количество).
4. Завершать ревизию (гейтуемое действие) — формируется протокол.

---

## User Flows / Task Flows

### Flow 1. Инициация ревизии
1. «+ Начать ревизию» → форма: вид («Неплановая» / «Плановая»), область (товары/ТМЦ), склад (опционально — вся клиника, если не выбран). Для плановой появляется блок «Повторять»: частота (день, неделя, месяц, год), интервал, дни, время, дата окончания.
2. Сохранение → ревизия в статусе «В процессе»; у плановой с повторением создаётся цепочка.

> Плановая ревизия повторяется цепочкой: первую создаёт сотрудник вручную, каждую следующую система создаёт сама после завершения предыдущей и уведомляет инициатора; пока ревизия не завершена, следующая не создаётся.

### Flow 1a. Цепочки плановых ревизий
1. Над списком — панель «Плановые ревизии»: правило повторения, склад и область, дата следующей ревизии (или «после завершения текущей»).
2. «Остановить» (с подтверждением) прекращает создание следующих ревизий; идущая ревизия завершается как обычно.

### Flow 2. Внесение строк результата
1. Для ревизии товаров строка результата вносится **на уровне партии** — «Добавить строку»: система подсказывает конкретную партию (серия, срок годности) и её ожидаемое количество на складе ревизии, пользователь вводит фактическое количество именно по ней. Для ревизии ТМЦ строка — на конкретную единицу ТМЦ (как правило, найденную сканированием инвентарного номера, см. `1.7.8`).
2. При расхождении — причина (необязательна на этом шаге, но рекомендуется).

### Flow 3. Завершение ревизии (гейтуемое действие)
1. Если сопроводительный документ (протокол) обязателен — пользователь сначала прикрепляет его отдельным действием «Прикрепить документ» в блоке «Связанные документы» (паттерн `1.7.0`); до этого «Завершить ревизию» неактивна.
2. «Завершить ревизию» — доступно, когда внесены строки по всем ожидаемым позициям (или явно, по решению пользователя, с предупреждением о неполном покрытии) и (если требуется) документ уже привязан.
3. Нажатие «Завершить ревизию» не содержит ссылки на документ — она уже установлена на шаге 1.
4. Если проверка не отложена — ревизия «Завершена», по строкам с расхождением проставляется решение (списание/корректировка/расследование); для товаров в истории движения соответствующей партии появляется событие «Корректировка по ревизии», для ТМЦ — карточка переводится в «Списано». Если отложена — ревизия остаётся «В процессе», блок «Связанные документы» показывает «Ожидает подписания», корректировки применяются автоматически после подписания, без повторного нажатия «Завершить».

## Визуал: High-Fidelity mockups

1. Строки с расхождением визуально выделены (⚠, цвет по знаку — недостача/излишек).
2. Кнопка «Завершить ревизию» показывает предупреждение, если покрыты не все ожидаемые позиции.
3. После завершения — строки с расхождением дополнительно показывают выбранное действие бейджем.

## Состояния и edge cases

### Empty
Строк ещё нет — «Добавьте первую строку результата».

### Loading / Error
Спиннер на завершении (применяет корректировки — не мгновенно); toast при сбое.

### Permissions
Просмотр ревизий, инициация и добавление строк, завершение доступны по соответствующим правам.

### Edge cases
* Правило повторения доступно только для плановой ревизии.
* Цепочка остановлена, пока последняя ревизия не завершена, — следующая не создаётся.
* Правило повторения закончилось (дата окончания раньше следующего срока) — цепочка закрывается сама.
* Завершение при неполном покрытии позиций — предупреждающая, но не блокирующая модалка (решение — на усмотрение пользователя, бизнес-правило не запрещает).
* Пока ревизия не завершена, остатки на `1.7.6`/`1.7.5` не меняются — даже если расхождение уже зафиксировано в строке.

---

## Interaction & Animation

Добавление строки — fade-in в таблицу. Завершение — модалка подтверждения с итоговой сводкой расхождений перед отправкой.

## Зависимости и ограничения

Следующую плановую ревизию создаёт Tasks module после завершения предыдущей по правилу повторения; первую создаёт сотрудник на этой странице. Корректировки после завершения отражаются в истории движения партии (`1.7.5. Stock & Batches Page`) и остатках (`1.7.6`).


---

## Acceptance criteria

* Список ревизий различает плановые и неплановые, показывает статус.
* Неплановая и плановая ревизии инициируются вручную с указанием области и (опционально) склада; у плановой можно задать повторение.
* Цепочки плановых ревизий видны и останавливаются.
* Строки результата подсказывают ожидаемое количество, фиксируют расхождение.
* Завершение корректно ведёт себя в обоих случаях обязательности документа и предупреждает о неполном покрытии.
* Блок «Связанные документы» отражает статус инициированного завершения.
* Состояния empty/loading/error/permissions обработаны.
