# 1.7.23 Revisions Page (Ревизии)

## Спецификация страницы интерфейса

* **Название страницы:** Ревизии
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка процесса
* **Основные роли:** Заведующий складом, Кладовщик
* **Маршрут:** `/warehouse/revisions`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0.2. Warehouse Overview`. Техническая реализация — `1.7.9. Revisions`.

---

## Назначение страницы и сценарии использования

Инвентаризация остатков товара или ТМЦ по складу: сравнение ожидаемого (учётного) и фактического количества, фиксация расхождений и завершение с автоматическим списанием/корректировкой.

С помощью страницы пользователь может:

1. Просматривать список ревизий (плановые — из Tasks module, неплановые — созданные вручную).
2. Инициировать неплановую ревизию.
3. Вносить строки результата по позициям (ожидаемое/фактическое количество).
4. Завершать ревизию (гейтуемое действие) — формируется протокол.

---

## User Flows / Task Flows

### Flow 1. Инициация неплановой ревизии
1. «+ Начать ревизию» → форма: область (товары/ТМЦ), склад (опционально — вся клиника, если не выбран).
2. Сохранение → ревизия в статусе «В процессе».

> Плановая ревизия появляется в списке автоматически (создаётся Tasks module по расписанию) — отдельной кнопки для неё нет.

### Flow 2. Внесение строк результата
1. По каждой позиции — «Добавить строку»: система подсказывает ожидаемое количество (сумма активных кодов/остатка ТМЦ), пользователь вводит фактическое.
2. При расхождении — причина (необязательна на этом шаге, но рекомендуется).

### Flow 3. Завершение ревизии (гейтуемое действие)
1. «Завершить ревизию» — доступно, когда внесены строки по всем ожидаемым позициям (или явно, по решению пользователя, с предупреждением о неполном покрытии).
2. Если сопроводительный документ (протокол) обязателен — модалка документа.
3. `deferred: false` — ревизия «Завершена», по строкам с расхождением проставляется `action_taken` (списание/корректировка/расследование), в истории кодов появляются события `revision_adjustment`. `deferred: true` — ревизия остаётся «В процессе», блок «Связанные документы» показывает «Ожидает подписания», корректировки не применены.

## Визуал: High-Fidelity mockups

1. Строки с расхождением визуально выделены (⚠, цвет по знаку — недостача/излишек).
2. Кнопка «Завершить ревизию» показывает предупреждение, если покрыты не все ожидаемые позиции.
3. После завершения — строки с расхождением дополнительно показывают выбранное действие (`action_taken`) бейджем.

## Состояния и edge cases

### Empty
Строк ещё нет — «Добавьте первую строку результата».

### Loading / Error
Спиннер на завершении (применяет корректировки — не мгновенно); toast при сбое.

### Permissions
`WAREHOUSE_REVISION_GET` — просмотр; `WAREHOUSE_REVISION_CREATE` — инициация и добавление строк; `WAREHOUSE_REVISION_COMPLETE` — завершение.

### Edge cases
* Плановая ревизия не может быть создана вручную — кнопка инициации создаёт только `type: "unplanned"`.
* Завершение при неполном покрытии позиций — предупреждающая, но не блокирующая модалка (решение — на усмотрение пользователя, бизнес-правило не запрещает).
* Пока ревизия не завершена, остатки на `1.7.20`/`1.7.19` не меняются — даже если расхождение уже зафиксировано в строке.

## Interaction & Animation

Добавление строки — fade-in в таблицу. Завершение — модалка подтверждения с итоговой сводкой расхождений перед отправкой.

## Зависимости и ограничения

Плановые ревизии инициируются Tasks module по расписанию — эта страница их не создаёт, только отображает и позволяет вести/завершать. Корректировки после завершения отражаются в истории кодов (`1.7.19`) и остатках (`1.7.20`).

## Роли / права

| Действие | Право |
|---|---|
| Просмотр | `WAREHOUSE_REVISION_GET` |
| Инициация / строки результата | `WAREHOUSE_REVISION_CREATE` |
| Завершение | `WAREHOUSE_REVISION_COMPLETE` |

## Acceptance criteria

* Список ревизий различает плановые и неплановые, показывает статус.
* Неплановая ревизия инициируется вручную с указанием области и (опционально) склада.
* Строки результата подсказывают ожидаемое количество, фиксируют расхождение.
* Завершение корректно ведёт себя в обоих случаях обязательности документа и предупреждает о неполном покрытии.
* Блок «Связанные документы» отражает статус инициированного завершения.
* Состояния empty/loading/error/permissions обработаны.
