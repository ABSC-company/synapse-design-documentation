# 1.7.3.1 Order Supplies Page (Заказ на поставку и поставки по нему)

## Спецификация страницы интерфейса

* **Название страницы:** Заказ на поставку · поставки по заказу
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Вложенный экран; открывается кликом по заказу на странице `1.7.3`
* **Маршрут:** `/warehouse/supply-orders/:orderId`
* **Положение в боковом меню:** Заказы на поставку → **Заказ n**
* **Статус документа:** Актуализировано

> Общие паттерны, включая «Сопроводительный документ»/«Связанные документы», — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.3.1. Order Supplies`.

---

## Назначение страницы и сценарии использования

Страница одного заказа: сведения о заказе, его подтверждение или отмена (подтверждение гейтуется сопроводительным документом), список **поставок по этому заказу** и создание новой поставки. Клик по поставке открывает страницу приёмки `1.7.4`.

С помощью страницы пользователь может:

1. Просматривать данные заказа и привязанные документы.
2. Подтверждать или отменять заказ.
3. Видеть все поставки по заказу (в том числе принятые и отменённые) и открывать любую кликом по строке.
4. Создавать поставку кнопкой «Создать поставку» — после создания автоматически открывается страница приёмки.

---

## User Flows / Task Flows

### Flow 1. Подтверждение заказа (гейтуемое действие)
1. Если сопроводительный документ обязателен (настройка Management Module) — пользователь сначала прикрепляет документ отдельным действием «Прикрепить документ» в блоке «Связанные документы» (паттерн `1.7.0`); кнопка «Подтвердить» до этого момента неактивна.
2. При выключенной настройке — блок документа не требуется, кнопка «Подтвердить» активна сразу.
3. Если привязанный документ ещё не подписан — заказ остаётся «Черновик», блок «Связанные документы» показывает «Ожидает подписания»; статус сменится на «Подтверждён» автоматически после подписания. Если документ уже подписан (или подписание не требовалось) — статус меняется сразу.

### Flow 2. Отмена заказа
1. «Отменить» доступно для «Черновик»/«Подтверждён» — не гейтуется документом.
2. Подтверждение → статус «Отменён», причина необязательна. Создание новых поставок после этого недоступно.

### Flow 3. Создание поставки и переход на приёмку
1. Кнопка **«Создать поставку»** доступна для подтверждённого или частично выполненного заказа, если по нему нет незавершённой поставки.
2. Нажатие создаёт поставку «В процессе» (приёмка — не отдельная запись: поставка и есть приёмка) и **сразу автоматически открывает страницу приёмки** этой поставки `1.7.4`. Окно добавления партии при этом не открывается.
3. Если у заказа уже есть незавершённая поставка («В процессе», «Предварительно принята», «Предварительно отменена»), кнопка неактивна с подсказкой «По заказу уже ведётся поставка» — открыть её можно кликом по строке.

### Flow 4. Открытие поставки
1. Клик по строке поставки открывает страницу приёмки `1.7.4`. Контекстного меню с действиями «Принять»/«Отменить» у строк поставок **нет** — принимать и отменять поставку можно только на странице приёмки.
2. Принятые, частично принятые и отменённые поставки открываются там же в режиме **только чтения**.

## Визуал: High-Fidelity mockups

1. Шапка заказа — компактная, статус бейджем; блок «Связанные документы» по общему паттерну модуля.
2. Таблица поставок — строки кликабельны; статусы поставки: «В процессе», «Предварительно принята», «Принята», «Частично принята», «Предварительно отменена», «Отменена».

## Состояния и edge cases

### Empty
Поставок по заказу ещё нет: для подтверждённого заказа — «Поставок пока нет» + «+ Создать поставку»; для черновика — «Создание поставок доступно после подтверждения заказа».

### Loading / Error
Скелетон; toast при сбое действия.

### Permissions
`WAREHOUSE_SUPPLY_ORDER_GET` — просмотр заказа; `WAREHOUSE_SUPPLY_ORDER_UPDATE` — подтверждение/отмена; `WAREHOUSE_SUPPLY_GET` — список поставок и переход на приёмку; `WAREHOUSE_SUPPLY_RECEIVE` — «Создать поставку».

### Edge cases
* Повторное подтверждение подтверждённого заказа — кнопка скрыта/disabled по статусу.
* Заказ «Выполнен» или «Отменён» — кнопки «Подтвердить», «Отменить», «Создать поставку» скрыты; поставки остаются доступны для просмотра.
* «Частично выполнен» — «Создать поставку» доступна для довоза остатка, если нет незавершённой поставки.
* Поставка в любом статусе открывается по клику; принятые и отменённые — только чтение.

---

## Interaction & Animation

После «Создать поставку» — мгновенный переход на страницу приёмки; в боковом меню под «Заказ n» появляется вложенный элемент «Поставка n». Смена статуса заказа или поставки (по подписанию документа) — плавная замена бейджа.

## Зависимости и ограничения

Приёмка и отмена поставки выполняются только на `1.7.4`. Список заказов — `1.7.3`.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр заказа | `WAREHOUSE_SUPPLY_ORDER_GET` |
| Подтверждение/отмена заказа | `WAREHOUSE_SUPPLY_ORDER_UPDATE` |
| Просмотр поставок, переход на приёмку | `WAREHOUSE_SUPPLY_GET` |
| Создание поставки | `WAREHOUSE_SUPPLY_RECEIVE` |

---

## Acceptance criteria

* Клик по заказу в `1.7.3` открывает эту страницу; здесь отображаются поставки только этого заказа.
* «Создать поставку» создаёт поставку и автоматически открывает страницу приёмки.
* Клик по поставке открывает страницу приёмки; контекстного меню «Принять/Отменить» у строк нет; принятые и отменённые поставки открываются только для чтения.
* Подтверждение заказа корректно ведёт себя при обеих настройках обязательности документа.
* Отмена заказа не гейтуется документом.
* Состояния empty/loading/error/permissions обработаны.
