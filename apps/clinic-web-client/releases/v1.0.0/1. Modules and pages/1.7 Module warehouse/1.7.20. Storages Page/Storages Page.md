# 1.7.20 Storages Page (Склады)

## Спецификация страницы интерфейса

* **Название страницы:** Склады
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка с остатками
* **Основные роли:** Заведующий складом, Кладовщик
* **Маршрут:** `/warehouse/storages`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0.2. Warehouse Overview`. Техническая реализация — `1.7.6. Storages`.

---

## Назначение страницы и сценарии использования

CRUD складов клиники (основных и потребительских) и просмотр остатков товара по каждому складу.

С помощью страницы пользователь может:

1. Просматривать список складов с кратким составом остатков.
2. Создавать/редактировать/удалять склад.
3. Открывать карточку склада с полным списком остатков по товарам.

---

## User Flows / Task Flows

### Flow 1. Создание склада
1. «+ Добавить склад» → форма: название, тип (основной/потребительский), отдел (обязателен для потребительского), родительский склад (опционально), ответственный сотрудник.
2. Сохранение → склад появляется в списке с нулевыми остатками.

### Flow 2. Удаление склада
1. «Удалить» доступно, только если на складе нет активных кодов маркировки и незавершённых запросов на пополнение.
2. При наличии зависимостей — кнопка недоступна с тултипом; сервер дополнительно отклоняет `409 ENTITY_HAS_DEPENDENCIES`.

### Flow 3. Просмотр остатков
1. Клик по складу → карточка со списком товаров и количеством.
2. Клик по позиции — переход в реестр маркировки (`1.7.19`), отфильтрованный по этому складу и товару.

## Визуал: High-Fidelity mockups

1. Список складов — компактная таблица с числом позиций как индикатором заполненности.
2. Карточка остатков — простой список без пагинации (внутренний, не общеклинический реестр), со стрелкой перехода в реестр маркировки у каждой позиции.
3. Форма создания — родительский склад и отдел показываются только при осмысленном выборе типа.

## Состояния и edge cases

### Empty
Нет складов — «Склады не созданы» + «+ Добавить склад». Остатки склада пусты — «На складе пока нет товара».

### Loading / Error
Скелетон списка/карточки; toast при сбое создания/удаления.

### Permissions
`WAREHOUSE_STORAGE_GET` — просмотр; `WAREHOUSE_STORAGE_MANAGE` — CRUD.

### Edge cases
* Смена типа склада с потребительского на основной у уже существующего склада с остатками — не блокируется отдельно на UI, сервер применяет обычную валидацию формы (отдел обязателен только для потребительского на момент сохранения).
* Удаление родительского склада, на который ссылаются дочерние, — сервер обрабатывает как обычную зависимость (`409`), отдельного каскадного UI-сценария нет.

## Interaction & Animation

Переключение вкладок «Все/Основные/Потребительские» — мгновенный фильтр без перезагрузки. Карточка — slide-in справа.

## Зависимости и ограничения

Остатки формируются кодами маркировки (`1.7.19`) — эта страница их не создаёт и не изменяет напрямую, только показывает агрегированную сводку.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр | `WAREHOUSE_STORAGE_GET` |
| CRUD | `WAREHOUSE_STORAGE_MANAGE` |

---

## Acceptance criteria

* Список складов фильтруется по типу, показывает число позиций остатков.
* Форма создания требует отдел для потребительского склада.
* Удаление заблокировано при наличии активных зависимостей (сервер + предварительная UI-проверка).
* Карточка склада показывает остатки с переходом в реестр маркировки по позиции.
* Состояния empty/loading/error/permissions обработаны.
