# 1.7.4 Receiving Page (Приёмка поставки)

## Спецификация страницы интерфейса

* **Название страницы:** Приёмка поставки
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Вложенный экран (процесс); открывается кликом по поставке на странице заказа `1.7.3.1` либо автоматически сразу после создания поставки кнопкой «Создать поставку»
* **Маршрут:** `/warehouse/supply-orders/:orderId/supplies/:supplyId`
* **Положение в боковом меню:** Заказы на поставку → Заказ n → **Поставка n**
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.4. Receiving`. Не пункт бокового меню.

---

## Назначение страницы и сценарии использования

Пошаговая приёмка фактической поставки по подтверждённому заказу: регистрация одной или нескольких партий (срок годности, серия, сертификат), проверка каждой партии с раздельным учётом небракованного и бракованного количества, затем **подтверждение приёмки** с выбором склада для каждой принятой партии либо **отмена поставки**. Учёт количественный, без индивидуальных кодов на единицу товара (см. «Изменено» в `WarehouseModule.md` §1).

С помощью страницы пользователь может:

1. Открыть приёмку поставки: после создания поставки на странице заказа (`1.7.3.1`, «Создать поставку») страница открывается автоматически; существующую поставку открывают кликом по ней в списке поставок заказа — страница открывается без автоматических окон.
2. Регистрировать партии кнопкой «Новая партия»: она открывает окно с формой приёмки партии (данные лота и результат проверки); партий может быть несколько.
3. Регистрировать результат проверки каждой партии — принято / брак, с количеством брака.
4. При браке — выбрать резолюцию (отменить всю поставку / не принимать дефектное количество / зафиксировать как долг поставщика).
5. Подтвердить приёмку: выбрать склад для каждой принятой партии и (если включён документооборот) прикрепить документ о приёмке.
6. Отменить поставку целиком (с документом, если включён документооборот) и при необходимости возобновить приёмку.

## User Flows / Task Flows

### Flow 1. Инициация приёмки и регистрация партий
1. Кнопка «Создать поставку» на странице заказа (`1.7.3.1`) создаёт поставку «В процессе» (поставка и есть приёмка — одна запись) и **автоматически открывает эту страницу**. **Окно приёмки партии при переходе не открывается** — страница показывает пустую таблицу партий с призывом «Добавьте первую партию».
2. Кнопка **«Новая партия»** (в шапке таблицы партий) открывает модальное окно с формой приёмки партии: серия, дата производства, срок годности, сертификат (необязателен), количество по накладной и результат проверки (Flow 2–3). После сохранения партия появляется в таблице; для следующей партии кнопка нажимается снова. Партий может быть несколько, добавлять их можно в течение всей приёмки, пока она «В процессе». Партию с прошлым сроком годности принять нельзя; суммарное количество по партиям не может превышать ожидаемое по заказу (учитывая ранее принятое) — допустима полная поставка (по ожидаемому количеству) либо неполная.
3. Данные партии можно править, пока она не проверена; если партия внесена без результата проверки, в её строке доступно действие «Проверить».

### Flow 2. Проверка партии — всё принято
1. В форме «Новая партия» (или действием «Проверить» в строке уже внесённой партии) выбирается результат «Принято»: количество принятого равно количеству по накладной, брак — 0.
2. Партия получает принятое количество; счётчик остатка индивидуальных кодов не создаёт.

### Flow 3. Проверка партии — брак (полный или частичный)
1. Результат «Частично брак» либо «Брак». Количество небракованного и **количество брака вводятся отдельными полями**; их сумма должна равняться количеству по накладной. При результате «Брак» количество небракованного равно 0, а количество брака подставляется равным количеству по накладной (можно изменить в пределах правил). Причина брака обязательна.
2. Обязателен выбор резолюции:
   - **Отменить всю поставку** — проверка сохраняется, после чего сразу открывается диалог отмены поставки (Flow 5; причина подставлена из причины брака). Если закрыть диалог — проверка остаётся, поставка продолжается, кнопка «Отменить поставку» доступна на странице. Отмена затрагивает **всю поставку и все её партии, включая уже проверенные и принятые**.
   - **Не принимать дефектное количество** — брак просто не входит в принятое, долг не создаётся.
   - **Зафиксировать как долг** — по подтверждению приёмки создаётся долг поставщика на количество брака (виден на `1.7.1`, вкладка «Долги»). Пока приёмка не подтверждена, долга ещё нет.
3. Брак всегда учитывается отдельно от принятого количества и не зачисляется на склад.

### Flow 4. Подтверждение приёмки
1. Кнопка «Подтвердить приёмку» активна, когда есть хотя бы одна партия и проверены все не отменённые партии. **Поставку без партий принять нельзя — её можно только отменить.** Принятая поставка считается «Принята», если принято ожидаемое количество полностью, и «Частично принята», если меньше.
2. Открывается окно подтверждения со списком партий: **ID партии, товар, серия, принятое количество** и **выбор склада** (только склады типа «Поставочный (main)») для каждой партии с принятым количеством. Партии без принятого количества (весь брак) и отменённые в списке не показываются.
3. Если включён документооборот к складским процессам — в окне блок «Документ о приёмке»: «Создать новый» (редактор документов с нуля) или «Из шаблона», далее документ привязывается к подтверждению. К поставке привязывается **только один документ**: если уже привязан документ (в том числе для отмены), второй прикрепить нельзя — сначала отзывают текущий. Без привязанного документа кнопка «Подтвердить» неактивна.
4. После «Подтвердить»:
   - документооборот выключен, либо документ уже подписан/отправлен — принятое сразу зачисляется на выбранные склады, поставка «Принята»/«Частично принята» (если принято меньше заказанного);
   - иначе поставка получает статус **«Предварительно принята»**, товар на склады **не зачисляется**, блок «Связанные документы» показывает «Ожидает подписания»; зачисление происходит автоматически, как только документ подписан (либо отправлен, если подписи не требуются).
5. С момента подтверждения кнопки «Подтвердить приёмку» и «Отменить поставку» **заблокированы**; добавлять партии и проверки нельзя.

### Flow 5. Отмена поставки
1. Кнопка «Отменить поставку» (доступна, пока поставка «В процессе») открывает диалог: причина (необязательно) и, при включённом документообороте, блок «Документ об отмене» (с нуля или из шаблона).
2. После «Отменить поставку»:
   - документооборот выключен, либо документ уже подписан/отправлен — поставка и **все её партии** сразу «Отменены», на склады ничего не зачисляется;
   - иначе поставка и партии получают статус **«Предварительно отменена»** до подписания документа (либо до его отправки, если подписи не требуются), затем становятся «Отменены».
3. Поставка и партии **не удаляются** — остаются в истории; кнопки «Подтвердить приёмку» и «Отменить поставку» заблокированы.

### Flow 6. Возобновление приёмки
1. У «Отменённой» поставки доступна кнопка «Возобновить приёмку» (без документа) — поставка снова «В процессе».
2. **Ранее отменённые партии остаются «Отменёнными»** (серый статус, без действий) и **никогда не зачисляются на склады**, даже если приёмка завершится подтверждением. Для товара можно зарегистрировать новые партии и подтвердить приёмку заново.
3. Если документ отмены ещё не подписан («Предварительно отменена»), поставку можно вернуть в работу, отозвав привязку документа в блоке «Связанные документы» (кнопка «Отозвать»); то же для «Предварительно принята».

## Вход на страницу и режим просмотра

Страница открывается кликом по поставке в списке поставок заказа (`1.7.3.1`) либо автоматически после создания поставки (контекстного меню «Принять/Отменить» у поставок нет — принять и отменить можно только здесь). Режим зависит от статуса поставки:

| Статус поставки | Режим страницы |
|---|---|
| В процессе | Рабочий: «Новая партия», проверка и правка партий, «Подтвердить приёмку», «Отменить поставку» |
| Предварительно принята / Предварительно отменена | Просмотр; доступен только «Отозвать» документ (возвращает поставку «В процессе») |
| Принята / Частично принята | Только чтение — партии, проверки, документ, итоги; кнопки заблокированы |
| Отменена | Только чтение; доступно единственное действие — «Возобновить приёмку» |

Пользователь без права на приёмку видит страницу в режиме чтения при любом статусе.

## Состояния и edge cases

### Empty
Приёмка только инициирована, партий нет — пустая таблица с призывом «Добавьте первую партию» и кнопкой «Новая партия»; окно партии автоматически не открывается. «Подтвердить приёмку» недоступна, пока нет ни одной партии.

### Loading / Error
Спиннер на сохранении; toast при сбое.

### Permissions
`WAREHOUSE_SUPPLY_RECEIVE` — вся страница; без права — read-only просмотр (`WAREHOUSE_SUPPLY_GET`).

### Edge cases
* **Блокировка кнопок.** В статусах «Предварительно принята», «Принята», «Частично принята», «Предварительно отменена», «Отменена» кнопки «Подтвердить приёмку» и «Отменить поставку» неактивны; редактирование партий и проверки недоступны.
* **Документ о приёмке/отмене отозван или отклонён** — поставка возвращается в «В процессе», партии — в прежние статусы, показывается уведомление.
* **Резолюция «Отменить всю поставку»** сохраняет проверку и открывает диалог отмены; если оператор закрыл диалог, проверка остаётся, поставка продолжается.
* **Отмена поставки с уже принятыми партиями** — отменяются все партии, включая проверенные; принятые количества на склады не попадают, так как зачисление происходит только при подтверждении.
* **Подтверждение со всеми бракованными партиями** — список размещения пуст, склад не выбирается; поставка «Частично принята», товар не зачисляется, долги создаются по резолюции «В долг».
* **Возобновление** — отменённые партии остаются отменёнными и не попадают в окно подтверждения.
* **Склад выбран не типа «Поставочный»** — недоступен в списке выбора.
* **Срок годности в прошлом** — партию сохранить нельзя, поле подсвечивается («Нельзя принимать партии с истёкшим сроком годности»).
* **Количество больше ожидаемого** — партию сохранить нельзя, показывается остаток по заказу; принять можно полную или неполную поставку.
* **Поставка без партий** — «Подтвердить приёмку» неактивна, «Отменить поставку» доступна.
* **Один документ на поставку** — после привязки документа кнопка «Прикрепить документ» скрыта; чтобы выбрать другое действие (отмену вместо подтверждения или наоборот), документ отзывают.
* **Настройка ЭДО изменилась, пока поставка «Предварительно принята/отменена»** — привязка сохраняется и применяется по подписанию документа; новое значение действует на последующие действия.

## Interaction & Animation

Добавление партии — fade-in новой строки таблицы. Переключение результата проверки — плавное раскрытие полей брака. Смена статуса поставки — плавная смена бейджа.

## Зависимости и ограничения

Принятые партии после подтверждения попадают в реестр `1.7.5. Stock & Batches Page`, откуда затем расходуются автоматически по FIFO (см. `1.7.0. Warehouse Overview`). Склад для размещения выбирается из `1.7.6`. Долги поставщика видны на `1.7.1`. Документ о приёмке/отмене создаётся в модуле документооборота (`1.5`) с нуля или из шаблона склада.

| Просмотр | `WAREHOUSE_SUPPLY_GET` |
| Все действия приёмки: «Новая партия», правка и проверка партий, «Подтвердить приёмку», «Отменить поставку», «Возобновить приёмку» (отдельных прав на подтверждение и отмену нет) | `WAREHOUSE_SUPPLY_RECEIVE` |

## Acceptance criteria

* Переход на страницу приёмки не открывает окно партии автоматически; партии добавляются кнопкой «Новая партия» через модальное окно с формой приёмки партии (данные лота и результат проверки), их может быть несколько и добавлять можно до завершения приёмки.
* Принятое и бракованное количество партии вводятся отдельными полями; их сумма равна количеству по накладной.
* Резолюция «Отменить всю поставку» ведёт к отмене поставки со всеми её партиями.
* Подтверждение приёмки открывает окно со списком партий (ID, товар) и выбором склада типа main для каждой принятой партии.
* При включённом документообороте документ прикрепляется при подтверждении и при отмене (с нуля или из шаблона); зачисление на склады и окончательная отмена происходят после подписания (или отправки, если подписи не нужны); до этого действуют статусы «Предварительно принята»/«Предварительно отменена».
* После подтверждения или отмены кнопки заблокированы; поставка и партии не удаляются; отменённую поставку можно возобновить, отменённые партии остаются отменёнными и не зачисляются.
* Долг поставщика по резолюции «В долг» создаётся при подтверждении приёмки и отражается на карточке поставщика.
* Состояния empty/loading/error/permissions обработаны.
* Партия с прошлым сроком годности не принимается; суммарное количество по партиям не превышает ожидаемого, допустима полная или неполная поставка.
* Поставку без партий нельзя принять, только отменить.
* К поставке привязывается не более одного документа.
