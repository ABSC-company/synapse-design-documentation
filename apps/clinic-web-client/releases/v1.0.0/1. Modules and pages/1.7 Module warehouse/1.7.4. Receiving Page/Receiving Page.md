# 1.7.4 Receiving Page (Приёмка поставки)

## Спецификация страницы интерфейса

* **Название страницы:** Приёмка поставки
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Вложенный экран (процесс), открывается из заказа на поставку
* **Маршрут:** `/warehouse/supplies/:id`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.4. Receiving`. Не пункт бокового меню.

---

## Назначение страницы и сценарии использования

Пошаговая приёмка фактической поставки по подтверждённому заказу: регистрация партий с указанием срока годности, серии и сертификата, регистрация результата проверки каждой партии (в т.ч. брак с выбором резолюции) — количественно, без создания индивидуальных кодов на единицу товара (см. «Изменено» в `WarehouseModule.md` §1).

С помощью страницы пользователь может:

1. Инициировать приёмку по заказу (если ещё не начата).
2. Регистрировать партии с обязательными данными лота — срок годности, серия, сертификат.
3. Регистрировать результат проверки каждой партии — количество принято / количество брака.
4. При браке — выбрать резолюцию (отменить всю поставку / отклонить дефектное количество / зафиксировать как долг поставщика).
5. Видеть сводку принятого/забракованного и итоговый статус поставки.

## User Flows / Task Flows

### Flow 1. Инициация приёмки
1. Переход из `1.7.3` с кнопки «Инициировать приёмку».
2. Создаётся `supply` в статусе `in_progress` — без выбора способа приёмки (поштучно/партиями): приёмка всегда ведётся по партиям с количествами.

### Flow 2. Регистрация проверки — товар принят
1. Кладовщик добавляет партию: данные лота (дата производства, срок годности, серия, сертификат — **обязательны всегда**, не только при определённом способе приёмки), заявленное количество.
2. Указывает результат «Принято» и количество принятого — партия сохраняется с `quantity_accepted`, счётчик остатка по ней **не создаёт индивидуальных кодов**, увеличивается только количество.

### Flow 3. Регистрация проверки — брак
1. Указывает количество брака → выбор резолюции:
   - **Отменить всю поставку** — вся `supply` переходит в `rejected`/`canceled`, ничего не принимается, форма закрывается.
   - **Не принимать дефектное количество** — дефектное количество просто не входит в `quantity_accepted`, долг не создаётся.
   - **Зафиксировать как долг** — дефектное количество принимается как выявленный брак партии, создаётся запись долга поставщика на это количество (видна на `1.7.1`, вкладка «Долги»).
2. Причина брака указывается обязательно.

### Flow 4. Финализация приёмки (гейтуемое действие)
1. Если сопроводительный документ (накладная-основание) обязателен — кладовщик прикрепляет его **отдельным действием** «Прикрепить документ» в блоке «Связанные документы» (паттерн `1.7.0. Warehouse Overview`) — доступно в любой момент процесса приёмки, не обязательно после последней проверки.
2. После регистрации последней ожидаемой проверки система автоматически пытается перевести статус поставки в «Принято»/«Частично принято» (см. открытый вопрос `WarehouseModule.md` §4.22/§12.5: финализирующий вызов, вероятно, последняя `POST /supplies/:id/inspections`, — точный триггер требует подтверждения бэкендом). Этот вызов не содержит и не может содержать ссылку на документ — привязка уже случилась (или не случилась) на шаге 1.
3. Если документ обязателен, но не привязан — кладовщик регистрирует проверки как обычно (это не блокируется, см. edge cases), но финальный переход статуса не наступит, пока документ не появится — блок «Связанные документы» покажет пустое состояние с призывом прикрепить.
4. С привязанным, но ещё не подписанным документом — поставка остаётся `in_progress`, а блок «Связанные документы» показывает «Ожидает подписания»; уже зарегистрированные партии видны, но общий статус поставки не меняется, пока не подпишут.

### Flow 5. Размещение на склад
1. После приёмки принятое по каждой партии количество требует явного размещения на склад типа «Поставочный» (простой выбор склада + «Разместить») — отдельным шагом на этой же странице, не автоматически. Размещение создаёт строку остатка (`storage_stock`) для этой партии на выбранном складе — партия появится на `1.7.5. Stock & Batches Page` с указанным сроком годности, войдёт в очередь автоматического расходования по FIFO (см. `1.7.0. Warehouse Overview`, «Паттерн «Списание по FIFO»»).

## Состояния и edge cases

### Empty
Приёмка только инициирована, партий ещё нет — «Добавьте первую партию» + кнопка.

### Loading / Error
Спиннер на сохранении проверки; toast при сбое.

### Permissions
`WAREHOUSE_SUPPLY_RECEIVE` — вся страница; без права — read-only просмотр (`WAREHOUSE_SUPPLY_GET`).

### Edge cases
* «Отменить всю поставку» доступно в любой момент, пока `status: in_progress` — отменяет только ещё не проверенные позиции; уже принятые партии остаются принятыми. Резолюция «отменить всю поставку» в форме проверки относится к конкретной партии, где обнаружен брак, требующий отмены всей поставки, — если нужно отменить уже частично принятую поставку целиком, используется отдельная кнопка «Отменить поставку целиком», доступная всегда в `in_progress`.
* Пока сопроводительный документ не подписан, кладовщик может продолжать регистрировать новые партии/проверки — гейтуется только финальный переход статуса поставки, не сам процесс регистрации.

## Interaction & Animation

Добавление партии — fade-in новой строки таблицы. Переключение результата «Принято»/«Брак» — плавное раскрытие доп. полей.

## Зависимости и ограничения

Принятые партии после размещения на склад попадают в реестр `1.7.5. Stock & Batches Page`, откуда затем расходуются автоматически по FIFO (см. `1.7.0. Warehouse Overview`). Размещение на склад — выбор из `1.7.6`. Долги поставщика видны на `1.7.1`.

## Acceptance criteria

* Приёмка регистрирует партии с обязательными данными лота (срок годности, серия, сертификат) без выбора способа приёмки.
* Регистрация проверки увеличивает принятое количество партии при «Принято», предлагает 3 резолюции при наличии брака.
* Финализация корректно ведёт себя при обоих случаях обязательности сопроводительного документа.
* Итоговая сводка отражает принятое/забракованное количество.
* Долг поставщика по резолюции «В долг» отражается на карточке поставщика.
* Состояния empty/loading/error/permissions обработаны.
