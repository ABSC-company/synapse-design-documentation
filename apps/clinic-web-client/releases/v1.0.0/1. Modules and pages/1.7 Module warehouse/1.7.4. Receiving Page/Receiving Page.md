# 1.7.4 Receiving Page (Приёмка поставки)

## Спецификация страницы интерфейса

* **Название страницы:** Приёмка поставки
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Вложенный экран (процесс), открывается из заказа на поставку
* **Маршрут:** `/warehouse/supplies/:id`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.4. Receiving`. Не пункт бокового меню.

---

## Назначение страницы и сценарии использования

Пошаговая приёмка фактической поставки по подтверждённому заказу: выбор способа приёмки (поштучно/партиями), регистрация результата проверки каждой единицы/партии (в т.ч. брак с выбором резолюции), автоматическое создание кодов маркировки для принятого товара.

С помощью страницы пользователь может:

1. Инициировать приёмку по заказу (если ещё не начата).
2. Выбрать способ приёмки (`unit`/`batch`).
3. Регистрировать результат проверки каждой единицы/партии — принято или брак.
4. При браке — выбрать резолюцию (отменить всю поставку / отклонить единицу / зафиксировать как долг поставщика).
5. Видеть сводку принятого/забракованного и итоговый статус поставки.

---

## User Flows / Task Flows

### Flow 1. Инициация приёмки
1. Переход из `1.7.3` с кнопки «Инициировать приёмку».
2. Модалка: выбор `receiving_type` (поштучно/партиями).
3. Создаётся `supply` в статусе `in_progress`.

### Flow 2. Регистрация проверки — товар принят
1. Кладовщик добавляет партию/единицу: данные партии (дата производства, срок годности, серия, сертификат — обязательны при `receiving_type: batch`), количество.
2. Отмечает результат «Принято» → создаётся код маркировки в `in_stock` (гранулярность зависит от `receiving_type`).

### Flow 3. Регистрация проверки — брак
1. Результат «Брак» → выбор резолюции:
   - **Отменить всю поставку** — вся `supply` переходит в `rejected`/`canceled`, коды не создаются, форма закрывается.
   - **Не принимать единицу** — единица не учитывается, код не создаётся.
   - **Зафиксировать как долг** — единица принимается как дефектная (код в статусе `defective`), создаётся запись долга поставщика (видна на `1.7.1`, вкладка «Долги»).
2. Причина брака указывается обязательно.

### Flow 4. Финализация приёмки (гейтуемое действие)
1. Если сопроводительный документ (накладная-основание) обязателен — кладовщик прикрепляет его **отдельным действием** «Прикрепить документ» в блоке «Связанные документы» (паттерн `1.7.0. Warehouse Overview`) — доступно в любой момент процесса приёмки, не обязательно после последней проверки.
2. После регистрации последней ожидаемой проверки система автоматически пытается перевести статус поставки в «Принято»/«Частично принято» (см. открытый вопрос `WarehouseModule.md` §4.22/§12.5: финализирующий вызов, вероятно, последняя `POST /supplies/:id/inspections`, — точный триггер требует подтверждения бэкендом). Этот вызов не содержит и не может содержать ссылку на документ — привязка уже случилась (или не случилась) на шаге 1.
3. Если документ обязателен, но не привязан — кладовщик регистрирует проверки как обычно (это не блокируется, см. edge cases), но финальный переход статуса не наступит, пока документ не появится — блок «Связанные документы» покажет пустое состояние с призывом прикрепить.
4. С привязанным, но ещё не подписанным документом — поставка остаётся `in_progress`, а блок «Связанные документы» показывает «Ожидает подписания»; коды маркировки уже созданных партий видны, но общий статус поставки не меняется, пока не подпишут.

### Flow 5. Размещение на склад
1. После приёмки принятые коды требуют явного размещения на склад типа «Поставочный» (простой выбор склада + «Разместить») — отдельным шагом на этой же странице, не автоматически.

## Визуал: High-Fidelity mockups

1. Таблица партий с раскрытием строки для просмотра кодов маркировки, созданных по этой партии.
2. Резолюция брака — радио-группа, раскрывается только при выборе «Брак».
3. Итоговая сводка — компактная строка внизу, не отдельная секция.
4. Блок «Связанные документы» — виден только когда документооборот включён и/или есть активная запись.

## Состояния и edge cases

### Empty
Приёмка только инициирована, партий ещё нет — «Добавьте первую партию/единицу» + кнопка.

### Loading / Error
Спиннер на сохранении проверки (создаёт код маркировки — не мгновенная операция); toast при сбое.

### Permissions
`WAREHOUSE_SUPPLY_RECEIVE` — вся страница; без права — read-only просмотр (`WAREHOUSE_SUPPLY_GET`).

### Edge cases
* «Отменить всю поставку» доступно в любой момент, пока `status: in_progress` — отменяет уже созданные коды текущей сессии проверки? (нет — только ещё не проверенные позиции; уже принятые партии остаются принятыми, резолюция «отменить всю поставку» относится к конкретной проверке, где обнаружен брак, требующий отмены — если нужно отменить уже частично принятую поставку целиком, используется отдельная кнопка «Отменить поставку целиком», доступная всегда в `in_progress`).
* Гранулярность кода (`unit`/`aggregate`) зависит от `receiving_type`, выбранного один раз при инициации — не меняется по ходу приёмки.
* Пока сопроводительный документ не подписан, кладовщик может продолжать регистрировать новые партии/проверки — гейтуется только финальный переход статуса поставки, не сам процесс регистрации.

## Interaction & Animation

Добавление партии — fade-in новой строки таблицы. Переключение результата «Принято»/«Брак» — плавное раскрытие доп. полей.

## Зависимости и ограничения

Коды маркировки, созданные здесь, попадают в реестр `1.7.5`. Размещение на склад — выбор из `1.7.6`. Долги поставщика видны на `1.7.1`.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр | `WAREHOUSE_SUPPLY_GET` |
| Приёмка/регистрация проверки | `WAREHOUSE_SUPPLY_RECEIVE` |

## Acceptance criteria

* Приёмка инициируется с выбором способа (поштучно/партиями).
* Регистрация проверки создаёт код маркировки при «Принято», предлагает 3 резолюции при «Брак».
* Финализация корректно ведёт себя при обоих случаях обязательности сопроводительного документа.
* Итоговая сводка отражает принятое/забракованное количество.
* Долг поставщика по резолюции «В долг» отражается на карточке поставщика.
* Состояния empty/loading/error/permissions обработаны.
