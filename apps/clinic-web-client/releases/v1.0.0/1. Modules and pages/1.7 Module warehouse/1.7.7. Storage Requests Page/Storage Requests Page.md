# 1.7.7 Storage Requests Page (Запросы на пополнение)

## Спецификация страницы интерфейса

* **Название страницы:** Запросы на пополнение
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка обработки
* **Основные роли:** Сотрудник потребительского отдела (инициатор), Кладовщик (обработка)
* **Маршрут:** `/warehouse/storage-requests`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.7. Storage Requests`.

---

## Назначение страницы и сценарии использования

Запрос сотрудника потребительского склада (например, отделения) на пополнение конкретными товарами и его обработка кладовщиком основного склада: подтверждение, отклонение или фактическая выдача с привязкой к конкретным кодам маркировки.

С помощью страницы пользователь может:

1. Создать запрос на пополнение (список товаров с количеством).
2. Просматривать список запросов, фильтровать по своему складу/статусу.
3. Обработать запрос: подтвердить, отклонить, выдать (гейтуемое действие).

---

## User Flows / Task Flows

### Flow 1. Создание запроса
1. Сотрудник потребительского склада — «+ Новый запрос».
2. Форма: склад-инициатор (предзаполнен, если у пользователя одно основное место), список позиций «Товар + количество» (минимум одна).
3. Сохранение → запрос в статусе «Создан».

### Flow 2. Обработка — подтверждение/отклонение
1. Кладовщик открывает запрос → «Подтвердить» (может скорректировать количество по позициям перед подтверждением) или «Отклонить» (причина обязательна).
2. Подтверждение переводит запрос в «Подтверждён» — не гейтуется документом.

### Flow 3. Выдача (гейтуемое действие)
1. Из подтверждённого запроса — кладовщик для каждой позиции выбирает конкретный код маркировки (система предлагает подходящие по товару/складу коды `in_stock`) и количество к выдаче — эта часть формы не зависит от документа и заполняется всегда.
2. Если сопроводительный документ обязателен — до кнопки «Выдать» пользователь отдельным действием «Прикрепить документ» в блоке «Связанные документы» привязывает документ (паттерн `1.7.0`); кнопка «Выдать» неактивна, пока документ не привязан.
3. Нажатие «Выдать» отправляет только позиции с выбранными кодами (`{ action: "issue", items }`, `WarehouseModule.md` §12.7) — без ссылки на документ, она уже установлена на шаге 2.
4. `deferred: false` — запрос переходит в «Выполнен», позиции получают `source_marking_code_id`, коды разделяются/перемещаются на склад-получатель. `deferred: true` — запрос остаётся «Подтверждён», блок «Связанные документы» показывает «Ожидает подписания», переход в «Выполнен» происходит автоматически после подписания.

## Состояния и edge cases

### Empty
Нет запросов — «Запросов пока нет» (+ «Новый запрос», если есть право создания).

### Loading / Error
Спиннер на выдаче (создаёт события движения кодов); toast при сбое.

### Permissions
`WAREHOUSE_STORAGE_REQUEST_GET` — просмотр; `WAREHOUSE_STORAGE_REQUEST_CREATE` — создание; `WAREHOUSE_STORAGE_REQUEST_PROCESS` — подтверждение/отклонение/выдача.

### Edge cases
* Попытка «Выдать» до подтверждения — кнопка недоступна на UI; сервер дополнительно отклоняет `409 STORAGE_REQUEST_NOT_APPROVED`.
* Код, выбранный для выдачи, имеет меньше остатка, чем подтверждённое количество, — инлайн-ошибка, форма не отправляется.
* Изменение количества позиции доступно только пока запрос в статусе «Создан» (`PATCH /storage-requests/:id/items/:itemId`) — после подтверждения количество фиксируется через сам процесс подтверждения.

## Interaction & Animation

Раскрытие селектора кода — dropdown с поиском. Подтверждение выдачи — модалка с итоговой сводкой перед отправкой.

## Зависимости и ограничения

Коды маркировки для выдачи берутся из реестра `1.7.5`, остаток — со склада-источника (`1.7.6`). Выдача создаёт события `split`/`moved` в истории кода.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр | `WAREHOUSE_STORAGE_REQUEST_GET` |
| Создание | `WAREHOUSE_STORAGE_REQUEST_CREATE` |
| Обработка (подтвердить/отклонить/выдать) | `WAREHOUSE_STORAGE_REQUEST_PROCESS` |

## Acceptance criteria

* Создание запроса требует минимум одну позицию «товар + количество».
* Подтверждение позволяет скорректировать количество по позициям; отклонение требует причину.
* Выдача доступна только из подтверждённого статуса, требует выбора конкретного кода на каждую позицию, корректно ведёт себя в обоих случаях обязательности документа.
* Блок «Связанные документы» отражает статус инициированной выдачи.
* Состояния empty/loading/error/permissions обработаны.
