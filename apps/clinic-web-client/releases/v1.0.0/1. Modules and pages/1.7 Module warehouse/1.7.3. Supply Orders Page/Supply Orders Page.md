# 1.7.3 Supply Orders Page (Заказы на поставку)

## Спецификация страницы интерфейса

* **Название страницы:** Заказы на поставку
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр заказов на поставку (только заказы)
* **Маршрут:** `/warehouse/supply-orders`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0. Warehouse Overview`. Техническая реализация — `1.7.3. Supply Orders`. Подтверждение, отмена заказа и поставки по нему — на странице заказа `1.7.3.1`.

---

## Назначение страницы и сценарии использования

Реестр **только заказов** на поставку товаров — по одной позиции товара каждый. Поставки и приёмка на этой странице не отображаются: клик по заказу открывает страницу заказа `1.7.3.1` с поставками по этому заказу, а клик по поставке — страницу приёмки `1.7.4`.

В боковом меню это вложенная цепочка: **Заказы на поставку → Заказ n → Поставка n** (см. `1.7.0. Warehouse Overview`).

С помощью страницы пользователь может:

1. Просматривать заказы, фильтровать по поставщику/статусу.
2. Создавать заказ (поставщик, товар, количество).
3. Открывать заказ кликом по строке — переход на страницу заказа `1.7.3.1`.

---

## User Flows / Task Flows

### Flow 1. Создание заказа
1. «+ Создать заказ» → выбор поставщика (влияет на список доступных товаров — только позиции с активным договором этого поставщика) → товар → количество.
2. Сохранение → заказ в статусе «Черновик».

### Flow 2. Переход к заказу
1. Клик по строке заказа открывает страницу заказа `1.7.3.1`: там подтверждение или отмена заказа, сопроводительный документ и список поставок по заказу.
2. Контекстного меню с действиями над заказом или поставкой у строк нет — все действия выполняются внутри страницы заказа.

## Визуал: High-Fidelity mockups

1. Статусные вкладки-фильтры вместо dropdown — заказы просматриваются пачками по статусу.
2. Строка заказа целиком кликабельна, курсор-«рука»; в колонке «Статус» для заказа с незавершённой приёмкой — дополнительная метка «Идёт приёмка».
3. Реестр не содержит поставок и кнопок приёмки.

---

## Состояния и edge cases

### Empty
Нет заказов — «Заказов пока нет» + «+ Создать заказ».

### Loading / Error
Скелетон таблицы; toast при сбое.

### Permissions
`WAREHOUSE_SUPPLY_ORDER_GET` — просмотр; `WAREHOUSE_SUPPLY_ORDER_CREATE` — создание.

### Edge cases
* Товар в форме создания заказа ограничен номенклатурой, привязанной к выбранному поставщику активным договором (`supplier_products`, `1.7.1`).
* Заказ можно перевести в «Выполнен»/«Частично выполнен» только автоматически (по подтверждению связанной приёмки) — ручного действия нет.

---

## Interaction & Animation

Стандартные для реестра. Переход на страницу заказа — без модального окна, обычная навигация; в боковом меню под пунктом «Заказы на поставку» раскрывается вложенный элемент «Заказ n».

## Зависимости и ограничения

Список товаров при создании заказа зависит от `1.7.1. Suppliers Page` (договоры). Дальше по цепочке: страница заказа `1.7.3.1`, затем приёмка `1.7.4`.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр реестра | `WAREHOUSE_SUPPLY_ORDER_GET` |
| Создание заказа | `WAREHOUSE_SUPPLY_ORDER_CREATE` |

---

## Acceptance criteria

* Реестр показывает только заказы, фильтруется по статусу и поставщику, поддерживает поиск и пагинацию.
* Форма создания ограничивает товары номенклатурой выбранного поставщика.
* Клик по заказу открывает страницу заказа `1.7.3.1`; контекстного меню у строк нет.
* Состояния empty/loading/error/permissions обработаны.
