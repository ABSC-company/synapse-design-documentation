# 1.7.22 Inventory Assets Page (ТМЦ)

## Спецификация страницы интерфейса

* **Название страницы:** ТМЦ (товарно-материальные ценности)
* **Модуль:** Warehouse (Склад)
* **Тип страницы:** Реестр + карточка закрепления
* **Основные роли:** Заведующий складом, Заведующий отделением (получатель закрепления)
* **Маршрут:** `/warehouse/items`
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.7.0.2. Warehouse Overview`. Техническая реализация — `1.7.8. Inventory Assets`.

---

## Назначение страницы и сценарии использования

Учёт основных средств и инвентаря клиники (оборудование, мебель, оргтехника) — в отличие от расходников (товаров), ТМЦ не расходуются, а закрепляются за складом/отделом/сотрудником и переиспользуются.

С помощью страницы пользователь может:

1. Просматривать каталог ТМЦ с фильтрами по категории/статусу.
2. Создавать/редактировать единицу ТМЦ, списывать.
3. Закреплять единицу за складом, отделом или сотрудником; снимать закрепление; смотреть историю закреплений.

---

## User Flows / Task Flows

### Flow 1. Создание единицы ТМЦ
1. «+ Добавить ТМЦ» → форма: название, категория (оборудование/мебель/оргтехника), инвентарный номер, стоимость, дата приобретения.
2. Сохранение → статус «На складе», закрепления нет.

### Flow 2. Закрепление
1. В карточке — «Закрепить»: выбор минимум одного из склад/отдел/ответственный сотрудник, примечание о состоянии.
2. Сохранение закрывает предыдущее активное закрепление (если было) и создаёт новое — единица переходит в статус «В использовании».

### Flow 3. Снятие закрепления
1. «Снять закрепление» → запись закрепления помечается как завершённая (не удаляется), единица возвращается к статусу «На складе» (либо остаётся «В использовании», если сразу указано новое — тогда это Flow 2).

### Flow 4. Списание
1. «Списать» → статус переходит в «Списано» (терминальный).

## Визуал: High-Fidelity mockups

1. Таблица каталога — компактная, статус-бейдж + текущее закрепление одной строкой.
2. История закреплений — вертикальный таймлайн, аналогично «Карьере» в HR (только для чтения).
3. Форма закрепления — минимум одно из трёх полей обязательно, валидируется на клиенте до отправки.

## Состояния и edge cases

### Empty
Нет ТМЦ по фильтру — «Ничего не найдено» + «Сбросить фильтры». История закреплений пуста — «Закреплений не было».

### Loading / Error
Скелетон таблицы/карточки; toast при сбое.

### Permissions
`WAREHOUSE_ITEM_GET` — просмотр; `WAREHOUSE_ITEM_MANAGE` — CRUD/списание; `WAREHOUSE_ITEM_ALLOCATION_MANAGE` — закрепление/снятие.

### Edge cases
* Списанная единица (`written_off`) — «Закрепить»/«Списать» скрыты, только просмотр истории.
* Новое закрепление поверх активного автоматически завершает предыдущее — предупреждение на UI перед подтверждением («Текущее закрепление будет завершено»).

---

## Interaction & Animation

Переключение категорий — мгновенный фильтр. Появление узла истории при новом закреплении — fade-in сверху.

## Зависимости и ограничения

Склад/отдел/сотрудник для закрепления — справочники Structure Module / HR Module. ТМЦ не связаны с кодами маркировки (`1.7.19`) — это отдельная, непотребляемая категория активов.

## Роли / права

| Действие | Право |
|---|---|
| Просмотр | `WAREHOUSE_ITEM_GET` |
| CRUD / списание | `WAREHOUSE_ITEM_MANAGE` |
| Закрепление / снятие | `WAREHOUSE_ITEM_ALLOCATION_MANAGE` |

---

## Acceptance criteria

* Каталог фильтруется по категории, поддерживает поиск.
* Форма закрепления требует минимум одно из склад/отдел/сотрудник.
* Новое закрепление автоматически завершает предыдущее активное с предупреждением.
* Списание — терминальный статус, скрывающий действия закрепления.
* История закреплений отображается таймлайном, только для чтения.
* Состояния empty/loading/error/permissions обработаны.
