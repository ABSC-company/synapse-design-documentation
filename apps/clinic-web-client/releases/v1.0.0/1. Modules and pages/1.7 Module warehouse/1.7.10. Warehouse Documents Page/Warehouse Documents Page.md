# 1.7.10 Warehouse Documents (Складское делопроизводство)

## Спецификация страницы интерфейса

* **Название страницы:** Складское делопроизводство
* **Модуль:** Warehouse — представление поверх модуля документооборота
* **Тип страницы:** Реестр документов (ЭДО), отфильтрованный по складской принадлежности
* **Основные роли:** Заведующий складом, Кладовщик, Руководитель
* **Маршрут:** `/warehouse/documents`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Базовая механика реестра, просмотра и подписания документов описана в модуле **1.5. Document Management Module** (страницы 1.5.1–1.5.4). Здесь — складская обёртка: те же документы, но сгруппированные по бизнес-процессам склада.

---

## Назначение страницы и сценарии использования

Единая точка доступа к сопроводительным документам складских процессов: заказы на поставку, приёмка и отмена поставок, запросы складов, ревизии.

С помощью страницы пользователь может:

1. Просматривать складские документы, сгруппированные по процессам (папкам).
2. Фильтровать по процессу, складу, статусу подписания, автору, периоду.
3. Открывать документ для просмотра и подписания (→ 1.5.2).
4. Видеть, к какому складскому действию (заказу, поставке, запросу, ревизии) относится документ, и переходить к нему.

---

## User Flows / Task Flows

### Flow 1. Навигация по процессам
1. Пользователь открывает «Складское делопроизводство».
2. Система показывает вкладки-папки: Все, Заказы на поставку, Приёмка поставок, Отмена поставок, Запросы складов, Ревизии, Основная.
3. Пользователь выбирает папку, список обновляется.

### Flow 2. Открытие и подписание документа
1. Клик по документу → страница документа (механика 1.5.2): метаданные, подписанты, история.
2. Подписание или отказ — по правилам ЭДО.

### Flow 3. Откуда берутся документы
1. Документ создаётся в карточке складского действия кнопкой «Прикрепить документ» (подтверждение заказа, приёмки, отмена поставки, выдача по запросу склада, завершение ревизии) и сразу попадает в папку своего процесса. Создать документ на этой странице нельзя.

### Flow 4. Переход к действию
1. В строке документа — ссылка на связанное действие (заказ, поставка, запрос, ревизия) → страница действия.

### Папки

Папки создаются автоматически после инициализации системы, названия на языке системы: Заказы на поставку, Приёмка поставок, Отмена поставок, Запросы складов, Ревизии, Основная. Каждый документ складского процесса сразу попадает в свою папку.

### Фильтры (Drawer)
* Процесс (папка), Склад, Статус подписания, Автор, Период.

### Строка документа
* Те же поля и действия, что в 1.5 (название, автор, даты, статус, прогресс подписания), плюс складская привязка: связанное действие и склад.
* Клик — переход к документу (1.5.2); ссылка на действие — на страницу действия.

### Создание документов
* Кнопки создания документа на странице нет: документ всегда прикрепляется к конкретному складскому действию.

## Состояния и edge cases

* **Empty:** «Складских документов нет» / пустая папка процесса.
* **Loading:** скелетон списка (как в 1.5).
* **Error:** блок ошибки + «Повторить»; toast при сбое действий.
* **Offline:** реестр из кэша; подписание заблокировано, toast.
* **Permissions:** документы и действия видны по правам ЭДО; без права на просмотр складских документов раздел скрыт.
* **Edge cases:** документ без привязки к действию (загруженный файл в «Основной»); действие уже отменено — документ остаётся в реестре со статусом «Отменён»; привязка снята — документ показывается без действия.

## Interaction & Animation

* Переключение папок — fade-смена списка.
* Поведение реестра, карточки и подписания — согласно 1.5.
* Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Базовая механика документов, редактор и шаблоны — модуль 1.5; Warehouse Module — владелец складской категории документов.
* Документы создаются в карточках складских действий (1.7.3.1, 1.7.4, 1.7.7, 1.7.9) блоком «Связанные документы».

---

## Acceptance criteria

* Раздел показывает складские документы ЭДО по папкам процессов (заказы на поставку, приёмка, отмена поставок, запросы складов, ревизии, основная) и общей вкладкой «Все».
* Фильтры по складу, процессу, статусу, автору и периоду работают на сервере.
* Из строки можно открыть документ и перейти к связанному действию.
* Кнопки создания документа на странице нет.
* Состояния empty/loading/error/permissions обработаны.
