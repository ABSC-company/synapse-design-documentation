# 1.8.3. Reports Page

## Спецификация страницы интерфейса

- Страница: Отчёты (журнал X/Z-отчётов)
- Модуль: Касса (Cash Register)
- Позиция в модуле: Четвёртая страница модуля
- Тип страницы: Реестр + просмотр документа
- Основные роли: Старший кассир, бухгалтер, администратор (кассир — доступ к отчётам своих смен через `1.8.2`)
- Статус документа: Draft
- Связанная бэкенд-документация: `CashRegisterModule.md` §4.3, §8 (включая новый `GET /reports`), §12.4

## Назначение страницы и сценарии использования

Сводный журнал всех X/Z-отчётов по клинике — не привязанный к конкретной смене экран для сверки выручки за период, по кассам и кассирам. Отдельный отчёт также открывается точечно из карточки смены (`1.8.2`) — это та же страница просмотра одного отчёта, вызванная из другого места.

Ключевые задачи страницы:

1. Просмотр списка всех отчётов с фильтрами (касса, кассир, тип X/Z, период).
2. Просмотр детального содержимого отчёта: суммы по методам оплаты, возвраты по методам, итоги.
3. Скачивание отчёта в Excel/PDF.

## User Flows / Task Flows для страницы

### Flow 1. Просмотр журнала отчётов

1. Пользователь открывает страницу «Отчёты».
2. Таблица со всеми отчётами (по умолчанию — текущий день).
3. Фильтры: касса, кассир, тип (X/Z), период дат.
4. Клик по строке открывает детальный просмотр (Flow 2).

### Flow 2. Детальный просмотр отчёта

1. Открывается модаль/панель с полным `snapshot`: суммы по каждому методу оплаты (`totals_by_method`), возвраты по методам (`refunds_by_method`), итоговая выручка, итоговые возвраты, net-сальдо, количество счетов и платежей.
2. Ссылки/список идентификаторов включённых счетов и платежей — сворачиваемый блок (могут быть десятки записей), не основной акцент экрана.
3. Кнопка **«Скачать»** — выбор формата (Excel/PDF) → скачивание файла.

### Flow 3. Скачивание отчёта

1. Пользователь нажимает «Скачать» в списке (быстрое действие в строке таблицы) либо в детальном просмотре.
2. Выбор формата — Excel или PDF (два явных пункта, не dropdown с сотней опций).
3. Файл скачивается напрямую (бинарный ответ, без промежуточного экрана прогресса — см. ограничения `CashRegisterModule.md` §12.4).

Общий layout страницы:

1. Слева: Sidebar в свёрнутом состоянии.
2. Сверху: **Page Header** — «Отчёты».
3. Контентная область: Toolbar (фильтры) + таблица отчётов + детальный просмотр (drawer/модаль).

## Структура: Wireframes

### Таблица отчётов

| Колонка | Описание |
|---|---|
| Тип | X / Z (иконка + бейдж, разные цвета) |
| Касса | Название кассы |
| Кассир | ФИО сотрудника, сформировавшего отчёт |
| Период | `period_from` — `period_to` |
| Выручка | `total_revenue` |
| Возвраты | `total_refunds` |
| Net | `net`, цветовая индикация (зелёный — положительный, красный — отрицательный, что штатно означает превышение возвратов над выручкой за период) |
| Действия | Иконка «Скачать» (быстрый доступ) |

### Детальный просмотр отчёта

- Заголовок: тип отчёта + период + касса + кассир.
- Карточки-метрики (крупные цифры): выручка, возвраты, net, количество счетов, количество платежей.
- Таблица «Суммы по методам оплаты»: строка на каждый метод (`cash`/`payme`/`click`/`terminal`/`uzum`/`combine`) с колонками «Оплачено» и «Возвращено».
- Сворачиваемый список идентификаторов включённых счетов/платежей.
- Кнопка «Скачать» (Excel/PDF).

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Тип отчёта — чёткая визуальная дифференциация X (промежуточный, нейтральный цвет) и Z (финальный, более насыщенный/акцентный цвет — подчёркивает его «закрывающий» характер).
2. Карточки-метрики в детальном просмотре — крупная типографика, как на дашбордах аналитики.
3. Таблица «Суммы по методам» — иконка метода оплаты рядом с названием (наличные/карта/логотипы Payme, Click, Uzum — если есть в дизайн-системе).
4. Net с отрицательным значением — выделяется красным, это нештатная, но не ошибочная ситуация (требует внимания бухгалтера).

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Таблица журнала отчётов (с X и Z вперемешку).
2. Детальный просмотр X-отчёта.
3. Детальный просмотр Z-отчёта.
4. Модаль выбора формата скачивания.
5. Состояние loading/empty/error.

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton таблицы; skeleton метрик в детальном просмотре |
| empty | Отчётов за период нет — «Нет данных», предложение сменить период |
| error | Ошибка загрузки — сообщение + «Повторить» |
| offline | Скачивание недоступно, список — только из кэша, если был загружен ранее |
| permissions | Страница скрыта без `CASH_REPORT_GET`; кнопка «Скачать» скрыта без `CASH_REPORT_DOWNLOAD` |

### Edge cases

1. У смены несколько X-отчётов подряд (частые передачи смены) — каждый отображается отдельной строкой со своим периодом, без визуального «слипания».
2. Отчёт с нулевой активностью за период (X-отчёт сразу после открытия смены, без единой операции) — все суммы «0», это штатное отображение, не ошибка/пустое состояние.
3. Скачивание отчёта с очень большим числом включённых счетов/платежей — согласно `CashRegisterModule.md` §10/§12.4 формирование одного отчёта синхронно (не должно требовать отдельного состояния «идёт формирование» на фронтенде для одиночного отчёта).
4. Неверный/отсутствующий формат при скачивании (гипотетически, если фронтенд некорректно собрал запрос) — `400 UNSUPPORTED_REPORT_FORMAT`, toast с ошибкой.

## Interaction & Animation

1. Открытие детального просмотра — slide-in справа (drawer), 300ms.
2. Скачивание — не блокирует интерфейс; в строке таблицы на время запроса иконка «Скачать» заменяется спиннером.
3. Цветовая индикация net — мгновенная, без анимации.

## Зависимости и ограничения

### API

1. `GET /cash-register/reports` — список с фильтрами (роут добавлен в рамках этой документации, см. `CashRegisterModule.md` §8, §12.4 — `ReportListItemDto`).
2. `GET /cash-register/reports/:id` — детальный отчёт (`ReportDto` с полным `snapshot`).
3. `GET /cash-register/reports/:id/download?format=excel|pdf` — скачивание.

### Роли и права

1. `CASH_REPORT_GET` — просмотр журнала и деталей.
2. `CASH_REPORT_DOWNLOAD` — скачивание.

## Acceptance criteria

1. Журнал отчётов фильтруется по кассе, кассиру, типу и периоду.
2. Детальный просмотр показывает полный `snapshot`: суммы/возвраты по методам, итоги, счётчики.
3. Скачивание в Excel и PDF доступно как из списка, так и из детального просмотра.
4. X- и Z-отчёты визуально различимы в списке.
5. Все состояния (loading/empty/error/offline/permissions) реализованы согласно таблице выше.
