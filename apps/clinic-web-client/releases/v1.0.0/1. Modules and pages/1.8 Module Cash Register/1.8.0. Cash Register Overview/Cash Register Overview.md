# 1.8.0. Cash Register Overview

## Спецификация страницы интерфейса

- Страница: Выбор кассы и открытие смены
- Модуль: Касса (Cash Register)
- Позиция в модуле: Первая страница — точка входа в модуль, до рабочего стола кассира
- Тип страницы: Выбор/действие (не рабочий экран)
- Основные роли: Кассир, старший кассир, сотрудник регистратуры (при включённой настройке), администратор
- Статус документа: Draft
- Связанная бэкенд-документация: `CashRegisterModule.md` §4.1–4.2, §6 (сценарии 1, 4, 5), §8, §12.2–12.3, §13

## Назначение страницы и сценарии использования

Страница — экран «входа в смену», аналогичный экрану выбора терминала в обычных POS-системах. Пока у сотрудника нет активной открытой смены, он не может попасть на рабочий стол кассира (`1.8.1`). Здесь же — управление справочником касс (создание/переименование/удаление), доступное только пользователям с правом `CASH_REGISTER_MANAGE`.

Ключевые задачи страницы:

1. Показать список физических/логических касс клиники со статусом занятости (открыта ли по ней смена).
2. Открыть новую смену на свободной кассе.
3. Если у текущего сотрудника уже есть открытая смена (в т.ч. открытая ранее на другом рабочем месте) — пропустить экран выбора и сразу перейти на `1.8.1`.
4. Управлять справочником касс (CRUD) — для ролей с соответствующим правом.
5. Явно и понятно объяснить отказ в доступе к кассирской роли (сотрудник регистратуры без включённой настройки).

## User Flows / Task Flows для страницы

### Flow 1. Вход с уже открытой сменой

1. Сотрудник открывает модуль «Касса».
2. Система проверяет наличие активной смены на текущего сотрудника (аналог `WorkShiftService.getActiveShift`).
3. Если смена уже открыта — экран выбора кассы не показывается, происходит немедленный редирект на `1.8.1. POS Page` с контекстом этой смены.

### Flow 2. Открытие новой смены

1. Сотрудник без активной смены видит список касс: занята/свободна.
2. Выбирает свободную кассу — кнопка **«Открыть смену»** становится активной.
3. Нажимает «Открыть смену» — подтверждающая модаль с названием кассы.
4. Система вызывает открытие смены; при успехе — редирект на `1.8.1`.
5. Если между отображением списка и нажатием кнопки кассу уже занял другой кассир (race condition) — toast «Касса уже занята» и список обновляется.

### Flow 3. Отказ в доступе (сотрудник регистратуры)

1. Сотрудник отдела «Регистратура» без включённой глобальной настройки `cash_register.registration_employee_as_cashier` нажимает «Открыть смену».
2. Система показывает информационное состояние (не toast-ошибку, а полноценный блок на странице): «Сотрудникам регистратуры недоступна роль кассира в этой клинике» с пояснением, что настройку включает администратор в Management Module.
3. Кнопки открытия смены скрыты/задизейблены для всех касс.

### Flow 4. Управление справочником касс (CRUD)

1. Пользователь с правом `CASH_REGISTER_MANAGE` видит кнопку **«Добавить кассу»** и, при наведении на строку списка, иконки «Редактировать»/«Удалить».
2. «Добавить кассу» — модаль с единственным полем «Название кассы».
3. «Редактировать» — та же модаль, предзаполненная текущим названием.
4. «Удалить» — подтверждающая модаль; если по кассе открыта смена — удаление блокируется на уровне API (`409 CASH_REGISTER_HAS_OPEN_SHIFT`), в UI кнопка удаления для занятой кассы сразу задизейблена с подсказкой «Нельзя удалить кассу с открытой сменой», без обращения к серверу.

Общий layout страницы:

1. Слева: Sidebar в свёрнутом состоянии.
2. Сверху: **Page Header** — «Касса», без стандартных кнопок регистратуры; вместо них — «Добавить кассу» (по праву `CASH_REGISTER_MANAGE`).
3. Контентная область: сетка карточек касс (не таблица — по аналогии с выбором терминала в POS/картой этажа, а не списком строк).

## Структура: Wireframes

### Карточка кассы (в сетке)

- Иконка кассового аппарата.
- Название кассы.
- Статус: бейдж «Свободна» (зелёный) / «Занята» — с именем текущего кассира (жёлтый/серый).
- Для свободной кассы — кнопка «Открыть смену» на карточке.
- Для занятой кассы, если текущий пользователь и есть её кассир (сессия истекла/страница перезагружена) — кнопка «Перейти к работе» вместо «Открыть смену».
- Иконки редактирования/удаления — в правом верхнем углу карточки, видны только при праве `CASH_REGISTER_MANAGE` и при наведении.

### Модаль открытия смены

- Заголовок «Открыть смену — {название кассы}».
- Текст-подтверждение с именем текущего сотрудника.
- Кнопки «Отмена» / «Открыть смену».

### Модаль CRUD кассы

- Заголовок «Новая касса» / «Редактировать кассу».
- Поле «Название» (обязательно).
- Кнопки «Отмена» / «Сохранить».

### Блок отказа в доступе (Flow 3)

- Иконка предупреждения.
- Текст: «Сотрудникам регистратуры недоступна роль кассира в этой клинике».
- Подпись: «Обратитесь к администратору, если это ошибка».

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Сетка карточек касс — 3–4 колонки на десктопе, адаптивно сужается на меньших экранах.
2. Карточка занятой кассы визуально «приглушена» (пониженный контраст) относительно свободной — свободные кассы визуально приоритетны.
3. Бейдж статуса — как в остальной системе (зелёный/жёлтый/серый, тот же паттерн, что бейджи статусов визитов в регистратуре).
4. Пустое состояние (касс ещё не создано) — крупная иллюстрация + кнопка «Добавить кассу» по центру.

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Sidebar в свёрнутом состоянии, Header модуля.
2. Сетка карточек касс (минимум: 1 свободная, 1 занятая текущим пользователем, 1 занятая другим).
3. Модаль открытия смены.
4. Модаль CRUD кассы (создание и редактирование).
5. Блок отказа в доступе (Flow 3).
6. Состояние loading (skeleton карточек).
7. Пустое состояние (нет касс).
8. Toast «Касса уже занята» (race condition, Flow 2, п. 5).

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton-карточки вместо сетки касс |
| empty | Касс не создано — иллюстрация + CTA «Добавить кассу» (только при праве `CASH_REGISTER_MANAGE`, иначе нейтральный текст «Обратитесь к администратору») |
| error | Ошибка загрузки списка касс — сообщение + кнопка «Повторить» |
| offline | Баннер отсутствия сети, открытие смены недоступно |
| permissions | Кнопки CRUD касс скрыты без `CASH_REGISTER_MANAGE`; кнопки открытия смены скрыты без `WORK_SHIFT_OPEN` |

### Edge cases

1. Смена уже открыта на текущего сотрудника на **другой кассе** (открыл на одном рабочем месте, зашёл с другого) — Flow 1 срабатывает независимо от рабочего места, редирект всегда идёт на актуальную смену.
2. Между загрузкой списка и кликом «Открыть смену» кассу занял другой кассир — `409 SHIFT_ALREADY_OPEN_ON_REGISTER`, toast и обновление статуса карточки без перезагрузки всей страницы.
3. Попытка удалить кассу с открытой сменой — кнопка удаления задизейблена на клиенте; если состояние устарело (открыли смену параллельно) — `409 CASH_REGISTER_HAS_OPEN_SHIFT` с той же формулировкой в toast.
4. Отключена настройка `cash_register.registration_employee_as_cashier` для сотрудника регистратуры — Flow 3, `403 CASHIER_NOT_ALLOWED`.
5. Название кассы при создании/редактировании пустое или дублирует существующее — инлайн-ошибка валидации (уникальность имени backend не гарантирует явно — см. открытый вопрос в фронтенд-документации).

## Interaction & Animation

1. Карточки касс — hover-приподнимание (elevation), плавный переход 150ms.
2. Модаль открытия/CRUD — fade-in с масштабированием, 250ms, идентично паттерну модалей в других модулях (Registry EMC).
3. После успешного открытия смены — короткая анимация перехода (fade) перед редиректом на `1.8.1`.
4. Статус карточки при race condition обновляется точечно (карточка «мигает» новым статусом), без перерисовки всей сетки.

## Зависимости и ограничения

### API

1. `GET /cash-register/registers` — список касс с `has_open_shift`.
2. `POST /cash-register/registers` / `PATCH /cash-register/registers/:id` / `DELETE /cash-register/registers/:id` — CRUD.
3. `POST /cash-register/shifts/open` — открытие смены.
4. Определение активной смены текущего сотрудника — нет отдельного клиентского роута в `CashRegisterModule.md`; используется `GET /cash-register/shifts?employee_id={me}&state=open` (см. открытый вопрос в фронтенд-документации о точном способе получения «моей активной смены»).

### Роли и права

1. `CASH_REGISTER_GET` — видимость страницы и списка касс.
2. `CASH_REGISTER_MANAGE` — CRUD касс.
3. `WORK_SHIFT_OPEN` — кнопка «Открыть смену».
4. `CASHIER_NOT_ALLOWED` (доменная ошибка, не право) — отдельно обрабатываемый сценарий для отдела «Регистратура».

### Feature flags

1. Показ страницы CRUD касс — по праву, отдельного флага не требуется.

## Acceptance criteria

1. При наличии активной смены сотрудник не видит экран выбора кассы — мгновенный редирект на `1.8.1`.
2. Список касс отображает актуальный статус занятости, обновляемый после каждого открытия/закрытия смены.
3. Открытие смены на занятой кассе невозможно — кнопка недоступна визуально до похода на сервер.
4. CRUD касс доступен только по праву `CASH_REGISTER_MANAGE`.
5. Удаление кассы с открытой сменой невозможно ни визуально, ни по факту (сервер вернёт `409`, если UI-блокировка была обойдена).
6. Сотрудник регистратуры без включённой настройки видит понятное объяснение отказа, а не сырую ошибку API.
7. Все состояния (loading/empty/error/offline/permissions) реализованы согласно таблице выше.
