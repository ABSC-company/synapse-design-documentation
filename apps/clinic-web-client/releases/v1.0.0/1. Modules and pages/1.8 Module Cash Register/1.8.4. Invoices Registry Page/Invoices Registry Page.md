# 1.8.4. Invoices Registry Page

## Спецификация страницы интерфейса

- Страница: Счета — реестр
- Модуль: Касса (Cash Register)
- Позиция в модуле: Пятая страница модуля
- Тип страницы: Реестр + карточка сущности
- Основные роли: Старший кассир, администратор, бухгалтер
- Статус документа: Draft
- Связанная бэкенд-документация: `PaymentsModule.md` §4.1, §5.1–5.2, §7 (сценарии 1, 5), §8

## Назначение страницы и сценарии использования

Полный реестр всех счетов клиники — в отличие от `1.8.1` (POS), где кассир видит счета только в контексте активного приёма оплаты, здесь — обзорная витрина для управленческого контроля: какие счета созданы, какие ещё не закрыты, где отменены позиции. Приём оплаты с этой страницы не выполняется напрямую — предполагается переход в `1.8.1` с этим счётом (либо использование этой страницы только для просмотра/отмены).

Ключевые задачи страницы:

1. Просмотр всех счетов клиники с фильтрами (статус, пациент, визит, период, закрыт/не закрыт).
2. Просмотр деталей счёта: позиции, их источник (услуга/пакет), история оплат.
3. Отмена счёта целиком либо отдельных позиций (до их оплаты).
4. Быстрый переход к оплате счёта на `1.8.1`.

## User Flows / Task Flows для страницы

### Flow 1. Просмотр реестра счетов

1. Пользователь открывает «Счета».
2. Таблица счетов с фильтрами: статус (`draft`/`partially_paid`/`paid`/`refunded`/`canceled`), закрыт/не закрыт, период, пациент/визит.
3. Клик по строке открывает карточку счёта.

### Flow 2. Карточка счёта

1. Модаль/drawer: пациент, визит, статус, признак `is_closed`.
2. Таблица позиций: наименование, источник (модуль-источник — услуга Services module, пакет и т.д.), цена, количество, `paid_amount`, статус позиции.
3. Блок истории оплат (переиспользует тот же компонент, что вкладка «Платежи» в `1.8.2`/история оплат в `1.8.1`).
4. Кнопка **«Оплатить»** (если есть неоплаченные позиции и есть право `PAYMENTS_PAYMENT_CREATE`) — переход на `1.8.1` с этим счётом предзагруженным в панель.

### Flow 3. Отмена счёта/позиций

1. В карточке счёта — кнопка **«Отменить»** на уровне счёта либо на уровне отдельной позиции (только для позиций в статусе `draft`, ещё не оплаченных).
2. Модаль подтверждения: «Позиция/счёт будут отменены, действие необратимо».
3. Подтверждение → `PATCH /invoices/:id/cancel`.
4. Статус позиции/счёта обновляется на `canceled`, кнопки отмены для уже отменённых позиций скрываются.

Общий layout страницы:

1. Слева: Sidebar в свёрнутом состоянии.
2. Сверху: **Page Header** — «Счета».
3. Контентная область: Toolbar (поиск, фильтры) + таблица счетов + карточка (drawer) при выборе строки.

## Структура: Wireframes

### Таблица счетов

| Колонка | Описание |
|---|---|
| № счёта | `id` |
| Пациент | ФИО + ссылка на ЭМК (переход в регистратуру) |
| Визит | Дата/номер визита в клинику |
| Статус | Бейдж: draft/partially_paid/paid/refunded/canceled |
| Закрыт | Иконка да/нет (`is_closed`) |
| Сумма | Итоговая сумма счёта по позициям |
| Оплачено | Сумма `paid_amount` по всем позициям |
| Создан | Дата создания |

### Карточка счёта

- Заголовок: № счёта, пациент, статус.
- Таблица позиций с колонкой «Источник» (иконка модуля: Services/Booking/пакет).
- Блок истории оплат.
- Кнопки: «Оплатить» (переход на `1.8.1`), «Отменить счёт», действие отмены на уровне строки позиции.

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Статус-бейджи счёта — переиспользуют цветовую палитру, уже принятую в системе для похожих статусов (зелёный paid, жёлтый partially_paid/draft, серый canceled, красный refunded).
2. Иконка `is_closed` — замок (закрыт) / открытый замок (не закрыт), с тултипом «Закрывается автоматически при завершении визита».
3. Источник позиции — небольшая иконка модуля перед наименованием (как иконки типов файлов в Registry EMC).

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Таблица счетов с разными статусами.
2. Карточка счёта с позициями разных источников.
3. Модаль отмены счёта/позиции.
4. Состояние loading/empty/error.
5. Кнопка «Оплатить» в карточке (переход на POS).

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton таблицы и карточки |
| empty | Счетов по фильтру нет — «Нет данных» |
| error | Ошибка загрузки — сообщение + «Повторить» |
| offline | Отмена недоступна, реестр — только просмотр из кэша |
| permissions | Кнопка «Отменить» скрыта без `PAYMENTS_INVOICE_CANCEL`; кнопка «Оплатить» скрыта без `PAYMENTS_PAYMENT_CREATE` |

### Edge cases

1. Попытка отменить уже оплаченную позицию — кнопка отмены недоступна для позиций не в статусе `draft` (согласно `PaymentsModule.md` §7, сценарий 4 — оплаченные позиции возвращаются, а не отменяются).
2. Счёт автоматически закрылся (визит завершён) между открытием карточки и попыткой добавить позицию — операция недоступна на этой странице в принципе (добавление позиций — прерогатива регистратуры/букинга, не кассы), поле только информативное.
3. Счёт с позициями из разных источников (услуга + проданный пакет) — корректное отображение иконок источника для каждой строки.
4. Переход «Оплатить» на счёт, который за время навигации стал `paid` другим кассиром — на `1.8.1` подтягивается актуальный статус, оплата блокируется с сообщением «Счёт уже оплачен» (тот же edge case, что и в `1.8.1`).

## Interaction & Animation

1. Открытие карточки счёта — slide-in справа (drawer), 300ms.
2. Переход «Оплатить» — переход на `1.8.1` с уже открытой панелью этого счёта (без повторного поиска).
3. Отмена — toast + точечное обновление статуса строки/позиции без перезагрузки всей таблицы.

## Зависимости и ограничения

### API

1. `GET /payments/invoices` (`GET /invoices`, `PaymentsModule.md` §8) — список с фильтрами.
2. `GET /invoices/:id` — детали счёта.
3. `PATCH /invoices/:id/cancel` — отмена счёта/позиций.
4. `GET /payments?invoice_id=` — история оплат счёта.

### Роли и права

1. `PAYMENTS_INVOICE_GET` — просмотр реестра и карточки.
2. `PAYMENTS_INVOICE_CANCEL` — отмена счёта/позиций.
3. `PAYMENTS_PAYMENT_CREATE` — кнопка «Оплатить» (переход на POS).
4. `PAYMENTS_PAYMENT_GET` — просмотр истории оплат в карточке.

## Acceptance criteria

1. Реестр счетов фильтруется по статусу, закрытости, пациенту/визиту и периоду.
2. Карточка счёта показывает все позиции с корректным источником и статусом, а также историю оплат.
3. Отмена доступна только для позиций/счетов в статусе `draft`.
4. Кнопка «Оплатить» открывает `1.8.1` с этим счётом предзагруженным.
5. Все состояния (loading/empty/error/offline/permissions) реализованы согласно таблице выше.
