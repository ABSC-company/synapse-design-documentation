# 1.8.2. Shifts Page

## Спецификация страницы интерфейса

- Страница: Смены — история и управление
- Модуль: Касса (Cash Register)
- Позиция в модуле: Третья страница модуля
- Тип страницы: Реестр + карточка сущности
- Основные роли: Кассир (свои смены), старший кассир/администратор (все смены)
- Статус документа: Draft
- Связанная бэкенд-документация: `CashRegisterModule.md` §4.2, §6 (сценарии 1–3), §8, §12.3

## Назначение страницы и сценарии использования

Реестр смен по всем кассам клиники, с карточкой конкретной смены (счета, платежи, X/Z-отчёты) и действиями управления текущей открытой сменой — передача и закрытие. Действия «Передать смену»/«Закрыть смену»/«Сформировать X-отчёт» также доступны быстрым доступом из Header страницы `1.8.1`, но описываются здесь как основной сценарий.

Ключевые задачи страницы:

1. Просмотр списка смен с фильтрами (касса, кассир, статус, период).
2. Просмотр деталей смены: счета и платежи, попавшие в неё, список сформированных отчётов.
3. Передача смены другому кассиру с автоформированием X-отчёта.
4. Закрытие смены с автоформированием Z-отчёта.
5. Формирование X-отчёта вручную, без передачи смены (промежуточная сверка в течение дня).

## User Flows / Task Flows для страницы

### Flow 1. Просмотр списка смен

1. Пользователь открывает страницу «Смены».
2. Таблица со всеми сменами (по умолчанию — текущий день, все кассы, доступные по правам пользователя).
3. Фильтры: касса, кассир, статус (открыта/закрыта), период дат.
4. Клик по строке открывает карточку смены (Flow 2).

### Flow 2. Карточка смены

1. Открывается модаль/панель с деталями: касса, кассир(ы) — если была передача, время открытия/закрытия.
2. Вкладка «Счета» — список счетов, попавших в смену (по `payments.work_shift_id`).
3. Вкладка «Платежи» — список платежей смены с методами и суммами.
4. Вкладка «Отчёты» — список X/Z-отчётов этой смены (краткая карточка каждого, клик открывает `1.8.3`).
5. Для открытой смены, принадлежащей текущему пользователю (или при праве управления чужими сменами) — кнопки «Передать смену», «Закрыть смену», «Сформировать X-отчёт».

### Flow 3. Формирование X-отчёта (промежуточная сверка)

1. В карточке открытой смены — кнопка **«Сформировать X-отчёт»**.
2. Подтверждающая модаль (X-отчёт не закрывает смену, но фиксирует срез — подчёркивается в тексте модали).
3. Подтверждение → `POST /shifts/:id/reports/x` → новый X-отчёт появляется во вкладке «Отчёты», предлагается сразу открыть/распечатать (переход на `1.8.3`).

### Flow 4. Передача смены

1. Кнопка **«Передать смену»** в карточке открытой смены.
2. Модаль: поиск/выбор нового кассира (сотрудники с правом `WORK_SHIFT_OPEN`, прошедшие ту же проверку `CashierPolicyService`, что и при открытии).
3. Предупреждение: «Будет автоматически сформирован X-отчёт от вашего имени».
4. Подтверждение → `POST /shifts/:id/transfer` → смена продолжается с новым кассиром, X-отчёт добавлен в список.
5. Текущий пользователь (передавший смену) теряет доступ к управлению сменой (может только просматривать), интерфейс возвращает его на `1.8.0` для выбора дальнейших действий (у него больше нет активной смены).

### Flow 5. Закрытие смены

1. Кнопка **«Закрыть смену»** в карточке открытой смены (либо из Header `1.8.1`).
2. Модаль подтверждения с явным предупреждением: «Смена будет закрыта, автоматически сформируется Z-отчёт. Действие необратимо».
3. Подтверждение → `POST /shifts/:id/close` → смена переходит в `close`, создаётся Z-отчёт.
4. Система сразу показывает Z-отчёт (переход на `1.8.3`) с предложением распечатать.
5. Пользователь теряет доступ к POS-экрану (`1.8.1`) — при следующем заходе в модуль будет предложено открыть новую смену (`1.8.0`).

Общий layout страницы:

1. Слева: Sidebar в свёрнутом состоянии.
2. Сверху: **Page Header** — «Смены», без специфичных кнопок создания (смена открывается только с `1.8.0`).
3. Контентная область: Toolbar (фильтры, поиск) + таблица смен + карточка (модаль/drawer) при выборе строки.

## Структура: Wireframes

### Таблица смен

| Колонка | Описание |
|---|---|
| Касса | Название кассы |
| Кассир | Текущий/последний кассир смены |
| Статус | Открыта / Закрыта (бейдж) |
| Открыта | Дата и время открытия |
| Закрыта | Дата и время закрытия либо «—» |
| Отчёты | Иконки количества X-отчётов + наличие Z-отчёта |

### Карточка/drawer смены

- Заголовок: касса + статус.
- Блок метаданных: кассир, время открытия/закрытия.
- Tab-меню: Счета / Платежи / Отчёты.
- Кнопки действий (только для открытой смены, с учётом прав): «Сформировать X-отчёт», «Передать смену», «Закрыть смену».

### Модали действий

- «Сформировать X-отчёт» — простое подтверждение.
- «Передать смену» — поиск кассира + предупреждение об автоформировании X-отчёта.
- «Закрыть смену» — предупреждение о необратимости + автоформировании Z-отчёта.

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Статус смены — бейдж: «Открыта» зелёный, «Закрыта» серый.
2. Открытая смена текущего пользователя выделяется в таблице (например, левая цветная полоса), чтобы её было легко найти среди списка.
3. Кнопка «Закрыть смену» — визуально «опаснее» (например, требует двойного подтверждения либо явно красный акцент), так как необратима.
4. Вкладка «Отчёты» в карточке — список компактных карточек-превью отчётов (тип, период, net-сумма), клик ведёт на `1.8.3`.

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Таблица смен с разными статусами.
2. Карточка открытой смены (с доступными действиями).
3. Карточка закрытой смены (только просмотр, без действий).
4. Модаль передачи смены (с поиском кассира).
5. Модаль закрытия смены (с предупреждением).
6. Состояние loading/empty/error.

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton таблицы и карточки |
| empty | Смен за период/по фильтру нет — «Нет данных», сброс фильтров |
| error | Ошибка загрузки — сообщение + «Повторить» |
| offline | Действия со сменой (передача/закрытие/X-отчёт) заблокированы |
| permissions | Действия скрыты без `WORK_SHIFT_TRANSFER`/`WORK_SHIFT_CLOSE`/`CASH_REPORT_CREATE` соответственно; чужие смены видны только с правом просмотра всех смен (не только своих) |

### Edge cases

1. Попытка передать/закрыть уже закрытую смену (устаревшее состояние экрана) — `409 SHIFT_NOT_OPEN`, карточка обновляется, действия скрываются.
2. Выбранный для передачи кассир не проходит `CashierPolicyService` (сотрудник регистратуры без настройки) — `403 CASHIER_NOT_ALLOWED`, инлайн-ошибка в модали передачи, поиск кассира остаётся открытым для выбора другого.
3. Смена передана несколько раз подряд — во вкладке «Отчёты» накапливается несколько X-отчётов, каждый привязан к соответствующему периоду и кассиру на момент передачи (`snapshot` неизменяем).
4. Пользователь без прав на просмотр чужих смен пытается открыть страницу — видит только свои смены (текущие и исторические), фильтр по кассиру скрыт либо зафиксирован на себе.
5. Z-отчёт формируется дольше ожидаемого (большой объём данных за смену) — индикатор загрузки в модали закрытия, без возможности повторно нажать «Закрыть» до завершения запроса.

## Interaction & Animation

1. Открытие карточки смены — slide-in справа (drawer), 300ms, как Drawer фильтра в Registry EMC.
2. Переключение вкладок карточки — cross-fade, 200ms.
3. Модали действий — fade-in с масштабированием, 250ms.
4. После успешного действия (X-отчёт/передача/закрытие) — toast + обновление строки таблицы без полной перезагрузки списка.

## Зависимости и ограничения

### API

1. `GET /cash-register/shifts` — список с фильтрами.
2. `GET /cash-register/shifts/:id` — детали (включая счета/платежи/отчёты).
3. `POST /cash-register/shifts/:id/reports/x` — X-отчёт.
4. `POST /cash-register/shifts/:id/transfer` — передача.
5. `POST /cash-register/shifts/:id/close` — закрытие.

### Роли и права

1. `WORK_SHIFT_GET` — просмотр списка/карточки.
2. `WORK_SHIFT_TRANSFER` — передача.
3. `WORK_SHIFT_CLOSE` — закрытие.
4. `CASH_REPORT_CREATE` — формирование X-отчёта.

> Открытый вопрос: право «видеть смены только свои vs все» не выделено отдельным кодом в `CashRegisterModule.md` §9 — `WORK_SHIFT_GET` описан как единое право просмотра. Разграничение «свои/все» либо на уровне фильтрации по `employee_id = me` на фронтенде (без серверного ограничения), либо требует уточнения у бэкенда перед реализацией.

## Acceptance criteria

1. Список смен фильтруется по кассе, кассиру, статусу и периоду.
2. Карточка смены показывает счета, платежи и отчёты, привязанные к ней.
3. Формирование X-отчёта, передача и закрытие смены доступны только для открытой смены и только при соответствующих правах.
4. После закрытия смены пользователь теряет доступ к `1.8.1` до открытия новой смены.
5. После передачи смены прежний кассир теряет доступ к управлению, но сохраняет доступ на просмотр.
6. Все состояния (loading/empty/error/offline/permissions) реализованы согласно таблице выше.
