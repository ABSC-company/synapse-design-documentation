# 1.9.4. Cash Registers Page

## Спецификация страницы интерфейса

* **Название страницы:** Кассы
* **Модуль:** Управление клиникой (Clinic Management Module)
* **Владеющие бэкенд-модули:** Structure Module (стенды и их расположение на карте), Cash Register Module (справочник касс)
* **Тип страницы:** Реестр + интерактивная 2D-карта этажа
* **Основные роли:** Администратор клиники (`STRUCTURE_STAND_*`, `CASH_REGISTER_MANAGE`)
* **Маршрут:** `/clinic-management/cash-registers`
* **Статус документа:** Актуализировано (`stand_id` — теперь собственное поле кассы, валидируется бэкендом: тип стенда и эксклюзивность проверяются на сервере, а не только на клиенте, см. §4.1a `CashRegisterModule.md`)

> Общие паттерны карты — см. `1.9.0. Clinic Management Overview`, раздел «Общий паттерн: стенды на 2D-карте клиники». Бэкенд-контракт — `StructureModule.md` §5.10, §8.8a, §14.9b (стенды); `CashRegisterModule.md` §4.1, §4.1a, §8, §12.2 (справочник касс и их размещение — тот же API, что использует `1.8.0. Cash Register Overview`, плюс `stand_id`).

## Назначение страницы и сценарии использования

Страница объединяет две ранее разрозненные задачи в одном месте: (1) справочник касс как бизнес-сущностей (создание/переименование/удаление — тот же API, что доступен операционно на `1.8.0` по праву `CASH_REGISTER_MANAGE`) и (2) физическое размещение каждой кассы на 2D-карте клиники через новый слой **стенды** (`StructureModule.md` §5.10). До этой ревизии у кассы не было понятия физического места на карте — касса существовала только как строка справочника.

С помощью страницы пользователь может:

1. Просматривать список касс клиники со статусом (занята сменой / свободна) и указанием стенда, на котором касса размещена (или «не размещена»).
2. Создавать/переименовывать/удалять кассу.
3. Открывать 2D-карту этажа и размещать кассу на свободном нераспределённом стенде.
4. Снимать кассу со стенда (стенд возвращается в `unassigned`, касса помечается «не размещена», сама касса не удаляется).

## User Flows / Task Flows

### Flow 1. Просмотр реестра

1. Таблица: название кассы, статус смены (переиспользует бейдж из `1.8.0`), стенд/этаж размещения (или «Не размещена» серым).
2. Клик по строке размещённой кассы — карта центрируется на её стенде (переход к Flow 3 в режиме просмотра).

### Flow 2. CRUD кассы (справочник)

1. «+ Добавить кассу» → модаль с полем «Название» — тот же контракт, что `1.8.0` Flow 4.
2. Создание не требует немедленного размещения на карте — касса может существовать без стенда (например, филиал ещё не разметил карту).
3. Удаление кассы, занятой открытой сменой, — заблокировано (`409 CASH_REGISTER_HAS_OPEN_SHIFT`, тот же контракт, что и `1.8.0`); удаление размещённой на стенде кассы дополнительно снимает привязку `stand_id` на фронте (Structure Module не оповещается — привязка живёт только на стороне бизнес-сущности кассы, см. Overview).

### Flow 3. Размещение кассы на карте

1. Пользователь выбирает этаж (тот же переключатель этажей/зданий, что в `1.6.2`) — карта показывает кабинеты (приглушённо, контекст) и стенды.
2. Стенды на карте окрашены по состоянию: акцентный цвет — стенд с уже размещённой на нём кассой; серый с точечной обводкой — нераспределённый стенд; нейтральный — стенд другого типа (ресепшен), недоступен для выбора здесь.
3. Клик по нераспределённой карточке кассы в боковой панели → режим «Выберите стенд на карте» — карта подсвечивает доступные (нераспределённые или уже кассовые) стенды, курсор меняется.
4. Клик по стенду на карте → подтверждение «Разместить кассу «{название}» на этом стенде?» → `PATCH /api/v1/cash-register/registers/{id}` с `{ stand_id }` (`CashRegisterModule.md` §4.1a, §12.2) — модуль сам валидирует и при необходимости классифицирует стенд через внутренний вызов к Structure Module, отдельного `PATCH /structure/stands/{id}` с фронта не требуется (тот же паттерн, что у точки электронной очереди, `1.9.7`). `422 STAND_TYPE_MISMATCH` — стенд уже `type: "reception"`; `409 STAND_ALREADY_ASSIGNED` — стенд уже занят другой кассой.
5. Стенд на карте немедленно перекрашивается в «занят кассой», подписывается названием кассы.

### Flow 4. Снятие кассы со стенда

1. Клик по размещённой кассе на карте или в списке → «Снять со стенда».
2. Подтверждающий диалог (необратимое в моменте действие — касса требует повторного размещения).
3. `PATCH /api/v1/cash-register/registers/{id}` с `{ stand_id: null }` — сервер сам возвращает стенд в `unassigned`, если он не занят ничем другим.

### Flow 5. Стенд пропал с карты (`orphaned`)

1. После перезаливки SVG этажа стенд, чей `path` больше не найден, переходит в `status: "orphaned"` на бэкенде (`StructureModule.md` §5.10) — он не удаляется, но и не отображается как активный слой карты.
2. Касса, ранее привязанная к такому стенду, в реестре (`1.9.4`) показывается с предупреждающим бейджем «Стенд не на карте» вместо обычного адреса размещения — требуется повторное размещение (Flow 3) на новом/другом стенде после актуализации карты в `1.6.2`.

## Визуал: High-Fidelity mockups

1. Карта наследует визуальный язык `1.6.2. Org Structure — Clinic map interaction`: те же управляющие элементы (zoom, fit-to-screen, переключение этажей).
2. Кабинеты на карте — уменьшенная непрозрачность (~40%), не кликабельны на этой странице.
3. Стенды — компактные маркеры (меньше кабинетов), форма отличается от кабинетов (например, скруглённый квадрат вместо прямоугольника помещения), чтобы визуально не путались с кабинетами даже без подписи.
4. Режим «Выберите стенд на карте» (Flow 3, п. 3) — затемнение недоступных стендов и всей остальной геометрии, доступные — пульсирующая обводка.
5. Пустая карта (этаж без загруженной SVG) — сообщение «Карта этого этажа ещё не создана» со ссылкой на `1.6.2`, без дублирования формы загрузки SVG здесь (загрузка карты — не ответственность этой страницы).

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton списка / карты |
| empty | Касс нет — иллюстрация + «+ Добавить кассу» |
| error | Toast при сбое CRUD/размещения; ошибка загрузки карты — блок ошибки + «Повторить» |
| offline | Баннер, размещение на карте недоступно |
| permissions | CRUD кассы, включая размещение — `CASH_REGISTER_MANAGE`; просмотр карты стендов — `STRUCTURE_STAND_GET` (классификацию стенда выполняет сам Cash Register Module, отдельное право на изменение стенда не требуется) |

### Edge cases

1. Попытка разместить кассу на стенде, уже занятом другой кассой, — стенд не предлагается как доступный (карта фильтрует по актуальному списку касс), но и при гонке (состояние на клиенте устарело) сервер отклоняет привязку (`409 STAND_ALREADY_ASSIGNED`, `CashRegisterModule.md` §4.1a) — клиентская фильтрация лишь ускоряет обратную связь, финальная защита от конфликта на сервере.
2. Попытка разместить на `1.9.7` точку электронной очереди на стенде, уже занятом кассой (`type: "cash_register"`), — отклоняется на уровне Electronic Queue Module (`422 STAND_TYPE_MISMATCH`, `ElectronicQueueModule.md` §4.1); двойное назначение стенда невозможно в обе стороны теперь, когда оба модуля-владельца (Cash Register, Electronic Queue) проверяют тип/занятость перед привязкой, а не полагаются на клиентскую фильтрацию.
3. Удаление стенда через `1.6.2`/перезаливку SVG, пока на него ссылается касса, — обрабатывается тем же путём, что Flow 5.

## Interaction & Animation

1. Переключение «Список ↔ Карта» — fade между режимами.
2. Клик по стенду в режиме размещения — короткая анимация «примагничивания» подписи кассы к стенду.
3. Снятие со стенда — подпись кассы исчезает с fade, стенд возвращается к нейтральному виду.

## Зависимости и ограничения

### API

1. `GET /cash-register/registers`, `POST/PATCH/DELETE /cash-register/registers` — справочник касс, включая размещение (`stand_id`, `CashRegisterModule.md` §4.1a, §12.2) — тот же контракт, что `1.8.0`, расширенный полем `stand_id`.
2. `GET /api/v1/structure/stands/{branch_id}?type=cash_register` и `?type=unassigned` — стенды для размещения (`StructureModule.md` §8.8a, §14.9b).
3. Сама привязка/классификация стенда выполняется через Cash Register Module (п. 1) — модуль сам вызывает `PATCH /structure/stands/{id}` внутренне при необходимости классификации; фронту не нужно вызывать этот маршрут напрямую (в отличие от предыдущей ревизии этого документа).

### Роли и права

| Действие | Право |
|---|---|
| Просмотр реестра касс | `CASH_REGISTER_GET` |
| CRUD кассы, включая размещение/снятие со стенда | `CASH_REGISTER_MANAGE` |
| Просмотр карты и стендов (только для отрисовки карты — классификацию стенда выполняет сам Cash Register Module, см. Flow 3) | `STRUCTURE_STAND_GET` (3440) |

## Acceptance criteria

1. Реестр касс показывает статус смены и место размещения (стенд/этаж или «не размещена»).
2. CRUD кассы работает независимо от размещения на карте — касса может существовать без стенда.
3. Размещение и снятие кассы со стенда выполняется через карту этажа с явным подтверждением.
4. Стенд, ставший `orphaned`, отражается в реестре кассы как «Стенд не на карте», без потери самой кассы.
5. Действия скрыты/задизейблены без соответствующих прав (`CASH_REGISTER_MANAGE` и/или `STRUCTURE_STAND_*`).
6. Состояния empty/loading/error/offline/permissions обработаны.
