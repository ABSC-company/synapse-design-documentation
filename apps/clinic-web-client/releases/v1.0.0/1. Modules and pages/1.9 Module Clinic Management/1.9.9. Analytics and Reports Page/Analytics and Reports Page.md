# 1.9.9. Analytics and Reports Page

## Спецификация страницы интерфейса

* **Название страницы:** Аналитика и отчёты
* **Модуль:** Управление клиникой (Clinic Management)
* **Позиция в модуле:** Девятая страница (после `1.9.8. Audit Log`)
* **Тип страницы:** Дашборд аналитики + генератор/журнал отчётов на выгрузку
* **Основные роли:** Администратор, руководитель/менеджмент клиники (доступ read-only даже для ролей с правом просмотра — экспорт требует отдельного права, см. §"Роли и права")
* **Маршрут:** `/clinic-management/analytics`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Draft
* **Связанная бэкенд-документация:** `ReportsAndAnalyticsModule.md` §7, §8, §12

> Общие паттерны модуля (статус-бейджи, подтверждающие диалоги, права) — см. `1.9.0. Clinic Management Overview`.

---

## Назначение страницы и сценарии использования

Единая точка аналитики по всей клинике: сводные KPI за период (дашборд) и генерация/выгрузка детальных отчётов — продажи, пациенты (по врачам / по услугам / итого), расходы склада — с фильтрами по периоду, отделу/филиалу, врачу, услуге и выгрузкой в CSV/Excel/PDF. Страница не хранит и не редактирует бизнес-данные — только читает агрегаты у модуля-источника (`ReportsAndAnalyticsModule.md` §1).

Ключевые задачи страницы:

1. Обзор ключевых показателей клиники за выбранный период (дашборд KPI).
2. Просмотр детального отчёта по направлению (продажи / пациенты / расходы) — график + таблица.
3. Настройка и запуск выгрузки отчёта: период, метрики/направление, формат файла.
4. Журнал ранее запрошенных выгрузок и скачивание готовых файлов.

## User Flows / Task Flows для страницы

### Flow 1. Просмотр дашборда аналитики

1. Пользователь открывает страницу «Аналитика» — по умолчанию период «текущий месяц».
2. Верх страницы — карточки KPI: выручка, возвраты, net, визиты, уникальные пациенты, средний чек; под ними — мини-списки «топ-услуги» и «топ-врачи».
3. Смена периода в Toolbar (диапазон дат + быстрые пресеты «Сегодня» / «Неделя» / «Месяц» / «Квартал» / «Год») перезагружает карточки без перехода со страницы.

### Flow 2. Просмотр отчёта по направлению

1. Под дашбордом — три вкладки: «Продажи», «Пациенты», «Расходы».
2. Внутри вкладки — свои фильтры (отдел/филиал — везде; врач — только «Пациенты»; услуга — «Продажи»/«Пациенты») и переключатель группировки (день/неделя/месяц).
3. График (для «Продажи»/«Расходы» — линейный/столбчатый по бакетам периода; для «Пациенты» — столбчатый по группе breakdown) + таблица детализации под ним.
4. Вкладка «Пациенты» дополнительно имеет переключатель breakdown: «По врачам» / «По услугам» / «Итого».

### Flow 3. Выгрузка отчёта

1. Кнопка **«Выгрузить»** в Toolbar (доступна на любой вкладке; предзаполняет тип отчёта и текущие фильтры выбранной вкладки).
2. Открывается модаль: тип отчёта (можно сменить), период, фильтры направления, формат (CSV / Excel / PDF — три явных пункта, не dropdown).
3. Подтверждение → запрос на создание задачи экспорта.
   - Если сервер обработал синхронно (маленький период) — сразу предлагается скачать файл, модаль закрывается.
   - Если поставлено в очередь (большой период) — тост «Отчёт формируется, уведомим по готовности» + переход в секцию «Журнал выгрузок».

### Flow 4. Журнал выгрузок

1. Отдельная вкладка «Журнал выгрузок» — таблица прошлых и текущих задач: тип отчёта, период, формат, статус, кто запросил, дата.
2. Задачи со статусом «В процессе» — бейдж-индикатор, статус обновляется автоматически (поллинг), без ручного обновления страницы пользователем.
3. Готовая задача — кнопка «Скачать» в строке. Задача с ошибкой — бейдж «Ошибка» + причина по клику + кнопка «Повторить» (создаёт новую задачу с теми же фильтрами).

Общий layout страницы:

1. Слева: Sidebar в свёрнутом состоянии.
2. Сверху: **Page Header** — «Аналитика» + Toolbar (период, кнопка «Выгрузить»).
3. Контентная область: KPI-карточки → табы отчётов (график + таблица) → секция/таб «Журнал выгрузок».

### Журнал выгрузок

|---|---|

## Визуал: High-Fidelity mockups

Визуальные правила:

1. KPI-карточки — крупная типографика (число + подпись + мини-иконка), как в `1.6.1. HR Dashboard`; net — цветовая индикация (зелёный/красный по знаку).
2. Графики отчётов — единая палитра дизайн-системы для всех трёх направлений, тултип со значением бакета при наведении, легенда при нескольких сериях (например, «Оплачено» / «Возвращено»).
3. Переключатель breakdown на вкладке «Пациенты» — сегмент-контрол (radio-группа как табы), не dropdown.
4. Модаль выгрузки — формат выбирается явными радио-кнопками/иконками (CSV/Excel/PDF), а не dropdown-списком, по аналогии с выбором формата на `1.8.3. Reports Page`.
5. Статус-бейджи журнала выгрузок — переиспользуют цветовую семантику `1.9.0` (готово — зелёный, в процессе — жёлтый/нейтральный со спиннером, ошибка — красный).

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Дашборд KPI с карточками и топ-листами.
2. Вкладка «Продажи» с графиком и таблицей.
3. Вкладка «Пациенты» с переключателем breakdown.
4. Вкладка «Расходы».
5. Модаль выгрузки отчёта.
6. Журнал выгрузок (все статусы: в очереди/в процессе/готов/ошибка).
7. Состояния loading/empty/error.

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton KPI-карточек; skeleton графика/таблицы при смене вкладки/фильтра |
| empty | Нет данных за период — «Нет данных за выбранный период», предложение сменить период; KPI-карточки показывают «0» без ошибки |
| error | Ошибка загрузки отчёта/дашборда — сообщение + «Повторить», не блокирует остальные виджеты страницы |
| offline | Показ последних закэшированных данных с пометкой «Данные могут быть неактуальны»; выгрузка недоступна, тост «Нет соединения» |
| permissions | Страница скрыта без прав на просмотр аналитики; отдельные вкладки скрыты без соответствующего права направления; кнопка «Выгрузить» скрыта без права на экспорт |

### Edge cases

1. Слишком большой период для синхронной обработки (порог задаёт бэкенд, `ReportsAndAnalyticsModule.md` §10) — выгрузка уходит в очередь, фронт не показывает файл сразу, а сообщает о постановке в очередь и обновляет журнал.
2. Задача экспорта завершилась с ошибкой — причина отображается по клику на бейдж «Ошибка» (`error_message`), доступна кнопка «Повторить» с теми же фильтрами.
3. Отчёт с нулевой активностью за период (например, новый филиал без визитов) — все значения «0», это штатное отображение, а не пустое состояние.
4. У пользователя есть право на просмотр дашборда, но нет прав ни на одну из вкладок отчётов — показывается только дашборд, вкладки отчётов не отображаются вовсе (не disabled).
5. Повторный запрос выгрузки с теми же фильтрами, пока предыдущая задача ещё «В процессе» — не блокируется (пользователь может запросить несколько выгрузок параллельно), обе отображаются в журнале отдельными строками.

## Interaction & Animation

1. Смена периода/пресета — плавное обновление KPI-карточек (fade), без полного перерендера страницы.
2. Переключение вкладок отчётов — fade содержимого, Toolbar периода общий и не сбрасывается при смене вкладки.
3. Открытие модали выгрузки — fade+scale, поля предзаполнены текущим контекстом вкладки.
4. Автообновление статуса в журнале выгрузок — визуально ненавязчивое (без мигания всей строки), обновляется только бейдж статуса и появляется кнопка «Скачать» по готовности.
5. Числа в KPI-карточках анимируются счётчиком при первой загрузке (как в `1.6.1. HR Dashboard`).

## Зависимости и ограничения

### API

1. `GET /reports/analytics/summary` — KPI-дашборд (`ReportsAndAnalyticsModule.md` §8, §12.2).
2. `GET /reports/sales`, `GET /reports/patients`, `GET /reports/expenses` — данные вкладок (§12.3).
3. `POST /reports/exports` — запуск выгрузки (§12.4).
4. `GET /reports/exports`, `GET /reports/exports/:id`, `GET /reports/exports/:id/download` — журнал и скачивание (§12.4).

### Роли и права

1. `REPORTS_ANALYTICS_VIEW` — просмотр дашборда KPI (видимость страницы в целом).
2. `REPORTS_SALES_VIEW` / `REPORTS_PATIENTS_VIEW` / `REPORTS_EXPENSES_VIEW` — видимость соответствующей вкладки.
3. `REPORTS_EXPORT_CREATE` — видимость кнопки «Выгрузить» и доступность модали.
4. `REPORTS_EXPORT_GET` — доступ к вкладке «Журнал выгрузок».
5. `REPORTS_EXPORT_DOWNLOAD` — доступность кнопки «Скачать» в журнале.

## Acceptance criteria

1. Дашборд отображает KPI за выбранный период с быстрыми пресетами и произвольным диапазоном дат.
2. Три вкладки отчётов (продажи/пациенты/расходы) показывают график и таблицу с фильтрами по отделу/врачу/услуге и группировкой по периоду.
3. Вкладка «Пациенты» поддерживает переключение breakdown: по врачам / по услугам / итого.
4. Модаль выгрузки позволяет выбрать тип отчёта, период, фильтры и формат (CSV/Excel/PDF), запускает создание задачи экспорта.
5. Журнал выгрузок показывает статус задач (в очереди/в процессе/готово/ошибка) и обновляется автоматически без перезагрузки страницы.
6. Готовые файлы скачиваются из журнала; задачи с ошибкой можно повторить.
7. Все состояния (loading/empty/error/offline/permissions) реализованы согласно таблице выше.
8. Видимость вкладок и кнопки «Выгрузить» строго соответствует правам пользователя (§"Роли и права").
