# 1.6.3 Employees

## Спецификация страницы интерфейса

* **Название страницы:** Сотрудники
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Реестр (таблица) + точка входа в электронное дело
* **Основные роли:** Администратор / HR-менеджер, Руководитель отдела
* **Маршрут:** `/hr/employees`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Общие паттерны (реестр, форма, статус-бейдж, массовый выбор, контекстное меню, объективка, первичный документ) — см. `1.6.0. Overview`. Техническая реализация (эндпоинты, схема запроса приёма, валидация, состояние) — во frontend-документе `1.6.3. Employees` (Frontend).

---

## Назначение страницы и сценарии использования

Табличный реестр всех сотрудников с базовой информацией и точкой входа в электронное дело (1.6.4). Отсюда выполняются приём, массовые операции и быстрые действия (объективка, учёт времени, увольнение). Уволенные физически в архиве и в основном списке не показываются — доступны через фильтр/раздел «Архив».

С помощью страницы пользователь может:

1. Просматривать сотрудников: ФИО, отдел, должность, статус, график работы.
2. Искать по ФИО, фильтровать (отдел, должность, пол, возраст, гражданство, семейное положение, системная роль, статус и т.д.).
3. Открывать электронное дело сотрудника.
4. Принимать нового сотрудника.
5. Массово выбирать строки (чекбокс) и удалять (bulk) через Action Bar.
6. Через контекстное меню (`⋮` / ПКМ): открыть эл. дело, уволить, скачать/распечатать объективку, скачать/распечатать учёт времени (check in-out).

## User Flows / Task Flows

### Flow 1. Просмотр, поиск, фильтрация

1. Пользователь открывает «Сотрудники».
2. Система показывает таблицу с пагинацией.
3. Пользователь вводит запрос в поиск → фильтрация по ФИО.
4. Пользователь открывает фильтры, задаёт параметры, применяет → таблица обновляется, на кнопке «Фильтр» счётчик активных.

### Flow 2. Открытие электронного дела

1. Пользователь кликает строку (вне чекбокса/`⋮`) → переход в эл. дело (1.6.4).

### Flow 3. Приём сотрудника

1. Пользователь нажимает «+ Принять сотрудника».
2. Открывается форма создания.
3. Пользователь выбирает способ передачи документа, удостоверяющего личность (сканирование / загрузка файла / фотографирование через веб-камеру) — тот же паттерн, что и в форме регистрации пациента (см. `1.3.0.1. Page Header` §Этап 2.1, EMC), либо пропускает этот шаг и заполняет форму полностью вручную.
4. Если документ передан — система распознаёт MRZ/персональные данные (полe формы автозаполняются, оператор проверяет и правит их до отправки), а фото и графическая подпись сотрудника будут извлечены из скана автоматически при сохранении формы (шаг 6) — отдельно ничего распознавать/подтверждать на этом шаге не нужно. При двустороннем документе оператор захватывает вторую сторону тем же способом через кнопку «Добавить вторую сторону».
5. Если документ не передан — оператор заполняет все поля вручную и при необходимости загружает фото и графическую подпись **по отдельности**, двумя независимыми (оба необязательны) полями загрузки.
6. Заполняет остальные обязательные поля (отдел; должность — опционально), выбирает способ создания системного пользователя и, если требуется, привязывает первичный документ (приказ о приёме / заявление), сохраняет.
7. Если приказ не требуется или подписание не предусмотрено — система сразу создаёт сотрудника на рабочем месте (фото/подпись к этому моменту уже извлечены из скана, если он был передан), фиксирует приказ (если был привязан) в делопроизводстве (1.6.10) и переходит в его эл. дело. Если приказ требует подписания — сотрудник **ещё не создан**: модалка закрывается с уведомлением «Приём инициирован, ожидает подписания приказа», переход в эл. дело не происходит (её ещё нет); инициированный приём появляется в блоке «Ожидают приёма» на этой же странице (см. ниже) и создаётся автоматически после подписания — извлечение фото/подписи из скана в этом случае тоже происходит только в момент фактического создания сотрудника, не раньше.
8. Если фото или подпись не удалось извлечь из скана (документ без фото, повреждённое изображение, сбой AI-сервиса) — это **не блокирует** приём: сотрудник создаётся без соответствующего поля, его можно дозагрузить позже из эл. дела.

### Flow 4. Массовое удаление (bulk)

1. Пользователь отмечает чекбоксы строк.
2. Снизу появляется Action Bar: «Выбрано: N» + «Удалить» + «Снять выбор».
3. «Удалить» → подтверждение «Удалить N сотрудников?» → удаление.

### Flow 5. Быстрые действия из контекстного меню

1. Пользователь нажимает `⋮` или кликает ПКМ по строке.
2. Открывается контекстное меню.
3. Выбор действия: открыть дело / уволить / объективка / учёт времени.

### Flow 6. Увольнение из контекстного меню

1. Пользователь выбирает «Уволить сотрудника».
2. Открывается модалка увольнения: предупреждение об архивировании и освобождении ставок + блок «Первичный документ» (паттерн из 1.6.0) — обязательность зависит от того, кто выполняет действие.
3. Если документ требуется, пользователь задаёт основание: создать приказ об увольнении (новый / из шаблона) либо загрузить/выбрать инициирующий документ сотрудника (заявление, рапорт, ходатайство) — из файла или из входящих ЭДО.
4. Кнопка «Уволить» активна сразу, если документ не требуется правилом; иначе — только после привязки документа.
5. Подтверждение → архивирование, освобождение ставок; строка исчезает из активного списка, документ (если был привязан) фиксируется в делопроизводстве (1.6.10).

### Header
* Заголовок «Сотрудники» — слева.
* «+ Принять сотрудника» — справа, видна при праве на приём.

### Блок «Ожидают приёма»

Показывает приёмы, инициированные формой «Принять сотрудника», но ещё не применённые — приказ о приёме создан, но не подписан, поэтому сотрудника как записи в системе ещё нет. Единственное место в реестре, где такой приём вообще виден (в таблицу он не попадёт, пока не применится). ФИО/отдел/должность в строке — из данных, введённых в форму приёма, не из карточки сотрудника (её нет). Клик по строке/«Открыть →» — карточка приказа (модуль 1.5), не эл. дело. Скрыт, если инициированных приёмов нет. См. паттерн «Связанные документы», `1.6.0. Overview`.

* **Статусные вкладки:** Все · На работе · Больничный · Отпуск · Командировка · **Архив** (уволенные).
* **Поиск** — по ФИО, debounce.
* **Кнопка «Фильтр»** — открывает Drawer, счётчик активных фильтров.

**Примечания для дизайнера:**
* **Документ, удостоверяющий личность** — три равнозначных способа получения изображения: сканирование (подключённый сканер рабочего места, недоступно на планшетном клиенте), загрузка файла, фотографирование через веб-камеру — тот же набор и то же визуальное решение, что в форме регистрации пациента (`1.3.0.1. Page Header`, design-репозиторий, Этап 2.1). Можно передать одну сторону документа либо обе (кнопка «Добавить вторую сторону» появляется после первого успешного захвата); каждая сторона снимается своей кнопкой «Очистить» независимо от другой.
* **Распознавание MRZ** — происходит сразу после захвата, поля формы (ФИО, дата рождения, гражданство, серия/номер) предзаполняются и остаются редактируемыми; индикатор авто-заполнения помечает такие поля (см. «Визуал» ниже).
* **Фото и подпись из документа** — в отличие от MRZ, не распознаются сразу на превью: они извлекаются AI-сервисами автоматически в момент сохранения формы (при склейке, если сторон две) и попадают в карточку сотрудника без отдельного подтверждения оператором. Если извлечь не удалось (нет фото на документе, сбой сервиса) — это не мешает созданию сотрудника, поля просто остаются пустыми, дозаполняются позже из эл. дела.
* **Ручной ввод фото/подписи** — если документ не сканировался, под блоком захвата (или вместо него, если оператор его свернул/очистил) видны два независимых поля загрузки «Фото» и «Графическая подпись», каждое опционально. Как только оператор загрузил хотя бы одну сторону скана, эти два поля скрываются — сканирование и ручная загрузка не смешиваются в одном приёме, весь блок целиком опционален (форма отправляется и без единого изображения).
* **Пол** и допустимые значения «Семейное положение» зависят от глобального стандарта клиники — не хардкодить число опций.
* **Отдел → Должность:** должность при приёме необязательна — сотрудника можно создать без неё и назначить должность позже отдельным действием (см. 1.6.4, секция «Рабочие данные»). Если должность выбрана сразу — показывается выбор рабочей ставки; «Должность» показывает доступный остаток ставки из штатного расписания.
* **Системный пользователь:** три взаимоисключающих режима — автогенерация логина/пароля системой, ручной ввод логина/пароля, или привязка уже существующего пользователя (тогда логин/пароль не запрашиваются).
* **Первичный документ** — обязателен для части исполнителей и не обязателен для остальных (см. `1.6.0. Overview`); кнопка «Создать» ведёт себя соответственно.
* После создания «Тип сотрудника» — неизменяем. Привязка к системному пользователю также не меняется после создания.

## Визуал: High-Fidelity mockups

1. Таблица — плотная, читаемая; аватар + ФИО в одной колонке; статус-бейджи по семантике модуля.
2. Активная статусная вкладка выделена; «Архив» визуально отделён.
3. Чекбоксы появляются при hover/в режиме выбора; выбранные строки подсвечены.
4. Action Bar фиксируется снизу поверх контента при выборе.
5. Кнопка `⋮` появляется при hover; контекстное меню одинаково для `⋮` и ПКМ.
6. Счётчик активных фильтров — бейдж на кнопке «Фильтр».
7. В форме приёма блок захвата документа визуально выделен (ускоряет ввод); распознанные поля помечены индикатором авто-заполнения.
8. Три кнопки захвата (сканировать/загрузить/сфотографировать) оформлены единообразно с аналогичной панелью в форме регистрации пациента (`1.3.0.1. Page Header`) — не отдельная визуальная система для HR.
9. Превью каждой стороны документа — с крестиком «Очистить» на самом превью, не общей кнопкой на весь блок.
10. Два поля ручной загрузки (фото/подпись) визуально второстепенны по отношению к блоку захвата документа — показывают, что это запасной путь, а не равноценная альтернатива по важности.
11. Соответствие единой дизайн-системе.

## Состояния и edge cases

### Empty
* Нет сотрудников: «Пока нет сотрудников» + «+ Принять сотрудника».
* Блок «Ожидают приёма» без инициированных приёмов не рендерится (не пустое состояние с текстом, а отсутствие блока).
* Нет результатов по фильтрам/поиску: «Ничего не найдено» + «Сбросить фильтры».
* Вкладка «Архив» пуста: «Уволенных сотрудников нет».

### Loading
* Скелетон строк таблицы; спиннер на «Создать» при сохранении формы; спиннер при генерации объективки/учёта времени.

### Error
* Сбой загрузки списка — блок ошибки + «Повторить».
* Сбой приёма/удаления — toast; форма остаётся открытой.
* Сбой распознавания MRZ — поля остаются ручными, toast «Не удалось распознать документ», кнопка «Повторить» на самой панели захвата.
* Сбой извлечения фото/подписи из скана (Face-AI/Sign-AI недоступны, либо на документе не найдено фото/подпись) — не блокирует приём; после создания сотрудника — ненавязчивый toast «Фото/подпись не удалось получить из документа, можно загрузить позже» со ссылкой на эл. дело.

### Offline
* Список из кэша; действия (приём, удаление, увольнение) заблокированы, toast «Нет соединения».

### Permissions
* Нет права на просмотр — страница недоступна.
* Нет права на приём — кнопка приёма скрыта.
* Нет права на удаление — чекбоксы/bulk-удаление недоступны.
* Нет права на увольнение — «Уволить» скрыт.
* Нет права на учёт времени — соответствующий пункт меню скрыт.
* Нет права на распознавание документа (`HR_PASSPORT_RECOGNIZE`) — кнопки «Сканировать»/«Загрузить»/«Сфотографировать» скрыты, форма сразу открыта в режиме ручного заполнения с полями фото/подписи по отдельности (без пустого блока-заглушки на их месте).

### Edge cases
* Bulk-удаление с частью защищённых записей — предупреждение со списком пропущенных.
* Сотрудник без назначенной должности — в колонках «Должность/Отдел» прочерк; виден в «не назначенных» (см. 1.6.2).
* Увольнение из меню — запускает флоу архивирования, освобождение ставок; после — строка исчезает из активного списка.
* Документ без графической подписи (например, некоторые ID-карты) — фото извлекается, подпись остаётся пустой; не считается ошибкой, отдельного предупреждения не показывается (в отличие от полного сбоя извлечения, где есть toast).
* Оператор загрузил вручную фото/подпись, а затем всё же отсканировал документ — поля ручной загрузки скрываются вместе с уже введёнными значениями; при отправке формы уходит только скан (взаимоисключение источников), ручной ввод, если он был, теряется без предупреждения — необходимо предусмотреть подтверждающий тултип/диалог при попытке отсканировать поверх уже заполненных вручную полей.
* Двусторонний документ, вторая сторона не добавлена — фото/подпись извлекаются из того, что есть; отсутствие подписи (например, она на неотсканированной стороне) — тот же нейтральный случай, что и выше.

## Interaction & Animation

* **Статусные вкладки** — мгновенное переключение с fade-сменой контента; анимированный индикатор активной.
* **Поиск/фильтр** — debounce; область списка показывает мягкий скелетон при обновлении.
* **Drawer фильтра** — slide-in справа, затемнение фона, закрытие по Esc/клику вне.
* **Выбор строк** — чекбокс fade-in на hover; Action Bar выезжает снизу.
* **Контекстное меню** — fade/scale из точки клика; ПКМ открывает в позиции курсора.
* **Форма приёма** — fade+scale; индикатор авто-заполнения «подсвечивает» распознанные поля.
* **Toast** — выезд, авто-скрытие 3–5 с.

## Зависимости и ограничения

* Отделы и должности — Structure Module; системные роли/пользователи — Auth Module; стандарты гендера/семейного положения — глобальные настройки; фото/скан/распознавание/генерация PDF — File Module.
* Распознавание MRZ, извлечение фото и подписи — три внешних AI-сервиса (MRZ-AI, Face-AI, Sign-AI), общие с формой регистрации пациента EMC (`1.3.0.1. Page Header`); HR Module — самостоятельная точка их вызова, не проксирует запросы через EMC.
* Уволенные — отдельная архивная выборка; в активном списке только через вкладку «Архив».
* Тип сотрудника и системный пользователь неизменяемы после создания.
* Остаток ставок ограничивает выбор должности при приёме.
* Распознавание MRZ/паспорта — best-effort; поля остаются редактируемыми.
* Скан документа для сотрудника, в отличие от пациента (EMC), остаётся полностью опциональным — форма отправляется и без единого изображения.
* Извлечение фото и подписи из скана — best-effort, отдельно от MRZ: сбой не блокирует приём, поля дозагружаются позже вручную из эл. дела.

## Acceptance criteria

* Таблица показывает колонки ФИО, отдел, должность, статус, график работы; поддерживает пагинацию и сортировку.
* Поиск по ФИО и фильтры (отдел, должность, пол, возраст, гражданство, семейное положение, системная роль, статус) работают; счётчик активных фильтров отображается.
* Клик по строке открывает электронное дело.
* Кнопка «+ Принять сотрудника» видна при праве; форма включает ФИО, дату рождения, пол, семейное положение, гражданство, адрес, захват документа удостоверяющего личность (сканирование/загрузка/фотографирование, одна или две стороны, с распознаванием MRZ и последующим извлечением фото и подписи), тип сотрудника, контактные данные, отдел (должность — опционально), выбор режима создания системного пользователя и первичный документ (когда требуется).
* Если документ не передан, форма позволяет заполнить все поля вручную и загрузить фото и графическую подпись по отдельности, каждое необязательно; форма отправляется даже без единого изображения.
* Сбой извлечения фото/подписи из скана не блокирует создание сотрудника — соответствующее поле остаётся пустым, доступным для дозагрузки из эл. дела.
* Массовый выбор чекбоксами показывает Action Bar с bulk-удалением и подтверждением.
* Контекстное меню открывается по `⋮` и по ПКМ и содержит: открыть эл. дело, уволить, объективку (скачать/печать), учёт времени (скачать/печать) — с учётом прав.
* Увольнение из контекстного меню открывает модалку с блоком первичного документа, корректно реагирующим на оба случая (обязателен/не обязателен).
* Уволенные не показываются в активных вкладках; доступны во вкладке «Архив».
* Форма приёма при обязательном подписании приказа не создаёт сотрудника сразу — инициированный приём отображается в блоке «Ожидают приёма» над таблицей со статусом и переходом на карточку приказа; блок скрыт при отсутствии инициированных приёмов.
* Состояния empty / loading / error / offline / permissions обрабатываются корректно.
