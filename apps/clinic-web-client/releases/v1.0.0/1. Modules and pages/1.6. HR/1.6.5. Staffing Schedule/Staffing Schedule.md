# 1.6.5 Staffing Schedule

## Спецификация страницы интерфейса

* **Название страницы:** Штатное расписание
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Реестр (таблица)
* **Основные роли:** Администратор, HR-менеджер, Руководитель
* **Маршрут:** `/hr/staffing`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Общие паттерны (реестр, форма, состояния) — см. `1.6.0. Overview`. Техническая реализация (эндпоинты, разделение операций между модулями, состояние) — во frontend-документе `1.6.5. Staffing Schedule` (Frontend).

---

## Назначение страницы и сценарии использования

Просмотр и управление штатным расписанием — перечнем должностей, количеством ставок, окладами и уровнем заполненности.

> **Важно:** создание и удаление штатной единицы технически выполняется через раздел управления орг. структурой (Structure Module) — они происходят автоматически как побочный эффект создания/удаления должности. Кнопки «+ Добавить позицию» и «Удалить» на этой странице создают/удаляют именно должность — запись расписания появляется/исчезает вслед за ней автоматически (стартовое значение — 1 ставка, ничего не занято). Штатное значение количества ставок, оклад и базовая роль донастраиваются отдельным, последующим действием уже на этой же странице. Занятость ставок по-прежнему формируется автоматически при назначении/снятии должностей сотрудников (1.6.4 / 1.6.2) и вручную не редактируется.

С помощью страницы пользователь может:

1. Просматривать должности расписания с количеством ставок и заполненностью.
2. Фильтровать по отделу и наличию вакансий.
3. Создавать и удалять должности (вместе с ними автоматически появляется/исчезает запись расписания), редактировать ставки/оклад/базовую роль.
4. Переходить к назначению на вакантную должность.

## User Flows / Task Flows

### Flow 1. Просмотр и фильтрация
1. Пользователь открывает «Штатное расписание».
2. Система показывает список с прогресс-барами заполненности.
3. Пользователь фильтрует по отделу/вакансиям.

### Flow 2. Создание позиции (штатной единицы)
1. «+ Добавить позицию».
2. Заполняет данные должности (название, отдел, тип, приоритет). Первичный документ на этом шаге не требуется.
3. Сохраняет → должность создаётся, для неё автоматически создаётся запись штатного расписания (1 ставка, оклад не задан). Новая строка сразу появляется в таблице.
4. Опционально сразу переходит к Flow 3, чтобы задать реальное количество ставок/оклад/базовую роль.

### Flow 3. Редактирование ставок/оклада/базовой роли
1. `⋯` → «Редактировать» → форма с количеством ставок, окладом и базовой ролью.
2. Сохраняет — изменения применяются немедленно, первичный документ не требуется.

### Flow 4. Удаление (упразднение) позиции
1. `⋯` → «Удалить» → модалка подтверждения → удаление должности.
2. Если у должности есть занятые ставки или на неё ссылаются кадровые записи — система отклоняет удаление; пользователь должен сначала снять всех сотрудников с должности (1.6.4 / 1.6.2).
3. При успешном удалении должности запись штатного расписания удаляется автоматически вслед за ней.

### Header / Control Bar
* Заголовок + «+ Добавить позицию».
* Поиск по названию должности + кнопка «Фильтр» (Drawer).

### Drawer фильтрации
| Поле | Тип |
|------|-----|
| Отдел | Multi-select |
| Наличие вакансий | Toggle |

### Таблица
| Колонка | Описание |
|---------|----------|
| Должность | Название |
| Отдел | Отдел должности |
| Всего ставок | Общее число ставок |
| Занято | Занято ставок (авто) |
| Вакантно | Разница между всего и занято |
| Заполненность | Прогресс-бар |
| Оклад (1 ставка) | Оклад |
| Базовая роль | Если задана, иначе «—» |
| Действия | `⋯` |

Цветовая индикация заполненности: полностью занято — зелёный; частично — жёлтый; пусто/вакантно — красный.

Контекстное меню `⋯`: Редактировать (ставки/оклад/базовая роль), Удалить (должность); «Назначить сотрудника →» (переход в орг. структуру 1.6.2 для вакантных).

### Форма «Добавить позицию» (создание должности)

| Поле | Тип | Обяз. |
|------|-----|:---:|
| Название должности | Text | ✓ |
| Отдел | Select | ✓ |
| Описание | Text | — |
| Тип должности | Select (младший/средний/старший медперсонал, штатный сотрудник, администрация) | ✓ |
| Приоритет | Number | ✓ |

Первичный документ не требуется. После сохранения должность создаётся, а запись штатного расписания для неё появляется в этой таблице автоматически со стартовыми значениями (1 ставка, ничего не занято, оклад не задан).

### Форма «Редактировать запись расписания»

| Поле | Тип | Обяз. |
|------|-----|:---:|
| Количество ставок | Number, шаг 0.25 | ✓ |
| Оклад за 1 ставку | Number | ✓ |
| Базовая роль | Select | — |

Поведение: занятые ставки не редактируются; нельзя задать количество ставок меньше уже занятого (инлайн-ошибка). Первичный документ не требуется. Сохранение применяется немедленно.

## Состояния и edge cases

* **Empty:** «Штатное расписание не заполнено» + «+ Добавить позицию».
* **Loading:** скелетон строк; спиннер на сохранении.
* **Error:** баннер + «Повторить»; toast при сбое сохранения/удаления.
* **Offline:** таблица из кэша; управление заблокировано, toast.
* **Permissions:** нет права на просмотр — раздел скрыт; нет права на редактирование ставок — «Редактировать» скрыт; нет прав на управление должностями — «+ Добавить позицию»/«Удалить» скрыты.
* **Edge cases:** снижение количества ставок ниже занятого — блок; удаление позиции с занятыми ставками или иными зависимостями — система отклоняет с понятной ошибкой, пользователь должен сначала снять сотрудников с должности; фильтр вакансий показывает только незанятые.

## Interaction & Animation

* Прогресс-бары плавно анимируются при загрузке/обновлении.
* Поиск — debounce 300–500 мс; Drawer — slide-in справа.
* Hover строки — подсветка, появление `⋯`; меню — fade/scale.
* Форма — fade+scale модалки; Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Просмотр/редактирование записи расписания и создание/удаление должности выполняются разными частями системы (кадровый учёт vs. управление структурой), но представлены пользователю как единая страница.
* Базовые роли — из модуля управления доступом.
* Связь с 1.6.4/1.6.2: назначение/снятие должности сотруднику меняет занятость ставок.
* Занятость ставок — вычисляемое значение; количество ставок не может быть меньше занятого; базовая роль авто-выдаётся сотруднику при назначении должности (не при создании штатной единицы).
* Первичный документ для операций этой страницы не требуется.

## Acceptance criteria

* Таблица отображает все записи с колонками всего/занято/вакантно/заполненность/оклад/базовая роль.
* Прогресс-бар корректно отражает заполненность с цветовой индикацией.
* Фильтр вакансий показывает только должности с незанятыми ставками.
* Форма редактирования не позволяет задать количество ставок меньше занятого.
* «+ Добавить позицию» создаёт должность; запись расписания появляется в таблице автоматически без отдельного создания.
* «Удалить» удаляет должность; при наличии занятых ставок/зависимостей система отклоняет удаление, интерфейс показывает понятную ошибку.
* После назначения/снятия должности занятость обновляется автоматически.
* Видимость кнопок и действий определяется соответствующими правами.
* Состояния empty / loading / error / offline / permissions обрабатываются корректно.
