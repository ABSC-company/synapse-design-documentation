# 1.6.0 HR Module — Обзор и навигация

## Спецификация модуля

* **Модуль:** HR Module (управление персоналом)
* **Тип:** раздел внутренней админки клиники
* **Платформа:** веб-приложение медицинской системы
* **Основные роли:** Администратор / HR-менеджер, Руководитель отдела, Сотрудник (просмотр своих данных)
* **Статус документа:** Актуализировано

> Этот файл — навигационная и паттерн-сводка модуля: она не описывает отдельную страницу по структуре спецификации, а фиксирует общие UX-правила, на которые ссылаются страницы 1.6.1–1.6.14 без повторного описания. Техническая реализация (эндпоинты, схемы запросов, права доступа как коды, состояние приложения) — в соответствующем frontend-документе `1.6.0. Overview` (Frontend).

## Что НЕ входит в модуль (точки интеграции)

* **Загрузка и хранение файлов** (фото, сканы документов, сертификаты, архивы, объективки) — File Module. В HR-экранах используется единый паттерн «Загрузить файл».
* **Кадровый документооборот (приказы)** — EDM Module. HR Module — владелец документов категории «Кадровые». Часть кадровых движений сопровождается первичным документом — см. паттерн «Первичный документ» ниже. Реестр и редактор приказов описаны в модуле 1.5.
* **Орг. структура как источник справочников** (отделы, должности, рабочие места, субординация) — Structure Module. Страница 1.6.2 визуализирует структуру и инициирует кадровые действия, но сами справочники ведутся в Structure Module.
* **Глобальные настройки** (стандарт гендера, списки специализаций и категорий врачей) — Management Module / сам HR Module.
* **Системные аккаунты / базовые роли** — Auth Module.
* **Планирование событий и напоминаний** («Календарь» на дашборде) — общесистемный модуль планирования задач, не специфичный для HR.

## Общие UI-паттерны

Зафиксированы один раз; страницы ссылаются на них без повторного описания.

### Паттерн «Реестр» (список сущностей)

```
┌─────────────────────────────────────────────────────────────────┐
│  Заголовок страницы                          [+ Кнопка создания] │
├─────────────────────────────────────────────────────────────────┤
│  [Вкладки/табы, если есть]                                        │
│  🔍 Поиск...                              [Фильтр ▾] [Сортировка] │
├─────────────────────────────────────────────────────────────────┤
│  Таблица / список карточек                                        │
├─────────────────────────────────────────────────────────────────┤
│  Пагинация                                                        │
└─────────────────────────────────────────────────────────────────┘
```

* Поиск — debounce 300–500 мс; набор искомых полей указан на странице.
* Фильтр — боковая выезжающая панель (Drawer) или dropdown.
* Длинные списки — серверная пагинация или infinite scroll.

### Паттерн «Форма создания/редактирования» (модальное окно)

* Обязательные поля помечены `*`.
* «Сохранить» неактивна, пока форма не валидна.
* Необратимое удаление — отдельное подтверждающее окно.

### Паттерн «Массовый выбор + Action Bar»

* Чекбокс появляется при hover строки / в режиме выбора.
* При выборе ≥1 элемента снизу появляется Action Bar: «Выбрано: N» + массовые действия (например, «Удалить») + «Снять выбор».

### Паттерн «Контекстное меню»

* Открывается кнопкой `⋮` в строке и по правому клику (ПКМ) на строке.
* Набор действий зависит от сущности и прав пользователя.

### Паттерн «Статус-бейдж»

Единая цветовая семантика модуля:

| Семантика | Где используется | Цвет |
|-----------|------------------|------|
| Активно / в порядке | «На рабочем месте», документ действующий, аттестация запланирована | Зелёный |
| Внимание / скоро истекает | «В отпуске», «В командировке», документ/аттестация истекает ≤30 дней | Жёлтый/янтарный |
| Критично / просрочено | аттестация просрочена/не пройдена, документ истёк, просроченный инструктаж | Красный |
| Нейтрально / неактивно | «Вне рабочего места», «Уволен», бессрочный документ | Серый |

### Паттерн «Пустое / Загрузка / Ошибка»

* **Empty** — иллюстрация + поясняющий текст + кнопка создания.
* **Loading** — скелетоны (списки/карточки/профиль); спиннер для точечных действий в формах.
* **Error** — блок с иконкой, текстом и кнопкой «Повторить» (для списков); toast (для действий); инлайн под полем (для валидации).

### Паттерн «Нет прав»

* Нет права на просмотр — раздел/вкладка скрыты из навигации.
* Есть просмотр, нет редактирования — интерактивные элементы скрыты или disabled с tooltip «Недостаточно прав».

### Паттерн «Загрузка файла» (File Module)

```
┌─────────────────────────────────────────┐
│   📎  Перетащите файл или нажмите         │
│   PDF, JPG, PNG до N МБ                   │
└─────────────────────────────────────────┘
```

После загрузки — превью + название + [Заменить] [Удалить]. Внутренняя логика — File Module.

### Паттерн «Первичный документ»

Часть кадровых движений сотрудника (приём, назначение/снятие должности, смена статуса — отпуск/командировка/больничный/возврат к работе, увольнение) может требовать привязки первичного документа — приказа, оформленного в ЭДО. Требование условно: оно зависит от того, кто выполняет действие (для части сотрудников клиники документ обязателен, для остальных — нет); интерфейс должен корректно поддерживать оба случая, не блокируя действие раньше времени.

Структурные изменения (создание/изменение/упразднение отдела или должности), а также второстепенные HR-операции (контакты, рабочие места, график, специализации, допуски, аттестации, документы сотрудника, инструктажи, лицензии, настройка ставок штатного расписания) первичного документа не требуют.

Каждая модалка кадрового действия, к которой применим этот паттерн, содержит блок «Первичный документ» с выбором источника (сегмент-контрол / табы):

```
┌────────────────────────────────────────────────┐
│  Первичный документ                             │
│  ◉ Создать новый   ○ Из шаблона                 │
│  ○ Загрузить файл  ○ Из входящих                │
├────────────────────────────────────────────────┤
│  [ область выбранного источника ]               │
│  • после привязки — превью/строка документа     │
│    (название, тип приказа, статус) + [Заменить] │
└────────────────────────────────────────────────┘
```

| Источник | Поведение |
|----------|-----------|
| **Создать новый** | Открывает редактор ЭДО (1.5.4) с предзаполненными категорией и папкой приказа по типу действия, а также контекстом (сотрудник, отдел/должность). |
| **Из шаблона** | Выбор шаблона нужного типа приказа → заполнение (1.5.3) с тем же контекстом. |
| **Загрузить файл** | Загрузка готового файла с устройства (паттерн «Загрузка файла», File Module). Для движений, инициированных самим сотрудником (рапорт, прошение, ходатайство, заявление). |
| **Из входящих** | Выбор существующего документа из входящих ЭДО (реестр 1.5.1) — например, ранее зарегистрированного заявления/рапорта сотрудника. |

Правила:

* Кнопка подтверждения действия (напр., «Уволить», «В отпуск», «Перевести») активна сразу, если для текущего пользователя документ не требуется; если требуется — активируется только после привязки.
* Привязанный документ связывается с движением и попадает в кадровое делопроизводство (1.6.10) в соответствующую папку приказа.
* Тип приказа предопределяется типом действия и в модалке read-only.
* Порядок подписания и вступление движения в силу — по правилам ЭДО (1.5); зависят от типа приказа (может применяться сразу при привязке черновика либо только после подписания).

### Паттерн «Объективка»

Объективка — печатная сводная карточка сотрудника (персональные + рабочие данные). Доступна как действие «Скачать / Распечатать объективку» из реестра сотрудников и электронного дела. На UI — кнопка и выбор формата (PDF / печать).

## Статусы сотрудника и матрица переходов

| Статус | Описание | Бейдж |
|--------|----------|-------|
| На рабочем месте | Активен, работает | Зелёный |
| Вне рабочего места | Отсутствует (в т.ч. больничный) | Серый |
| В отпуске | В отпуске | Жёлтый |
| В командировке | В командировке | Жёлтый |
| Уволен | В архиве | Серый |

```
На рабочем месте → Вне места | В отпуске | В командировке | Уволен
Вне места / В отпуске / В командировке → На рабочем месте
Уволен → На рабочем месте  (только через процедуру восстановления из архива)
```

* Каждый переход статуса — HR-движение и выполняется только через модалку действия, а не «молчаливой» сменой бейджа; требование первичного документа — см. паттерн выше.
* Переход в «Уволен» запускает архивирование данных сотрудника.
* Уволенные не отображаются в активном реестре; для них — фильтр/раздел «Архив» внутри 1.6.3.
* Переходы «В отпуске» / «В командировке» / «Вне места» логически связаны с графиком отпусков (1.6.9) и приказами ЭДО; возврат на рабочее место также оформляется первичным документом при необходимости (напр., приказ/уведомление о выходе).

## Права доступа — общий принцип

Видимость и доступность элементов интерфейса модуля определяется набором прав пользователя: право на просмотр раздела скрывает/показывает сам раздел, право на управление — интерактивные элементы (кнопки создания/редактирования/удаления) внутри него. Права на создание/удаление штатной единицы (кнопки на 1.6.5) относятся не к HR, а к орг. структуре (Structure Module). Полная сводная таблица конкретных прав — во frontend-документации `1.6.0. Overview` (Frontend).

## Acceptance criteria — общие (для всех экранов модуля)

* Навигация HR содержит активные пункты: Дашборд, Орг. структура, Сотрудники, Штатное расписание, Инструктажи, Аттестации, Табель, График отпусков, Кадровое делопроизводство; и Soon-пункты (Испытательные сроки, Интерны, Рекрутинг, Отчёты).
* Электронное дело — вложенный экран, открываемый из реестра/карты/списков, а не пункт меню.
* Все реестры поддерживают поиск, фильтрацию, пагинацию и состояния пусто/загрузка/ошибка.
* Статус-бейджи во всех разделах используют единую цветовую семантику.
* Формы — модальные окна с `*`-полями и неактивной кнопкой сохранения до валидации.
* Контекстное меню доступно по `⋮` и по ПКМ.
* Кадровые движения, к которым применим паттерн «Первичный документ», содержат соответствующий блок; кнопка подтверждения корректно ведёт себя в обоих случаях (документ требуется / не требуется). Редактор ЭДО переиспользуется (1.5), а не встраивается.
* Элементы без прав скрыты или disabled с tooltip.
* Soon-разделы управляются feature-флагами и до включения показываются как «Скоро».
