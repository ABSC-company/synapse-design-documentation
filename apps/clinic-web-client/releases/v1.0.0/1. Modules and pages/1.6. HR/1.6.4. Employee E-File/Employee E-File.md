# 1.6.4 Employee E-File (Электронное дело сотрудника)

## Спецификация страницы интерфейса

* **Название страницы:** Электронное дело сотрудника
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Карточка сущности с секциями/вкладками
* **Основные роли:** Администратор / HR-менеджер, Руководитель отдела, Сотрудник (своё дело — просмотр)
* **Маршрут:** `/hr/employees/:id`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Общие паттерны (форма, статус-бейдж, загрузка файла, первичный документ, объективка, состояния) — см. `1.6.0. Overview`. Техническая реализация (единый источник данных карточки, схемы запросов по секциям, состояние) — во frontend-документе `1.6.4. Employee E-File` (Frontend).

---

## Назначение страницы и сценарии использования

Единое электронное дело сотрудника со всеми кадровыми данными и точкой кадровых действий. Дело разбито на секции (вкладки): персональные данные, рабочие данные, врачебные данные (для врачей), график, учёт времени, карьера, аттестации, документы. В шапке — быстрые кадровые действия (отпуск, больничный, командировка, увольнение).

С помощью страницы пользователь может:

1. Просматривать и редактировать персональные и рабочие данные.
2. Управлять специализациями/допусками врача (с удостоверяющими документами).
3. Настраивать рабочий график.
4. Смотреть учёт рабочего времени в виде календаря (приход/уход по дням, выбор месяца).
5. Видеть карьеру (таймлайн смены должностей).
6. Просматривать аттестации (таймлайн результатов).
7. Загружать/удалять документы сотрудника.
8. Выполнять кадровые действия: отпуск, больничный, командировка, увольнение.

## User Flows / Task Flows

### Flow 1. Открытие и навигация по секциям
1. Пользователь открывает дело из реестра (1.6.3), карты (1.6.2) или списка дашборда.
2. По умолчанию — секция «Персональные данные».
3. Для врача видны секции «Специализации», «Допуски», «Аттестации».

### Flow 2. Прямое редактирование данных
1. В секции «Персональные»/«Рабочие данные» пользователь нажимает «Редактировать» (или редактирует инлайн).
2. Вносит изменения, сохраняет → данные и шапка обновляются.

### Flow 3. Кадровое действие из шапки (отпуск/больничный/командировка)
1. Пользователь нажимает соответствующую кнопку в шапке (или выбирает статус в бейдж-дропдауне).
2. Открывается модалка действия: период/даты, комментарий, блок «Первичный документ» (паттерн из 1.6.0) — обязательность зависит от того, кто выполняет действие.
3. Если документ требуется, пользователь задаёт его одним из способов: создать новый приказ в ЭДО, создать из шаблона, загрузить готовый файл (напр., заявление/рапорт сотрудника) или выбрать из входящих.
4. Кнопка подтверждения активна сразу, если документ не требуется правилом; иначе — только после привязки.
5. Подтверждение → если приказ не требуется или подписание не предусмотрено — статус сотрудника меняется сразу, запись отражается в графике/табеле, документ (если был привязан) попадает в кадровое делопроизводство (1.6.10). Если приказ требует подписания — статус сотрудника **пока не меняется**, движение появляется в блоке «Связанные документы» (см. ниже) со статусом «Ожидает подписания»; статус сотрудника изменится автоматически после подписания (см. паттерн «Связанные документы», 1.6.0).

> **Кнопка «В отпуск» — быстрый путь.** Это простая смена статуса без учёта баланса дней и без создания структурированной записи отпуска. Для отпуска с учётом остатка дней, типа отпуска и планирования заранее — используется страница «График отпусков» (1.6.9), которая при оформлении переводит статус тем же образом, но через отдельную сущность учёта отпусков.

### Flow 4. Увольнение
1. Пользователь нажимает «Уволить» в шапке.
2. Модалка увольнения: предупреждение об архивировании и освобождении ставок + блок «Первичный документ» — обязательность зависит от того, кто выполняет действие.
3. Если документ требуется, пользователь задаёт основание: создать приказ об увольнении (новый / из шаблона) либо загрузить/выбрать инициирующий документ сотрудника (заявление об увольнении, рапорт, ходатайство) — из файла или из входящих ЭДО.
4. Кнопка «Уволить» (деструктивный стиль) активна сразу, если документ не требуется правилом; иначе — только при привязанном документе.
5. Подтверждение → если приказ не требуется или подписание не предусмотрено — сразу архивирование (спиннер «Архивируем данные…»), освобождение ставок, сотрудник уходит в архив; приказ (если был привязан) фиксируется в делопроизводстве и карьере. Если приказ требует подписания — сотрудник **остаётся активным**, никакого архивирования на этом шаге не происходит; увольнение появляется в блоке «Связанные документы» со статусом «Ожидает подписания» и применяется автоматически после подписания.

### Flow 5. Работа с врачебными данными / документами
1. В секции «Специализации»/«Допуски»/«Документы» — добавление через форму с загрузкой удостоверяющего файла; удаление с подтверждением.

## Структура: Wireframes

### Общий layout

```
┌───────────────────────────────────────────────────────────────────────────┐
│  ← Назад к списку                                                          │
├───────────────────────────────────────────────────────────────────────────┤
│  🖼  Иванов Иван Иванович            ● На рабочем месте ▾                   │
│      Хирург · Хирургия                                                      │
│      [🏖 В отпуск] [🤒 На больничный] [✈ В командировку] [🚪 Уволить] [⋮]   │
├───────────────────────────────────────────────────────────────────────────┤
│  ┌── Связанные документы ────────────────────────────────────────────┐    │
│  │  📄 Приказ о переводе       ● Ожидает подписания      [Открыть →] │    │
│  └─────────────────────────────────────────────────────────────────┘    │
│  (блок виден, только если есть хотя бы одно связанное движение)          │
├───────────────────────────────────────────────────────────────────────────┤
│ [Персональные][Рабочие данные][Специализации]*[Допуски]*[График]            │
│ [Учёт времени][Карьера][Аттестации]*[Документы]                             │
├───────────────────────────────────────────────────────────────────────────┤
│                       содержимое активной секции                           │
└───────────────────────────────────────────────────────────────────────────┘
```

\* «Специализации», «Допуски», «Аттестации» — только для врачей.

### Шапка дела
* Крупный аватар, ФИО, основная должность · отдел.
* Статус — кликабельный бейдж-дропдаун (допустимые переходы, см. `1.6.0`); выбор перехода открывает модалку кадрового действия.
* Кнопки кадровых действий: **В отпуск**, **На больничный**, **В командировку**, **Уволить**.
* `⋮` — доп. действия: объективка (скачать/печать), учёт времени (экспорт), редактировать.

### Блок «Связанные документы»

Показывает движения этого сотрудника, инициированные через модалки шапки (отпуск/больничный/командировка/увольнение) и через назначение/снятие должности (секция «Рабочие данные»), ждущие подписания приказа либо недавно применённые — см. паттерн в `1.6.0. Overview`. Расположен сразу под шапкой, над вкладками секций, чтобы быть заметным независимо от того, какая секция открыта. Клик по строке — карточка документа (модуль 1.5). Скрыт, если движений нет.

### Секция «Персональные данные»
Прямое редактирование (инлайн или кнопка «Редактировать»).
```
┌─────────────────────────────────────────────────────────┐
│  Персональные данные                  [Редактировать]    │
├─────────────────────────────────────────────────────────┤
│  ФИО · Дата рождения · Пол · Семейное положение          │
│  Гражданство · Адрес проживания                          │
│  Контакты: 📞 …  ✉️ …  💬 …                              │
│  Документы личности: MRZ · Серия/номер  (служебно)       │
└─────────────────────────────────────────────────────────┘
```

### Секция «Рабочие данные»
Прямое редактирование. Должности + статус инструктажей + рабочие места.
```
┌─────────────────────────────────────────────────────┐
│  Должности                  [+ Назначить должность]  │
│  Хирург · Хирургия         Ставка 1.0      [✏][✕]    │
│  Консультант · Терапия      Ставка 0.5     [✏][✕]    │
├─────────────────────────────────────────────────────┤
│  Рабочие места             [+ Назначить место]       │
│  Кабинет 204  ★ Основное                  [✏][✕]    │
├─────────────────────────────────────────────────────┤
│  Статус инструктажей                                 │
│  ✅ ТБ в операционной — пройден 12.01.2026           │
│  ⚠ Работа с оборудованием — требуется                │
└─────────────────────────────────────────────────────┘
```
* Назначение/снятие должности занимает/освобождает ставку (штатное расписание) и оформляется через модалку с блоком первичного документа — обязательность зависит от того, кто выполняет действие. Если приказ требует подписания, список должностей в этой секции **не меняется** до подписания — движение отражается в блоке «Связанные документы» под шапкой.
* Одно основное рабочее место; смена основного снимает метку с прежнего (с предупреждением).
* Статус инструктажей агрегирует требуемые/пройденные (источник — 1.6.6); «требуется» подсвечено.

### Секция «Специализации» (врач)
```
┌─────────────────────────────────────────────────────┐
│  Специализации              [+ Добавить]             │
│  🩺 Хирургия · Категория: Высшая   📎 документ [✏][✕]│
│  🩺 Эндоскопия · Категория: —      📎 документ [✕]   │
└─────────────────────────────────────────────────────┘
```
Форма: специализация + категория (необяз.) + удостоверяющий документ.

### Секция «Допуски» (врач)
```
┌─────────────────────────────────────────────────────┐
│  Допуски к услугам          [+ Добавить]             │
│  Услуги: УЗИ, Гастроскопия    📎 сертификат  [✏][✕] │
└─────────────────────────────────────────────────────┘
```
Форма: услуги (мульти-select) + сертификат (может быть бессрочным).

**Эффективный набор услуг врача — не равен списку допусков.** Реально оказать услугу врач может, только если она также покрыта лицензией клиники — фактический список = допуски ∩ лицензии клиники. Если у клиники нет лицензии на услугу, интерфейс должен явно показывать это как отдельную причину недоступности услуги (не просто «нет допуска»), например бейджем «Услуга не лицензирована клиникой» рядом с этой услугой в списке допусков. Управление самими лицензиями клиники — общеклиническая, а не персональная сущность, отдельного экрана в текущем объёме не описано.

### Секция «График»
Недельная таблица рабочих дней/промежутков/перерывов.
```
        Пн     Вт     Ср     Чт     Пт    Сб Вс
Раб.     ✓      ✓      ✓      ✓      ✓     –  –
Время  09–18  09–18  09–18  09–18  09–18
Перерыв13–14  13–14  13–14  13–14  13–14
```
«Редактировать»: multi-toggle дней, динамические пары time-picker'ов (промежутки и перерывы), валидация «перерыв внутри рабочего времени». Пусто — «График не установлен» + «Установить график».

### Секция «Учёт рабочего времени» (календарь)
```
┌─────────────────────────────────────────────────────────────┐
│  Учёт времени          ◀ Июнь 2026 ▶        [+ Отметка]      │
├─────────────────────────────────────────────────────────────┤
│  Пн   Вт   Ср   Чт   Пт   Сб   Вс                            │
│  ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐                                │
│  │1 ││2 ││3 ││4 ││5 ││6 ││7 │                                │
│  │09││09││— ││09││09││  ││  │  ← приход                       │
│  │18││18││  ││18││17││  ││  │  ← уход                         │
│  └──┘└──┘└──┘└──┘└──┘└──┘└──┘                                │
│  ...                                                         │
│  Итого за месяц: 168 ч · Опозданий: 2 · Пропусков: 1         │
└─────────────────────────────────────────────────────────────┘
```
Месячный календарь: в каждой ячейке дня — приход/уход; день без отметок выделен; опоздания/недоработки — цветовой акцент. Переключение месяца стрелками; сводка по месяцу внизу. «+ Отметка» (корректирующее, secondary-стиль) — тип (Приход/Уход) + дата-время.

### Секция «Карьера» (таймлайн должностей)
История смены должностей в рамках клиники.
```
┌─────────────────────────────────────────────────────┐
│  Карьера                                             │
│  ● 2026 — наст. время                                │
│  │   Хирург · Хирургия · ставка 1.0                  │
│  │   📄 Приказ о переводе                            │
│  ● 2023 — 2026                                        │
│  │   Врач-ординатор · Хирургия · ставка 0.5          │
│  │   📄 Приказ о приёме                              │
│  ○ ...                                                │
└─────────────────────────────────────────────────────┘
```
Вертикальный таймлайн: период, должность, отдел, ставка, ссылка на приказ (ЭДО). Только просмотр.

### Секция «Аттестации» (врач, таймлайн)
```
┌─────────────────────────────────────────────────────┐
│  Аттестации                 [+ Добавить]             │
│  ● 09.2026  Хирургия · Присвоение категории          │
│             ● Запланирована                          │
│  ● 03.2026  Терапия · Подтверждение категории         │
│             ● Просрочена                             │
└─────────────────────────────────────────────────────┘
```
Таймлайн результатов; статус-бейдж. Форма: специализация + период + тип/статус.

### Секция «Документы»
```
┌─────────────────────────────────────────────────────────────┐
│  Документы                        [+ Добавить документ]      │
│  📄 Диплом · Бессрочный                            [✏][✕]    │
│  📄 Удостоверение · до 12.05.2027  ● Действует     [✏][✕]    │
│  📄 Сертификат · до 01.02.2026  ● Истекает скоро   [✏][✕]    │
└─────────────────────────────────────────────────────────────┘
```
Форма: тип документа (справочник, управляемый мини-реестром из формы) + чекбокс «Бессрочный» (скрывает период) + срок + файл. Статус-бейдж по сроку (действует/истекает ≤30 дней/истёк/бессрочный).

### Модалки кадровых действий (шапка)

Все модалки кадровых действий содержат блок «Первичный документ» (сегмент-контрол: создать новый / из шаблона / загрузить файл / из входящих — см. паттерн в 1.6.0); документ обязателен, и кнопка подтверждения неактивна без него, только для части исполнителей — для остальных блок опционален, кнопка активна сразу.

```
┌──────────────────────────────────────────────┐
│  Уволить сотрудника                       [✕] │
├──────────────────────────────────────────────┤
│  ⚠ Данные будут заархивированы, ставки        │
│     освобождены. Действие необратимо.         │
│                                                │
│  Дата увольнения *   [ 15.07.2026 ]           │
│  Комментарий         [ ................. ]     │
│                                                │
│  ┌── Первичный документ ────────────────────┐ │
│  │ ◉ Создать новый  ○ Из шаблона            │ │
│  │ ○ Загрузить файл ○ Из входящих           │ │
│  │ ─────────────────────────────────────    │ │
│  │ 📄 Приказ об увольнении · Draft [Заменить]│ │
│  └───────────────────────────────────────────┘ │
├──────────────────────────────────────────────┤
│              [Отмена]        [Уволить]        │
└──────────────────────────────────────────────┘
```

**В отпуск / В командировку:** период (date-range) + комментарий + блок первичного документа. Подтверждение → смена статуса; отпуск отражается в графике отпусков (1.6.9).
**На больничный:** дата начала (+ ожидаемая дата окончания, необяз.) + комментарий + блок первичного документа. Статус меняется на «отсутствует».
**Возврат на рабочее место** (выход с отпуска/больничного/командировки) — также через модалку с первичным документом на тех же условиях (приказ/уведомление о выходе).
**Уволить:** предупреждение об архивировании + освобождении ставок + блок первичного документа — приказ об увольнении (новый/из шаблона) или инициирующий документ сотрудника (заявление/рапорт, загруженный или из входящих); кнопка «Уволить» — деструктивный стиль; во время архивирования — спиннер «Архивируем данные…».

## Визуал: High-Fidelity mockups

1. Шапка доминирует: крупный аватар, ФИО, статус-дропдаун, ряд кнопок кадровых действий с понятными иконками.
2. Кнопка «Уволить» визуально отделена (деструктивный акцент) от отпуска/больничного/командировки.
3. Секции переключаются вкладками с индикатором активной; врачебные секции появляются по типу занятости.
4. Учёт времени — наглядный месячный календарь с цветовой индикацией опозданий/пропусков и месячной сводкой.
5. Карьера и аттестации — вертикальные таймлайны с маркерами и статус-бейджами.
6. Все статус-бейджи — единая семантика модуля.
7. Формы с загрузкой файла показывают превью документа.
8. Соответствие единой дизайн-системе.

## Состояния и edge cases

### Empty (по секциям)
Должности — «Должности не назначены»; Рабочие места — «Не назначены»; Специализации/Допуски — «Не добавлены»; График — «Не установлен»; Учёт времени — «Отметок за месяц нет»; Карьера — «История пуста»; Аттестации — «Аттестаций нет»; Документы — «Документы не добавлены»; Связанные документы — блок не рендерится вовсе (не пустое состояние, а отсутствие блока).

### Loading
Скелетон содержимого секции; спиннер в формах и при архивировании (увольнение); блок «Связанные документы» — узкая полоска-скелетон под шапкой на время загрузки (не блокирует остальную страницу).

### Error
Сбой загрузки секции — блок ошибки + «Повторить»; сбой действия — toast; валидация — инлайн под полем.

### Offline
Кадровые действия и CRUD заблокированы, toast «Нет соединения»; незагруженная секция — Error.

### Permissions
Секция/действие скрыты без соответствующего права; своё дело сотрудник видит read-only; кадровые действия скрыты без права на смену статуса/увольнение.

### Edge cases
* Тип занятости неизменяем — набор врачебных секций фиксирован.
* Снятие последней должности освобождает ставку (предупреждение).
* Смена основного рабочего места снимает метку с прежнего (предупреждение).
* Перерыв вне рабочего промежутка — блок валидацией.
* Отпуск/командировка с пересекающимися периодами — предупреждение о конфликте (проверка по графику отпусков).
* Возврат с больничного/отпуска/командировки — переход обратно на рабочее место.

## Interaction & Animation

* **Переключение секций** — fade ~150–200 мс, анимированный индикатор вкладки.
* **Статус-дропдаун** — раскрытие из бейджа; выбор целевого статуса открывает соответствующую модалку кадрового действия, а не меняет статус «молча»; бейдж перекрашивается только после подтверждения.
* **Кнопки кадровых действий** — открывают модалки fade+scale; «Уволить» — подтверждение + спиннер архивирования.
* **Календарь учёта** — слайд при смене месяца; hover дня показывает детали отметок.
* **Таймлайны** — последовательное появление узлов при прокрутке (reveal).
* **CRUD в секциях** — hover-подсветка строк, `[✏][✕]` на hover; удаление с подтверждением и анимацией исчезновения.
* **Toast** — выезд, авто-скрытие 3–5 с.

## Зависимости и ограничения

* Должности/отделы/места — Structure Module; роли — Auth Module; специализации/категории/гендер-стандарт — глобальные настройки; услуги для допусков — модуль услуг; файлы (фото, документы, объективка, архив) — File Module; приказы — EDM Module.
* Тип занятости, системный пользователь, филиал — неизменяемы после создания.
* Занятость ставки обновляется автоматически при назначении/снятии должности.
* Одно основное рабочее место; перерыв внутри рабочего времени.
* Карьера/история — только просмотр.

## Acceptance criteria

* Дело — единая страница с секциями; шапка показывает фото, ФИО, должность/отдел, статус и кнопки кадровых действий (отпуск, больничный, командировка, увольнение).
* Секции «Специализации», «Допуски», «Аттестации» видны только для врача.
* В «Персональных» и «Рабочих данных» данные редактируются напрямую.
* Специализации/допуски добавляются/удаляются с загрузкой удостоверяющего документа.
* График настраивается недельной формой с валидацией перерыва.
* «Учёт времени» — календарь с приходом/уходом по дням и выбором месяца.
* «Карьера» — таймлайн смены должностей; «Аттестации» — таймлайн результатов со статус-бейджами.
* «Документы» — загрузка/удаление с указанием типа; различение срочных/бессрочных.
* Кадровые действия корректно реагируют на оба случая обязательности первичного документа; увольнение архивирует данные и освобождает ставки.
* Блок «Связанные документы» под шапкой показывает движения, ждущие подписания приказа (и недавно применённые), со статусом и переходом на карточку документа; скрыт при отсутствии движений. Пока движение не подписано — соответствующие данные сотрудника (статус, должности) на странице не меняются.
* Смена статуса через бейдж-дропдаун открывает модалку действия, а не меняет статус «молча».
* Для каждой секции предусмотрены состояния: пусто, загрузка, ошибка, нет прав.
