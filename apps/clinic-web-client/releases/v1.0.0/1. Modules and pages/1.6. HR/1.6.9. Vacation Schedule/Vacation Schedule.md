# 1.6.9 Vacation Schedule (График отпусков)

## Спецификация страницы интерфейса

* **Название страницы:** График отпусков
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Таймлайн/диаграмма Ганта (сотрудники × календарь) + реестр
* **Основные роли:** Администратор / HR-менеджер, Руководитель отдела
* **Маршрут:** `/hr/vacations`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано
* **Feature flag:** `hr_vacations`

> Общие паттерны — см. `1.6.0. Overview`. Быстрая, неструктурированная отправка сотрудника в отпуск (без учёта баланса дней) также доступна из его эл. дела (1.6.4) через прямую смену статуса — см. примечание там. Техническая реализация (эндпоинты, состав полей, интеграция с задачами) — во frontend-документе `1.6.9. Vacation Schedule` (Frontend).

---

## Назначение страницы и сценарии использования

Годовой график отпусков клиники в виде диаграммы-таймлайна: кто и когда в отпуске, планируемые и фактические периоды, пересечения внутри отдела. Помогает планировать отпуска без оголения отделов и контролировать остаток отпускных дней.

С помощью страницы пользователь может:

1. Видеть отпуска всех сотрудников на годовой шкале (по отделам).
2. Различать запланированные и утверждённые отпуска.
3. Выявлять пересечения отпусков в отделе.
4. Планировать/оформлять отпуск (период, тип); оформление может требовать первичного документа (приказ об отпуске / заявление).
5. Отслеживать остаток отпускных дней по сотруднику.

---

## User Flows / Task Flows

### Flow 1. Просмотр графика
1. Пользователь открывает «График отпусков».
2. Система показывает таймлайн на год; строки — сотрудники, сгруппированные по отделам.
3. Фильтрует по отделу/сотруднику/году.

### Flow 2. Планирование отпуска
1. Пользователь нажимает «+ Запланировать отпуск» (или выделяет диапазон на шкале сотрудника).
2. Открывается форма: сотрудник, период, тип отпуска.
3. Сохранение → запланированный отпуск появляется на шкале; статус сотрудника пока не меняется.

### Flow 3. Утверждение / оформление
1. Пользователь открывает запланированный отпуск → «Оформить».
2. Форма с блоком первичного документа (приказ об отпуске / заявление) — обязательность зависит от того, кто выполняет действие.
3. Подтверждение → отпуск переходит в статус «Утверждён». Статус сотрудника автоматически меняется на дату начала и возвращается обратно на дату окончания — не в момент оформления.

## Структура: Wireframes

### Общий layout (Гант)
```
┌──────────────────────────────────────────────────────────────────────────┐
│  График отпусков   [Год 2026 ▾]            [Фильтр ▾]  [+ Запланировать]   │
├───────────────────┬────────────────────────────────────────────────────────┤
│  Сотрудник        │ Янв Фев Мар Апр Май Июн Июл Авг Сен Окт Ноя Дек         │
├───────────────────┼────────────────────────────────────────────────────────┤
│  ▸ Хирургия                                                                 │
│    Иванов И.      │              ▓▓▓▓(план)        ███(факт)                │
│    Сидоров К.     │      ███                                                 │
│  ▸ Терапия                                                                  │
│    Петрова А.     │                         ▓▓▓▓▓                            │
└───────────────────┴────────────────────────────────────────────────────────┘
   Легенда: ███ утверждён · ▓▓▓ запланирован · ░░░ отменён/отклонён (приглушённый) · ⚠ пересечение
```

### Управление
* Селектор года; «Фильтр» (Drawer): отдел, сотрудник, тип отпуска, статус.
* Группировка строк по отделам (сворачиваемые группы).

### Полоса отпуска (на шкале)
* Цвет/паттерн: утверждён — сплошной; запланирован — штриховка; отменён/отклонён — приглушённый, зачёркнутый (по умолчанию скрыт фильтром статуса).
* Пересечения в отделе подсвечиваются (⚠) — предупреждение, не блокировка.
* Hover — тултип: сотрудник, период, тип, статус; клик — карточка/действия.

### Форма «Запланировать/оформить отпуск»
```
┌────────────────────────────────────────┐
│  Отпуск                              [✕]│
├────────────────────────────────────────┤
│  Сотрудник *      ▾ (поиск по ФИО)       │
│  Тип отпуска *    ▾ Ежегодный /          │
│                      Без сохранения з/п /│
│                      Учебный / Больничный│
│  Период *         [с] – [по]             │
│  Остаток дней (за год, только для        │
│    ежегодного): 14 из 28 (подсказка)     │
│  Комментарий                             │
│  ┌── Первичный документ ──────────────┐  │
│  │ (обязателен только при оформлении, │  │
│  │  см. ниже, и не для всех)          │  │
│  │ ◉ Создать новый  ○ Из шаблона      │  │
│  │ ○ Загрузить файл ○ Из входящих     │  │
│  └─────────────────────────────────────┘  │
├────────────────────────────────────────┤
│       [Отмена]  [Запланировать/Оформить]│
└────────────────────────────────────────┘
```
* Тип отпуска — фиксированный набор из четырёх значений: ежегодный, без сохранения зарплаты, учебный, больничный.
* «Остаток дней» — только для ежегодного отпуска: годовая норма минус сумма дней уже утверждённых/завершённых отпусков этого типа за календарный год периода. Для остальных типов остаток не считается и не показывается.
* **Планирование** создаёт запись со статусом «Запланирован» — первичный документ на этом шаге не запрашивается, статус сотрудника не меняется.
* **Оформление** (перевод в «Утверждён») — HR-движение, первичный документ обязателен только для части исполнителей. При оформлении статус сотрудника меняется автоматически на даты начала/окончания, а не немедленно.

### Реестр-режим (альтернативный вид)
Переключатель «Таймлайн / Список»: таблица отпусков (Сотрудник · Отдел · Тип · Период · Статус · Дней) с фильтрами и сортировкой.

## Визуал: High-Fidelity mockups

1. Годовая Гант-диаграмма с залипающей колонкой сотрудников и прокручиваемыми месяцами; «сегодня» — вертикальная линия.
2. Полосы отпусков различимы по статусу (план/факт); пересечения внутри отдела подсвечены предупреждающим цветом.
3. Группы отделов сворачиваются; легенда статусов видна.
4. Переключатель «Таймлайн/Список». Единая дизайн-система.

## Состояния и edge cases

* **Empty:** «Отпуска не запланированы» (+запланировать).
* **Loading:** скелетон таймлайна/таблицы; спиннер на сохранении.
* **Error:** блок ошибки + «Повторить»; toast при сбое.
* **Offline:** график из кэша; планирование заблокировано, toast.
* **Permissions:** без права на просмотр — раздел недоступен; без права на управление — планирование/оформление/отмена скрыты (только просмотр); раздел скрыт без включённого feature flag.
* **Edge cases:** пересечение периодов одного и того же сотрудника — жёсткий запрет, не предупреждение; пересечение отпусков разных сотрудников одного отдела — система не проверяет, интерфейс показывает как визуальное предупреждение, не блокирует; превышение остатка дней ежегодного отпуска — система отклоняет; отмена утверждённого отпуска — только через явный перевод в статус «Отменён» (снимает связанное автоматическое изменение статуса на будущие даты); удалить (а не отменить) можно только запланированную запись; авто-смена статуса сотрудника выполняется на даты начала/окончания периода, а не в момент оформления.

## Interaction & Animation

* Прокрутка месяцев — горизонтальный слайд с залипающей колонкой; сворачивание групп — анимация высоты.
* Выделение диапазона на шкале — drag для создания отпуска с живым предпросмотром полосы.
* Hover полосы — тултип; клик — карточка действий (fade+scale).
* Предупреждение о пересечении — мягкая пульсация акцента. Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Отделы — Structure Module; приказы — через первичный документ (EDM); автоматический переход статуса сотрудника на начало/конец периода — общесистемный модуль планирования задач; связь с табелем (1.6.8) и дашбордом (1.6.1, «предстоящие отпуска»).
* Раздел под feature flag `hr_vacations`; типы отпусков — фиксированный набор, не редактируемый справочник; остаток дней считается только для ежегодного отпуска от глобальной нормы клиники; пересечение периодов одного сотрудника — жёсткий запрет, пересечение разных сотрудников отдела — только предупреждение на UI.

---

## Acceptance criteria

* График отображает отпуска всех сотрудников на годовой шкале, сгруппированных по отделам.
* Запланированные и утверждённые отпуска визуально различимы; пересечения в отделе подсвечены как предупреждение, не блокируют.
* Планирование отпуска не требует первичного документа и не меняет статус сотрудника; оформление требует первичного документа только для части исполнителей.
* Статус сотрудника меняется не в момент оформления, а автоматически на даты начала/окончания периода.
* Пересечение периодов одного сотрудника система отклоняет; превышение остатка дней ежегодного отпуска система отклоняет.
* Доступен альтернативный список-вид с фильтрами.
* Раздел управляется feature-флагом; планирование/оформление скрыто без права на управление.
* Состояния empty / loading / error / offline / permissions обрабатываются корректно.
