# 1.6.9 Absence Schedule (График отсутствий)

## Спецификация страницы интерфейса

* **Название страницы:** График отсутствий (отпуска, командировки, больничные)
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Таймлайн/диаграмма Ганта (сотрудники × календарь) + реестр
* **Основные роли:** Администратор / HR-менеджер, Руководитель отдела
* **Маршрут:** `/hr/absences`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано
* **Feature flag:** `hr_absences`

> Общие паттерны — см. `1.6.0. Overview`. Отсутствия можно оформлять и из электронного дела сотрудника (`1.6.4`), там та же форма и те же правила.

---

## Назначение страницы и сценарии использования

Единый журнал и годовой график отсутствий клиники: кто, когда и по какой причине не работает — отпуск, командировка, больничный или иное. Запись журнала определяет статус сотрудника («В отпуске», «В командировке», «На больничном», «Вне рабочего места»).

С помощью страницы пользователь может:

1. Видеть отсутствия всех сотрудников на годовой шкале (по отделам).
2. Различать типы отсутствий цветом и состояния (запланировано, согласовано, идёт, завершено) прозрачностью или штриховкой.
3. Выявлять пересечения в отделе.
4. Планировать и оформлять отпуск или командировку (период, тип, для командировки место и цель); оформление может требовать первичного документа (приказ).
5. Заводить больничный и иное отсутствие без документа и закрывать их, когда сотрудник вышел.
6. Отслеживать остаток отпускных дней по сотруднику.

---

## User Flows / Task Flows

### Flow 1. Просмотр графика
1. Пользователь открывает «График отсутствий».
2. Система показывает таймлайн на год; строки — сотрудники, сгруппированные по отделам.
3. Фильтрует по отделу, сотруднику, типу, статусу, году.

### Flow 2. Планирование отпуска или командировки
1. Пользователь нажимает «+ Запланировать» (или выделяет диапазон на шкале сотрудника).
2. Форма: сотрудник, тип, период; для командировки — место назначения и цель.
3. Сохранение → запись появляется на шкале; статус сотрудника пока не меняется.

### Flow 3. Оформление (отпуск, командировка)
1. Пользователь открывает запланированную запись → «Оформить».
2. Форма с блоком первичного документа (приказ об отпуске или командировке); обязательность зависит от того, кто выполняет действие.
3. Подтверждение → если приказ не требуется, запись сразу «Согласовано»; если приказ нужно подписать, запись остаётся «Запланировано» с блоком «Связанные документы».
4. Статус сотрудника меняется автоматически в день начала и возвращается после окончания периода.

### Flow 4. Больничный и иное отсутствие (без документа)
1. Пользователь нажимает «+ Запланировать» и выбирает тип «Больничный» или «Иное», либо открывает электронное дело сотрудника.
2. Указывает дату начала (не позже сегодняшнего дня) и комментарий, при желании прикладывает подтверждающий файл.
3. Запись создаётся сразу в статусе «Идёт», сотрудник сразу получает статус «На больничном» или «Вне рабочего места»; дата окончания не указывается.
4. Когда сотрудник вышел, пользователь нажимает «Закрыть» и указывает дату выхода (по умолчанию сегодня): запись становится «Завершено», статус сотрудника возвращается на «На рабочем месте».

### Flow 5. Досрочный выход
Для идущего отпуска или командировки действие «Закрыть» сокращает период до выбранной даты и возвращает сотрудника на работу; документ не нужен.

### Flow 6. Предупреждение о записях пациентов
1. Пользователь выбирает сотрудника-врача и период в форме отсутствия (на странице графика или в электронном деле).
2. Система заранее показывает, сколько у врача записей пациентов на период: «У врача N записей (предварительных — R, оплаченных — P). После оформления они будут отменены, пациенты получат уведомление, оплаченные записи будут помечены на возврат». Подробный список (дата, время, пациент, услуга) доступен раскрывающимся блоком только пользователю с правом на просмотр записей.
3. Для больничного и иного оформление возможно только после отметки «Подтверждаю отмену записей»; для отпуска и командировки при планировании предупреждение информационное, при оформлении отметка обязательна.
4. После оформления записи отменяются автоматически; в карточке отсутствия виден счётчик «Отменено записей: N».

## Структура: Wireframes

### Общий layout (Гант)
```
┌──────────────────────────────────────────────────────────────────────────┐
│  График отсутствий   [Год 2026 ▾]          [Фильтр ▾]  [+ Запланировать]   │
├───────────────────┬────────────────────────────────────────────────────────┤
│  Сотрудник        │ Янв Фев Мар Апр Май Июн Июл Авг Сен Окт Ноя Дек         │
├───────────────────┼────────────────────────────────────────────────────────┤
│  ▸ Хирургия                                                                 │
│    Иванов И.      │              ▓▓▓▓(план)        ███(идёт)                │
│    Сидоров К.     │      ███                  🟧🟧🟧▶(больничный открыт)     │
│  ▸ Терапия                                                                  │
│    Петрова А.     │                         ▓▓▓▓▓ (командировка)             │
└───────────────────┴────────────────────────────────────────────────────────┘
   Легенда: цвет — тип отсутствия · сплошной — идёт/согласовано · штриховка — запланировано · приглушённый — отменено · ▶ открыто · ⚠ пересечение · ▒ нерабочий день клиники
```

### Управление
* Селектор года; «Фильтр» (Drawer): отдел, сотрудник, тип отсутствия, статус; поиск по ФИО.
* Группировка строк по отделам (сворачиваемые группы). Диаграмма листается страницами сотрудников; уволенные сотрудники не показываются; нерабочие дни клиники закрашены на шкале отдельным цветом (ежегодные праздники и разовые нерабочие дни).

### Полоса отсутствия (на шкале)
* Цвет — тип (ежегодный, без сохранения, учебный, командировка, больничный, иное); паттерн — состояние: идёт/согласовано — сплошной, запланировано — штриховка, отменено — приглушённый и зачёркнутый (по умолчанию скрыт фильтром).
* Открытая запись (больничный или иное без даты окончания) тянется до сегодняшнего дня и заканчивается стрелкой «▶».
* Пересечения в отделе подсвечиваются (⚠) — предупреждение, не блокировка.
* Hover — тултип: сотрудник, период, тип, место (для командировки), состояние; клик — карточка и действия.

**Карточка записи.** Показывает тип, период (или «с даты, открыто»), место и цель командировки, комментарий, документ. При состоянии «Запланировано» с инициированным, но ещё не подписанным оформлением — блок «Связанные документы» со статусом подписания. Действия по состоянию: «Оформить» и «Отменить» (запланировано), «Закрыть» (идёт), «Удалить» (запланировано).

### Форма «Запланировать / оформить»
```
┌────────────────────────────────────────┐
│  Отсутствие                          [✕]│
├────────────────────────────────────────┤
│  Сотрудник *      ▾ (поиск по ФИО)       │
│  Тип *            ▾ Ежегодный отпуск /   │
│                      Без сохранения з/п /│
│                      Учебный / Командировка │
│                      / Больничный / Иное│
│  Период *         [с] – [по]             │  ← для больничного и «иного» только «с»
│  Место назначения *  [____]  (командировка)│
│  Цель             [____]  (командировка) │
│  Остаток дней (только ежегодный):        │
│    14 из 28 (подсказка)                  │
│  Комментарий                             │
│  ┌── Первичный документ ──────────────┐  │
│  │ (отпуск и командировка; при        │  │
│  │  оформлении, не для всех)          │  │
│  │ ◉ Создать новый  ○ Из шаблона      │  │
│  │ ○ Загрузить файл ○ Из входящих     │  │
│  └─────────────────────────────────────┘  │
├────────────────────────────────────────┤
│       [Отмена]  [Запланировать/Оформить]│
└────────────────────────────────────────┘
```
* Тип — фиксированный набор из шести значений.
* Журнал отсутствий — единый: по типу активной записи сотрудник получает статус «В отпуске» (ежегодный, без сохранения, учебный), «В командировке», «На больничном» или «Вне рабочего места» (иное). Отдельного журнала статусов нет.
* «Остаток дней» — только для ежегодного отпуска: годовая норма минус дни уже согласованных, идущих и завершённых ежегодных отпусков.
* **Планирование** создаёт запись «Запланировано»: документ на этом шаге не запрашивается, статус сотрудника не меняется.
* **Оформление** отпуска или командировки — HR-движение: первичный документ обязателен только для части исполнителей. Если приказ нужно подписать, запись остаётся «Запланировано» до подписания.
* **Больничный и иное** документа не требуют, создаются сразу «Идёт» и закрываются отдельным действием.

### Реестр-режим (альтернативный вид)
Переключатель «Таймлайн / Список»: таблица (Сотрудник · Отдел · Тип · Период · Состояние · Дней) с фильтрами и сортировкой; у открытых записей в колонке периода «с даты, открыто».

## Визуал: High-Fidelity mockups

1. Годовая Гант-диаграмма с залипающей колонкой сотрудников и прокручиваемыми месяцами; «сегодня» — вертикальная линия.
2. Полосы различимы по типу цветом и по состоянию прозрачностью или штриховкой; открытые записи со стрелкой.
3. Группы отделов сворачиваются; легенда видна.
4. Переключатель «Таймлайн/Список». Единая дизайн-система.

## Состояния и edge cases

* **Empty:** «Отсутствия не запланированы» (+запланировать).
* **Loading:** скелетон таймлайна/таблицы; спиннер на сохранении.
* **Error:** блок ошибки + «Повторить»; toast при сбое.
* **Offline:** график из кэша; создание и изменения заблокированы, toast.
* **Permissions:** без права на просмотр — раздел недоступен; без права на управление — запланировать, оформить, закрыть, отменить, удалить скрыты (только просмотр).
* **Edge cases:** пересечение периодов одного сотрудника — жёсткий запрет, открытая запись считается идущей до закрытия; пересечение отсутствий разных сотрудников одного отдела — предупреждение; превышение остатка ежегодного отпуска — предупреждение с возможностью продолжить правом управления; врач с согласованным или идущим отсутствием недоступен для записи пациентов.

## Interaction & Animation

* Прокрутка месяцев — горизонтальный слайд с залипающей колонкой; сворачивание групп — анимация высоты.
* Выделение диапазона на шкале — drag для создания записи с живым предпросмотром полосы.
* Hover полосы — тултип; клик — карточка действий (fade+scale).
* Закрытие открытой записи — выбор даты выхода, полоса «обрезается» с анимацией.
* Предупреждение о пересечении — мягкая пульсация акцента. Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Отделы — Structure Module; приказы — через первичный документ (EDM); автоматический переход статуса сотрудника на начало и конец периода — общесистемный планировщик задач; запись пациентов к врачу учитывает журнал отсутствий (Booking).

---

## Acceptance criteria

* График отображает отсутствия всех сотрудников на годовой шкале, сгруппированных по отделам, с разным цветом для каждого типа.
* Диаграмма листается страницами сотрудников, не показывает уволенных и закрашивает нерабочие дни клиники; пересечения в отделе считаются по всему отделу, а не только по текущей странице.
* Запланированные, согласованные, идущие и завершённые записи визуально различимы; пересечения в отделе подсвечены как предупреждение.
* Планирование отпуска или командировки не требует документа и не меняет статус сотрудника; оформление требует документа только когда это обязательно для исполнителя.
* Статус сотрудника по отпуску и командировке меняется автоматически на даты начала и окончания, по больничному и иному — сразу при создании записи и возвращается при закрытии.
* Если приказ нужно подписать, запись остаётся «Запланировано» до подписания, а карточка показывает «Связанные документы».
* Больничный и иное создаются без документа и без даты окончания; кнопка «Закрыть» фиксирует дату выхода.
* Если у врача есть записи пациентов на период, форма заранее показывает их число (предварительных и оплаченных), а список только при праве на просмотр записей; оформление требует подтверждения отмены, после чего записи отменяются автоматически, пациенты уведомляются, оплаченные записи помечаются на возврат.
* Пересечение периодов одного сотрудника отклоняется; превышение остатка ежегодного отпуска предупреждает.
* Доступен список-вид с фильтрами; раздел управляется feature-флагом; действия скрыты без права на управление.
* Состояния empty / loading / error / offline / permissions обрабатываются корректно.
