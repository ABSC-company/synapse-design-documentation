# 1.6.6 Briefings (Инструктажи)

## Спецификация страницы интерфейса

* **Название страницы:** Инструктажи
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Реестр (две вкладки: Шаблоны / Прохождение)
* **Основные роли:** Администратор / HR-менеджер
* **Маршрут:** `/hr/briefings`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Вкладка «Прохождение» не поддерживает ручное создание записи — отметка прохождения создаётся системой автоматически, в момент назначения сотруднику должности, для которой заведены шаблоны инструктажей. Вкладка «Прохождение» — read-only отчётный реестр.

> Общие паттерны — см. `1.6.0. Overview`. Отметки прохождения конкретным сотрудником также доступны из его эл. дела (1.6.4). Техническая реализация — во frontend-документе `1.6.6. Briefings` (Frontend).

---

## Назначение страницы и сценарии использования

Управление инструктажами клиники: инструктажи, привязанные к должности, и контроль их прохождения сотрудниками. Инструктаж не принадлежит конкретному сотруднику, поэтому раздел — отдельный пункт меню.

> Содержание инструктажа — не произвольный текст. Инструктаж ссылается на переиспользуемый **шаблон документа** (модуль документооборота ЭДО / EDM Module + субмодуль шаблонов документов, бэкенд), точно так же, как первичные документы кадровых движений (см. `1.6.0. Overview`). При назначении сотруднику должности, для которой заведён инструктаж, система автоматически создаёт по этому шаблону отдельный экземпляр документа персонально для сотрудника и отправляет его на подписание или ознакомление — правки шаблона не затрагивают уже созданные экземпляры.

С помощью страницы пользователь может:

1. Вести реестр инструктажей (по должностям).
2. Открывать привязанный документ инструктажа (шаблон) для просмотра содержания.
3. Создавать инструктаж сразу на несколько должностей, редактировать/удалять записи реестра.
4. Контролировать прохождение: кто прошёл, кому требуется (по должности).

---

## User Flows / Task Flows

### Flow 1. Управление инструктажами
1. Вкладка «Шаблоны» → список записей реестра (название + должность + документ-шаблон).
2. «+ Создать инструктаж» → форма: название, документ-шаблон (выбор существующего или создание нового по паттерну «Первичный документ», см. `1.6.0. Overview`), одна или несколько должностей, флаг обязательности подписания. При выборе нескольких должностей сервер создаёт отдельную запись реестра на каждую (см. Зависимости и ограничения).
3. `[✏]` — редактирование одной записи (название, документ-шаблон, подписание; смена набора должностей — через создание новых записей / удаление лишних). `[✕]` — удаление записи (снимает инструктаж с одной должности) с подтверждением.
4. Клик по карточке — открытие привязанного документа-шаблона (просмотр содержания в паттерне документов ЭДО).

### Flow 2. Контроль прохождения
1. Вкладка «Прохождение» → список сотрудников с требуемыми/пройденными инструктажами (отчётный реестр, только чтение).
2. Фильтр по отделу/должности/статусу (пройдено/требуется).
3. Клик по строке — переход в эл. дело сотрудника (1.6.4), где виден статус документа инструктажа и его подписание/ознакомление по правилам ЭДО.

## Структура: Wireframes

### Вкладка «Шаблоны»
```
┌─────────────────────────────────────────────────────────────┐
│  Инструктажи   [Шаблоны][Прохождение]     [+ Создать инструктаж]│
├─────────────────────────────────────────────────────────────┤
│  🔍 Поиск по названию/должности...                            │
├─────────────────────────────────────────────────────────────┤
│  ТБ в операционной                                           │
│  Должность: Хирург            [📄 Документ]        [✏] [✕]   │
├─────────────────────────────────────────────────────────────┤
│  ТБ в операционной                                           │
│  Должность: Анестезиолог      [📄 Документ]        [✏] [✕]   │
├─────────────────────────────────────────────────────────────┤
│  Обработка инструментов                                      │
│  Должность: Медсестра         [📄 Документ]        [✏] [✕]   │
└─────────────────────────────────────────────────────────────┘
```
* Карточка: название + должность + значок документа; клик по значку/карточке открывает привязанный документ-шаблон (просмотр содержания в паттерне документов ЭДО, см. `1.6.0. Overview`) — своя модалка/разворот, не редактор текста.
* Одному названию/документу могут соответствовать несколько карточек — по одной на каждую должность, на которую распространён инструктаж (создаются вместе при создании, см. Flow 1, шаг 2).

**Форма «Создать инструктаж»:** название * + документ-шаблон * (выбор существующего шаблона документа бакета `hr` или создание нового — паттерн источников «Первичный документ», `1.6.0. Overview` §1) + должности * (мультивыбор, минимум одна — при нескольких создаётся отдельная карточка на каждую) + требуется подписание (checkbox).

**Форма «Редактировать»:** те же поля, кроме списка должностей (одна запись = одна должность; правится в рамках своей карточки).

### Вкладка «Прохождение»
```
┌─────────────────────────────────────────────────────────────┐
│  Инструктажи   [Шаблоны][Прохождение]                        │
├─────────────────────────────────────────────────────────────┤
│  🔍 Поиск по сотруднику...                  [Фильтр ▾]       │
├─────────────────────────────────────────────────────────────┤
│ Сотрудник       │ Должность│ Инструктаж        │ Статус       │
│ Иванов И.       │ Хирург   │ ТБ в операционной │ ✅ Пройден   │
│ Петров П.       │ Хирург   │ ТБ в операционной │ ⚠ Требуется  │
└─────────────────────────────────────────────────────────────┘
```
* Данные отчёта приходят с сервера одним запросом — сервер сам сопоставляет должности с шаблонами инструктажей и фактическими отметками прохождения по всей клинике.
* Статус «Требуется» — отметка о прохождении не найдена; «Пройден»/иной статус — берётся из статуса связанного документа ЭДО.
* Строка кликабельна только на переход в эл. дело — никаких действий редактирования на этой вкладке нет.

## Состояния и edge cases

* **Empty:** «Инструктажи не созданы» (+создать) / «Нет данных о прохождении».
* **Loading:** скелетон карточек/строк; спиннер на сохранении.
* **Error:** блок ошибки + «Повторить»; toast при сбое действий.
* **Offline:** списки из кэша; действия заблокированы, toast.
* **Permissions:** без права на управление инструктажами — режим чтения (создание/редактирование/удаление скрыты); без права на просмотр сотрудников — раздел (обе вкладки) недоступен.
* **Edge cases:** несколько инструктажей на должность допустимы; удаление записи не стирает зафиксированную историю прохождений уже отправленных документов; смена должности сотрудника меняет набор требуемых инструктажей (новые инструктажи отправляются автоматически только при следующем назначении должности — снятие/добавление инструктажа к уже занятой должности задним числом отметку не создаёт); при создании на несколько должностей часть должностей может уже иметь этот же документ-шаблон — сервер отклоняет весь запрос (ни одна из карточек не создаётся), форма должна показать, для каких должностей произошёл конфликт.

## Interaction & Animation

* Переключение вкладок — fade-смена контента.
* Поиск — debounce; открытие документа-шаблона — модалка fade+scale (вьюер документов ЭДО).
* Hover карточки/строки — подсветка, появление действий; удаление с подтверждением и анимацией.
* Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Инструктажи привязаны к должностям (орг. структура); один инструктаж (документ-шаблон) может быть распространён на несколько должностей — каждая должность оформляется отдельной записью реестра.
* Связь с 1.6.4 (статус инструктажей в рабочих данных сотрудника) и 1.6.1 (виджет «требуемые инструктажи»).
* Содержание инструктажа — документ-шаблон ЭДО (модуль документооборота + субмодуль шаблонов документов, бэкенд), а не текст на этой странице; отметки прохождения не редактируются и не удаляются вручную ни с этой страницы, ни из эл. дела.

---

## Acceptance criteria

* Раздел — отдельный пункт меню с вкладками «Шаблоны» и «Прохождение».
* Записи реестра показывают название, должность и документ-шаблон; клик открывает документ-шаблон в вьюере ЭДО; форма создания требует название, документ-шаблон и хотя бы одну должность (при выборе нескольких — по записи на каждую).
* Создание/редактирование/удаление шаблонов — только при соответствующем праве; удаление с подтверждением.
* Вкладка «Прохождение» — read-only отчёт, сопоставляющий требуемые инструктажи с фактическими отметками и показывающий статус; ручного создания/редактирования отметок в интерфейсе нет.
* Состояния empty / loading / error / offline / permissions обрабатываются корректно.
