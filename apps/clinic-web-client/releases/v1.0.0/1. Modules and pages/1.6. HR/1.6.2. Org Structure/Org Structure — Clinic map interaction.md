# 1.6.2. Org Structure — Взаимодействие с картой клиники

## Спецификация

* Документ: описание пользовательского взаимодействия с картой клиники — здания, этажи, кабинеты, рабочие места и их привязка к орг-структуре.
* Связанные документы: [Org Structure.md](./Org%20Structure.md) (дерево отделов), `1.6.5. Staffing Schedule` (ставки), `1.3.4. Clinic map Page` (просмотр карты в регистратуре).
* Основные роли: Администратор системы, HR-менеджер.
* Статус документа: Актуализировано

> Техническая реализация (источники данных, запросы, ограничения контрактов, открытые вопросы к бэкенду) — во frontend-документе `1.6.2. Org Structure` (Frontend), раздел «Карта клиники».

## Общая модель взаимодействия

Карта клиники строится иерархически: у филиала — одна общая карта (загруженная SVG-схема), на ней выделяются этажи, этажи объединяются в здания, для каждого этажа отдельно загружается более детальная схема, на которой выделяются кабинеты. Кабинет соответствует одному рабочему месту, к которому привязываются сотрудники отдела. Процесс распознавания слоёв на загруженной графике выполняется автоматически при загрузке — пользователь только загружает файл и работает с уже размеченными интерактивными элементами.

---

## Flow 1. Загрузка карты филиала и получение этажей

1. Пользователь открывает страницу карты клиники. Пока карта не создана, страница пустая: по центру — empty state блок с кнопкой «Создать карту филиала».
2. Клик по кнопке открывает модальное окно, через которое пользователь загружает общую схему филиала (требования к файлу — подсказкой в модалке).
3. Система анализирует графику и автоматически выделяет слои как этажи.
4. Пользователь получает интерактивную схему: каждый выявленный этаж — кликабельный/выделяемый элемент (hover-подсветка, выделение кликом).

Ограничения:

* У филиала может быть только одна карта. Повторная загрузка — через удаление/замену существующей.
* Если система не смогла распознать ни одного слоя на загруженном файле — показывается ошибка валидации с подсказкой о требованиях к файлу.

## Flow 2. Объединение этажей в здания

Слои, выявленные на карте филиала, — это этажи. Зданий на исходной схеме нет: здание — логическая группировка, которую задаёт пользователь.

1. Пользователь переходит в режим «Объединение в здания».
2. Мультивыбор слоёв: клик/ctrl-клик (или рамка выделения) по элементам этажей на схеме — выбранные слои подсвечиваются.
3. Пользователь нажимает «Объединить в здание» и вводит название здания.
4. Система создаёт здание и группирует выбранные этажи; интерфейс визуально группирует слои (общий цвет/контур группы, подпись здания).
5. Пользователь повторяет шаги 2–4 для остальных зданий.

Правила и edge cases:

* Этаж может принадлежать только одному зданию; уже сгруппированные слои недоступны для выбора в новое здание (визуально погашены).
* Названия этажей внутри здания задаются отдельно (например «1 этаж», «2 этаж») — сразу в мастере или позже.
* Разгруппировка/правка состава здания доступна позже; удаление здания возвращает этажи в несгруппированное состояние, но не удаляет их.
* Незавершённое состояние допустимо: этажи без здания сохраняются; мастер показывает счётчик «не распределено этажей: N».

## Flow 3. Загрузка схемы этажа и получение кабинетов

1. Пользователь выбирает этаж (на карте филиала или в списке этажей здания) и загружает отдельную детальную схему этажа.
2. Система анализирует графику и автоматически выделяет слои как кабинеты; вместе с каждым кабинетом автоматически создаётся его рабочее место.
3. Пользователь получает интерактивный план этажа: каждый кабинет — кликабельный элемент.

## Flow 4. Настройка кабинета

Пользователь кликает по кабинету на плане этажа — открывается панель настройки кабинета:

| Поле | Назначение |
| --- | --- |
| Название кабинета | Свободный ввод, сохраняется по blur/кнопке «Сохранить» |
| Отдел (по орг-структуре) | Select с деревом отделов филиала; при выборе название рабочего места автоматически обновляется на название отдела |
| Кол-во сотрудников | Числовое поле — на сколько сотрудников рассчитан кабинет |
| Есть склад (склад отдела) | В разработке — контракт с бэкендом не согласован, поле пока не отображается в интерфейсе |

Кабинет без настройки (без названия/отдела) валиден — интерфейс помечает такие кабинеты как «не настроен».

## Flow 5. Назначение сотрудника на кабинет (рабочее место)

Кабинет и есть рабочее место: пользователь открывает кабинет → видит его отдел, вместимость и назначенных сотрудников → назначает сотрудника.

1. Пользователь открывает кабинет на плане этажа.
2. Панель кабинета показывает: отдел, занято/вместимость, список назначенных сотрудников.
3. Пользователь нажимает «Назначить сотрудника» и выбирает сотрудника (поиск по сотрудникам; приоритетно — сотрудники отдела кабинета).
4. Если у рабочего места ещё нет отдела, он автоматически определяется по кадровой записи назначаемого сотрудника; если отдел уже задан, а сотрудник из другого отдела — интерфейс предупреждает о несоответствии (кадровый перевод выполняется на странице [Org Structure.md](./Org%20Structure.md) через приказ, не здесь).
5. Число сотрудников кабинета не может превышать вместимость; при достижении лимита кнопка назначения недоступна с подсказкой.
6. Снятие сотрудника с рабочего места — действие в том же списке.

## Состояния и edge cases

* **Empty**: карта филиала не создана — по центру страницы empty state блок с кнопкой «Создать карту филиала»; клик открывает модальное окно загрузки (Flow 1).
* **Loading**: анализ загруженной схемы может занимать время — прогресс-состояние «Анализируем карту…»; интерфейс блокируется до ответа.
* **Error**: ошибка анализа схемы — записи не создаются частично, интерфейс показывает ошибку и оставляет форму загрузки; нарушение бизнес-ограничений — тост с текстом ошибки.
* **Permissions**: операции требуют соответствующих прав на управление структурой; без прав на изменение карта доступна read-only.
* **Удаление**: удаление этажа/кабинета с назначенными сотрудниками — предупреждение и требование предварительно снять привязки.
* **Повторная загрузка схемы этажа**: поведение при перезаливке (пересоздание кабинетов vs. дозаливка) — уточняется, см. открытые вопросы во frontend-документе.

---

## Зависимости и ограничения

* Карта клиники, здания, этажи, кабинеты, рабочие места — ведутся в модуле управления структурой клиники.
* Сотрудники и их привязка к рабочим местам — модуль управления персоналом.
* Требования к подготовке файла схемы должны попасть в инструкцию для пользователя (подсказка в мастере загрузки).
* Все данные карты относятся к конкретному филиалу.
