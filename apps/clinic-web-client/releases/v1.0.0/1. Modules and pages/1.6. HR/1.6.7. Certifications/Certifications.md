# 1.6.7 Certifications (Аттестации)

## Спецификация страницы интерфейса

* **Название страницы:** Аттестации
* **Модуль:** HR (Human Resources)
* **Тип страницы:** Реестр (таблица) с агрегацией по сотрудникам
* **Основные роли:** Администратор / HR-менеджер, Руководитель
* **Маршрут:** `/hr/certifications`
* **Платформа:** веб-приложение медицинской системы
* **Статус документа:** Актуализировано

> Общие паттерны — см. `1.6.0. Overview`. Аттестации конкретного сотрудника также доступны в его эл. деле (1.6.4, таймлайн). Техническая реализация — во frontend-документе `1.6.7. Certifications` (Frontend).

---

## Назначение страницы и сценарии использования

Общеклинический реестр аттестаций — плановых, предстоящих и просроченных. Раздел отвечает на вопрос «кому и когда нужна аттестация» и позволяет управлять записями централизованно (преимущественно для врачей; специализация обязательна).

С помощью страницы пользователь может:

1. Видеть активные аттестации (запланированные, просроченные, не пройденные) с сотрудником, специализацией, периодом и статусом, а историю пройденных — на отдельной вкладке.
2. Фильтровать по статусу (запланирована/просрочена/не пройдена), отделу, специализации, периоду.
3. Создавать/редактировать/удалять аттестации и фиксировать результат «Пройдена» с новой категорией, датой и документом.
4. Переходить в эл. дело сотрудника.

---

## User Flows / Task Flows

### Flow 1. Контроль аттестаций
1. Пользователь открывает «Аттестации».
2. По умолчанию — сортировка по ближайшей дате; просроченные подсвечены.
3. Фильтрует по статусу/специализации/периоду.

### Flow 2. Создание / редактирование
1. «+ Добавить аттестацию» (или `⋯` → «Редактировать»).
2. Заполняет форму, сохраняет.

### Flow 3. Переход в дело
1. Клик по строке → эл. дело сотрудника, секция «Аттестации».

## Структура: Wireframes

### Общий layout
```
┌─────────────────────────────────────────────────────────────────┐
│  Аттестации                                  [+ Добавить]        │
├─────────────────────────────────────────────────────────────────┤
│  [Активные]  [Пройденные]                                        │
│  🔍 Поиск по сотруднику...                          [Фильтр ▾]   │
├──────────────┬────────────┬──────────────┬───────────────┬──────┤
│ Сотрудник    │ Отдел      │ Специализация│ Период        │Статус│
│ Иванов И.    │ Хирургия   │ Хирургия     │ 01–15.09.2026 │●Запл.│
│ Сидорова А.  │ Терапия    │ Терапия      │ 01–10.03.2026 │●Прср.│
└──────────────┴────────────┴──────────────┴───────────────┴──────┘
```

### Фильтры (Drawer)
| Поле | Тип |
|------|-----|
| Статус (вкладка «Активные») | Запланирована / Просрочена / Не пройдена |
| Отдел | Multi-select |
| Специализация | Select |
| Период | Date-range |

### Таблица
| Колонка | Содержание |
|---------|-----------|
| Сотрудник | Аватар + ФИО |
| Отдел | Отдел сотрудника |
| Специализация | Специализация |
| Категория | Квалификационная категория (если есть) |
| Период | Диапазон дат |
| Статус | Статус-бейдж |
| `⋯` | Контекстное меню |

Статус-бейджи: запланирована — зелёный; просрочена/не пройдена — красный (близкие к истечению — жёлтый акцент).

Вкладка «Пройденные»: те же колонки, но вместо периода — «Категория по результату», «Дата прохождения» и значок документа; сортировка по дате прохождения (новые сверху). Значок «Автоматически» у аттестаций, созданных системой по флажку в специализации врача. Пагинация и поиск работают на сервере на обеих вкладках.

Контекстное меню: Редактировать, Удалить, Открыть эл. дело. У просроченной и запланированной аттестации также «Отметить результат» (открывает форму со статусом «Пройдена»).

### Форма «Добавить/редактировать аттестацию»
| Поле | Тип | Обяз. |
|------|-----|:---:|
| Сотрудник | Select (поиск по ФИО, только врачи) | ✓ |
| Специализация | Select (специализации выбранного врача) | ✓ |
| Период | Date-range | — |
| Статус | Запланирована / Не пройдена / Пройдена («Просрочена» ставит система и в форме не предлагается) | ✓ |
| Категория по результату | Select; появляется при статусе «Пройдена» | ✓ при «Пройдена» |
| Дата прохождения | Date; при статусе «Пройдена» | ✓ при «Пройдена» |
| Документ | Select из личных документов врача; при статусе «Пройдена» | — |
| Новый сертификат | Переключатель: «Бессрочный» / «Назначить следующую аттестацию по сроку»; при втором варианте дата окончания сертификата; при «Пройдена» | ✓ при «Пройдена» |

При создании из эл. дела сотрудника поле «Сотрудник» предзаполнено и read-only. При выборе «Пройдена» показывается подсказка: категория врача по специализации будет обновлена, а если у специализации включено автоматическое планирование, следующая аттестация назначится сама.

## Состояния и edge cases

* **Empty:** «Аттестаций нет» (+добавить); по фильтру — «Ничего не найдено».
* **Loading:** скелетон строк; спиннер на сохранении.
* **Error:** блок ошибки + «Повторить»; toast при сбое.
* **Offline:** таблица из кэша; управление заблокировано, toast.
* **Permissions:** без права на управление — режим чтения; без права на просмотр сотрудников — раздел недоступен.
* **Edge cases:** аттестация без периода — статус задаётся вручную; авто-перевод «запланирована → просрочена» по наступлении даты, страница обновляется при возврате на вкладку и раз в несколько минут; просроченную можно перевести в «Не пройдена» или «Пройдена» либо перенести срок; аттестации только для врачей; если пройденных аттестаций нет — «История пуста».

## Interaction & Animation

* Статусные вкладки — fade-смена; сортировка/фильтр — мягкий скелетон при обновлении.
* Drawer — slide-in; форма — fade+scale.
* Hover строки — подсветка, `⋯`; удаление с подтверждением.
* Toast — выезд, авто-скрытие 3–5 с.

---

## Зависимости и ограничения

* Справочники специализаций и категорий ведутся самим модулем HR. Просроченный сертификат специализации (в зависимости от настройки Management) блокирует запись к врачу на услуги по этой специализации.
* Связь с 1.6.4 (таймлайн в деле) и 1.6.1 (виджет «предстоящие аттестации»).
* Специализация обязательна.

---

## Acceptance criteria

* Реестр показывает сотрудника, специализацию, период и статус аттестации; сортируется по ближайшей дате.
* Фильтрация по статусу, отделу, специализации и периоду работает.
* Пройденные аттестации вынесены на отдельную вкладку с пагинацией, поиском и фильтрами.
* Просроченные аттестации визуально выделены.
* Форма требует сотрудника, специализацию и статус; период необязателен; при статусе «Пройдена» обязательны категория и дата прохождения.
* Клик по строке открывает эл. дело сотрудника.
* Управление доступно только при соответствующем праве.
* Состояния empty / loading / error / offline / permissions обрабатываются корректно.
