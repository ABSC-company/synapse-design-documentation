Компонент «Электронная очередь» — фиксированный правый блок на страницах модуля Регистратуры.

Он может занимать всю доступную высоту контента или сочетаться с соседним компонентом в одной обёртке, например с календарём.

Основная структура компонента:

- Header
  - Название очереди, например: «Регистратура. Окно 3».
  - Список окон точки очереди, из которого пользователь выбирает текущее рабочее окно — выбор занимает окно за сотрудником (`PATCH /windows/{id}/occupy`, `ElectronicQueueModule.md` §6.9): пока окно не выбрано явно, сотрудник не участвует в обслуживании общей очереди. Если у точки только одно окно (типичный случай приёма врача) — занятие может происходить автоматически при открытии рабочей страницы, без отдельного выбора в списке.
  - Две основные кнопки‑триггеры:
    - приостановка очереди (`PATCH /windows/{id}/pause`/`resume`) — временная пауза именно занятого окна, не всей точки: остальные окна той же точки продолжают вызывать из общей очереди;
    - вызов следующего посетителя — берёт следующий номер из **общей** очереди точки (не «своей» очереди окна — очередь одна на все окна точки, номера, уже взятые другим окном, в списке ожидания не показываются, `ElectronicQueueModule.md` §6.9).

- Body
  - Список карточек текущей электронной очереди.
  - Каждая карточка содержит:
    - порядковый номер;
    - время становления в очередь;
    - время ожидания.
  - Отдельная свёрнутая по умолчанию секция «Пропущенные» — талоны в статусе `no_show`, вызванные на это окно/точку сегодня, но не подошедшие; не участвуют в основном списке ожидания (`ElectronicQueueModule.md` §6.9), поэтому не смешиваются с обычными карточками. Секция показывает только талоны, привязанные к визиту (`visit_to_clinic_id` заполнен) — только у них есть кнопка «Вернуть в очередь»: талон без визита (выданный на киоске, никогда не превратившийся в приём) после `no_show` — действительно конец истории, для него секция показывает лишь сам факт неявки, без действия. Каждая карточка секции — номер талона, ФИО пациента.
  - «Вернуть в очередь» (`POST /electronic-queue/tickets/{id}/recall`, `ElectronicQueueModule.md` §6.11) — открывает Booking Scheduler (`1.3.2. Booking Page`) на сегодняшней дате, отфильтрованный на врача этого приёма, со свободными и занятыми ячейками графика; пользователь кликает свободную ячейку — модуль переносит время соответствующей консультации на выбранный слот и возвращает **этот же** талон в статус `waiting` (не выпускает новый — талон, привязанный к визиту, живёт до его завершения, §6.11) — карточка сама перемещается из «Пропущенных» обратно в основной список ожидания этого же виджета, встаёт в общий FIFO-порядок точки очереди наравне с остальными — не занимает чьё-то место.

Требования к оформлению:

- Блок должен быть визуально отделён от основного контента страницы.
- Заголовок очереди должен быть чётким и легко читаемым.
- Кнопки управления очередью должны быть доступны и заметны.
- Список карточек должен быть компактным, но информативным, с акцентом на номер и текущее ожидание.

Варианты использования:

- Полноэкранный вид: когда «Электронная очередь» занимает всю высоту доступной контентной области.
- Комбинированный вид: когда компонент расположен рядом с дополнительным модулем, например календарём, в единой обёртке.

Этот виджет — лишь часть более широкой системы электронной очереди, включающей киоск выдачи талонов ([Kiosk Ticket Issue Page.md](../../../1.15%20Module%20Electronic%20Queue/Kiosk%20Ticket%20Issue%20Page.md)) и публичные мониторы табло в масштабе точки очереди целиком либо отдельного окна — в т.ч. монитор у кабинета врача, технически тот же тип табло ([Queue Display Monitors.md](../../../1.15%20Module%20Electronic%20Queue/Queue%20Display%20Monitors.md)). Оба документа — в отдельном модуле «Электронная очередь» (`1.15`).
