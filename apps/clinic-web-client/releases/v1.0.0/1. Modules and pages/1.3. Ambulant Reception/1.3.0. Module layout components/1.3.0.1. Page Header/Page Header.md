# Page Header

## Описание компонента

**Page Header** — заголовочный блок, расположенный в верхней части контентной области страницы на всю ширину. Компонент разделён на две части:

- **Левая часть**: заголовок страницы с названием текущей секции или модуля.
- **Правая часть**: две основные кнопки-триггеры для управления пациентами и их визитами.

---

## Кнопка «Зарегистрировать пациента»

Предназначена для создания новой записи пациента в системе.

### Task Flow

#### Этап 1. Инициация регистрации

1. Пользователь нажимает кнопку **Зарегистрировать пациента** в Header.
2. Открывается модальное окно регистрации.
3. Пользователь выбирает тип гражданства:
   - Гражданин Республики Узбекистан
   - Иностранный гражданин

#### Этап 2. Поиск существующего пациента

Над компонентом Tab располагается **поле для поиска** пациента с дебаунсингом:

- **Для граждан РУз**: поиск по PINFL или FaceID
- **Для иностранных граждан**: поиск по MRZ (Machine Readable Zone)

#### Этап 2.1. Захват документа: 3 способа (панель распознавания)

Под полем поиска располагается **панель распознавания документа** — вместо единственной кнопки сканирования доступны **3 равнозначные кнопки** захвата изображения документа (паспорт/ID/метрика):

1. **Сканировать документ** — захват через подключённый к рабочему месту документ-сканер (десктоп).
2. **Загрузить изображение** — загрузка готового файла (фото/скан) с компьютера или из галереи устройства.
3. **Сфотографировать документ** — захват через веб-камеру рабочего места (десктоп) либо через камеру устройства (планшет).

Выбор способа не влияет на дальнейшую логику — все три кнопки приводят к одному и тому же результату: изображение документа передаётся на бекенд Synapse, который пересылает его во внешний AI-сервис распознавания (MRZ/фото/подпись) и возвращает уже распознанные поля. Фронтенд не обращается к AI-сервису напрямую.

**Task Flow панели:**

1. Сотрудник регистратуры выбирает один из трёх способов.
2. Система показывает индикатор загрузки/распознавания («Распознаём документ…»).
3. При успехе — связанные поля автоматически заполняются (страна, гражданство, пол, ФИО, дата рождения, серия/номер документа, MRZ) в разделе «Персональные данные» (Этап 3); фотография гражданина и графическая подпись с документа извлекаются отдельно и попадают на бекенд вместе с самим сканом при финальной отправке формы (Этап 4) — на этом шаге они не показываются оператору отдельными превью.
4. Сотрудник **проверяет и при необходимости правит** автозаполненные поля вручную (обязательный шаг — MRZ/OCR может ошибаться, особенно на транслитерации имён).
5. Кнопка **«Очистить»** рядом с превью документа — сбрасывает загруженный скан и все автозаполненные из него поля, возвращая форму в состояние ручного ввода (не затрагивает поля, которые оператор уже успел отредактировать вручную после автозаполнения — уточняется дизайном интеракций).
6. Кнопка **«Заполнить вручную»** — всегда доступна и пропускает распознавание; форма остаётся полностью пустой для ручного заполнения.

**Индикация результата распознавания:**

- Успех — превью загруженного документа + toast «Данные распознаны»;
- MRZ не найден (документ без MRZ либо резервный сценарий ещё не готов) — toast «MRZ не найден, заполните данные вручную», форма остаётся пустой, это штатный случай, не ошибка;
- Ошибка AI-сервиса (недоступен, таймаут) — toast с ошибкой и кнопкой «Повторить», форма доступна для ручного заполнения без блокировки регистрации.

**Устройство ввода: десктоп vs планшет** (см. также §15a `EMCModule.md` и раздел «Планшетная версия» ниже в этом документе):

- **Десктоп** — «Сканировать документ» работает через интеграцию с подключённым сканером рабочего места (TWAIN/SANE/производитель-специфичный драйвер — интеграция на уровне ОС/десктоп-агента, не браузерный API); «Сфотографировать» — через веб-камеру рабочего места (`getUserMedia`).
- **Планшет** — кнопка «Сканировать документ» скрывается (внешнего сканера нет); доступны только «Сфотографировать» (камера самого планшета) и «Загрузить изображение» (файл/галерея планшета).

#### Этап 3. Заполнение данных пациента

Форма содержит три раздела, доступные через компонент **Tab**:

##### **Раздел 1: Персональные данные** (обязательно)

- **MRZ паспорта** (опционально) — автозаполняется при сканировании
- **Идентификационный номер/Серия паспорта** (опционально)
  - Поддерживаемые типы: номер/серия паспорта, загран. паспорта, метрика
- **Ф.И.О** (обязательно) — три отдельных инпута: фамилия, имя, отчество
  - Отчество опционально
- **Дата рождения** (обязательно)
- **Пол** (обязательно)
- **Страна** (обязательно)
- **Город/Провинция** (обязательно)
- **Адрес** (обязательно для граждан РУз, опционально для иностранцев)
- **Контактная информация** (минимум 1)
  - Тип: номер телефона, почта, социальная сеть
  - Значение: номер, адрес почты, ссылка на профиль
- **Фото пациента** (опционально)
- **Категория пациента** (опционально) — выбор из предопределённого списка

##### **Раздел 2: Физиологические данные** (полностью опционально)

- **Рост**
- **Вес**
- **Индекс массы тела** — рассчитывается автоматически на основе роста и веса
- **Группа крови**

##### **Раздел 3: Особые данные** (полностью опционально)

- **Хронические заболевания**
- **Инвалидность**
- **Аллергии**

#### Этап 4. Проверка дубликатов

5. После заполнения формы система **автоматически выполняет поиск дубликатов**.
   - Поиск выполняется перед финальным подтверждением регистрации.

#### Этап 5. Подпись соглашения об обработке ПДн

6. Если дубликаты не найдены, форма (Раздел 1–3, Этап 3) отправляется — `POST /emc/patients` создаёт ЭМК (§6.10.4 `EMCModule.md`). Скан/фото документа, переданный в этот запрос, становится **обязательным**: без изображения документа (`passport_scan`, либо готовые `passport_photo`/`graphic_sign_photo`) регистрация не завершается — это отличие от прежней версии дизайна, где скан был опционален.
7. Сразу после создания ЭМК открывается модаль **«Согласие об обработке персональных данных»** (см. полный юридический текст документа: `synapse-architecture-documentation/.../2.1.0. EMC module/Personal Data Processing Agreement (PDPA) Template.md`).

##### 5.1 Превью документа

- Модаль показывает **превью документа** — тот же текст соглашения, но с уже подставленными значениями пациента (ФИО, дата рождения, адрес, название клиники и филиала, дата, сотрудник регистратуры) — `GET /emc/patients/:id/pdpa/render`. Место подписи в превью до подписания остаётся пустым.
- Над/под превью — три кнопки действия: **«Скачать»**, **«Подписать»**, **«Подписать на планшете»**.

##### 5.2 Кнопка «Скачать» → печать → повторный захват (3 кнопки)

1. Оператор нажимает **«Скачать»** — система формирует PDF (`GET /emc/patients/:id/pdpa/download`) и открывает системное окно печати браузера/ОС.
2. Документ печатается на принтере рабочего места.
3. Пациент подписывает документ на бумаге собственноручно и отдаёт его сотруднику регистратуры.
4. Модаль подписания переходит в состояние **«Оцифруйте подписанный документ»** — вместо трёх кнопок захвата шага 2.1 показываются те же **3 кнопки** в контексте уже подписанного бумажного документа:
   - **Сфотографировать документ** (веб-камера/камера планшета);
   - **Загрузить документ** (файл);
   - **Отсканировать документ** (подключённый сканер, десктоп-версия).
5. После захвата изображение отправляется на бекенд: `POST /emc/patients/:id/pdpa` (`file`, `source: "scan" | "photo" | "upload"`) — сохраняет документ и **автоматически** запускает сверку подписи через Sign-AI относительно эталонной подписи с документа пациента (`graphic_sign_photo`, извлечённой на Этапе 2.1) — см. `EMCModule.md` §9.8.2–§9.9.
6. Кнопка **«Очистить»** рядом с превью загруженного скана соглашения — сбрасывает загруженный файл, позволяя переснять/перезагрузить заново без повторной печати.

##### 5.3 Кнопка «Подписать» / «Подписать на планшете» (цифровая подпись)

1. Оператор (или сам пациент, если экран/планшет развёрнут к нему) нажимает **«Подписать»** (мышь/тачпад/палец на touch-экране рабочего места) либо **«Подписать на планшете»** (внешний планшет для подписи со стилусом, десктоп-версия) или подписывает прямо на экране планшетного клиента.
2. Открывается область подписи **прямо поверх превью документа** (в месте `{{ sign__picture__1 }}`, см. шаблон соглашения) — пациент расписывается стилусом/пальцем.
3. **Синхронно с процессом подписи** превью документа отображает уже нанесённые штрихи в реальном времени (canvas поверх превью, без задержки на сервер) — пациент/оператор видят, как формируется подпись, до завершения.
4. По завершении (кнопка **«Готово»**/поднятие пера дольше N сек — уточняется UX) штрихи рендерятся в изображение (PNG, прозрачный фон) и отправляются: `POST /emc/patients/:id/pdpa` (`file` = PNG подписи, `source: "digital_signature"`) — тот же роут и та же автоматическая сверка Sign-AI, что и в сценарии 5.2.
5. Кнопка **«Очистить подпись»** — доступна пока штрихи ещё не отправлены; стирает canvas и позволяет расписаться заново без повторного открытия модали.

##### 5.4 Результат сверки и завершение

8. Если сверка (§9.9) вернула `decision: "match"` — соглашение помечается `is_verified: true` автоматически, модаль закрывается, показывается toast «Соглашение подписано и проверено».
9. Если `decision: "uncertain"` либо Sign-AI недоступен (`502 AI_SERVICE_ERROR`) — соглашение сохраняется как есть (`is_verified: false`), оператору показывается предупреждение «Не удалось автоматически подтвердить подпись» с кнопками **«Подтвердить вручную»** / **«Переснять/переподписать»**. Регистрация при этом **не блокируется** — см. п. 10 ниже.
10. Если `decision: "not_match"` — предупреждение «Подпись не совпадает с образцом в документе», предлагается переснять документ или переподписать; оператор может подтвердить вручную при явной уверенности (например, известная деформация подписи из-за травмы руки).
11. Сотрудник регистратуры может **завершить регистрацию без загрузки соглашения** и оформить его в течение дня в ЭМК пациента (кнопка **«Пропустить, подписать позже»** в модали).
12. ЭМК пациента, в котором нет верифицированного соглашения об обработке ПД, доступна только в рамках текущей клиники на срок **1 сутки**. Пациент при обращении в другую клинику может подписать и загрузить документ у другой регистратуры.

#### Этап 6. Завершение регистрации

13. После подписания соглашения (или явного пропуска, п. 11):
    - Система подтверждает регистрацию.
    - ЭМК пациента считается зарегистрированной — становится доступным немедленное создание записи на услугу (кнопка «Запись пациента к врачу», открывающая тот же поток, что и ниже в этом документе, уже с найденным пациентом).

#### Сценарии блокировки

14. Подтверждение регистрации (создание ЭМК, `POST /emc/patients`) блокируется в следующих случаях:
    - Обнаружен дубликат пациента в системе (`409 PATIENT_ALREADY_EXISTS`).
    - Не приложен скан/фото документа личности (теперь обязателен, п. 6).
    - В обоих случаях показывается **Toast-уведомление** об ошибке, регистрация не выполняется.
15. Модаль подписания соглашения (Этап 5) **не блокирует** завершение регистрации — ЭМК уже создана к моменту её открытия (п. 6–7); лимит **10 минут** на подписание из предыдущей версии дизайна снят, так как несёт риск повторного визита в очередь ради простой печати документа — вместо этого действует правило «1 сутки, только текущая клиника» (п. 12).

#### Edge cases: подпись соглашения

- **Пациент отказывается подписывать** — оператор нажимает «Пропустить, подписать позже» (п. 11); ЭМК создана, ограничение доступа — см. п. 12.
- **Печать не удалась** (нет бумаги, принтер офлайн) — toast с ошибкой печати и предложением подписать цифровым способом (§5.3) вместо повторной попытки печати.
- **Веб-камера/сканер недоступны или не подключены** — соответствующая кнопка недоступна (disabled) с подсказкой при наведении «Устройство не обнаружено»; доступные способы остаются активными.
- **Пациент подписывает, но случайно закрывает вкладку/обновляет модаль до отправки** — незавершённый canvas-набросок не сохраняется; при повторном открытии модали область подписи пуста, требуется расписаться заново.
- **Повторная попытка после `not_match`/`uncertain`** — новый файл загружается через `PUT /emc/patients/:id/pdpa/:pdpaId`, полностью замещая предыдущий и запуская сверку заново (не создаёт вторую запись соглашения).
- **Двое сотрудников одновременно открывают модаль подписания для одного пациента** (редкий кейс, несколько окон регистратуры) — сервер принимает первую успешную загрузку; вторая попытка получает актуальное состояние (`is_verified`) при следующем открытии карточки.

### Планшетная версия сайта — как выглядит

На планшетном клиенте (сенсорный экран, без подключённого стационарного оборудования) весь процесс воспроизводится теми же экранами, но источники устройств переопределяются на встроенные возможности самого планшета:

| Функция десктоп-версии | Аналог на планшете |
|---|---|
| Сканер документов (Этап 2.1) | Недоступен — кнопка «Сканировать документ» скрыта; остаются «Сфотографировать» (встроенная камера) и «Загрузить изображение» |
| Веб-камера рабочего места (Этап 2.1, 5.2) | Встроенная камера планшета (то же самое приложение съёмки, без внешнего устройства) |
| Принтер (Этап 5.2, кнопка «Скачать») | Кнопка «Скачать» доступна, если к планшету подключён (Bluetooth/Wi-Fi) принтер регистратуры; если печать физически невозможна на конкретном рабочем месте — кнопка скрывается по feature-флагу филиала, остаются только цифровые способы подписи |
| Отдельный планшет для подписи со стилусом (Этап 5.3, «Подписать на планшете») | Кнопка «Подписать на планшете» не нужна отдельно — сам планшетный клиент **является** этим планшетом: кнопка «Подписать» сразу открывает область подписи на весь экран, ввод — пальцем или стилусом планшета напрямую по стеклу |
| Захват после печати (Этап 5.2, 3 кнопки) | Те же «Сфотографировать» / «Загрузить» доступны; «Отсканировать» скрыта по той же причине, что и в Этапе 2.1 |

Дополнительно для планшетной версии:

- Область подписи (§5.3) занимает большую часть экрана в портретной/альбомной ориентации, чтобы обеспечить комфортный росчерк пальцем — это не уменьшенная копия десктоп-виджета, а отдельный полноэкранный режим модали.
- Кнопки капчи документа (Этап 2.1, 5.2) укрупнены под тач-таргет (минимум 44×44px) и расположены с увеличенными отступами по сравнению с десктоп-версией.
- Ориентация экрана не блокируется — модаль подписи адаптируется к повороту устройства пациентом при подписании.

## Кнопка «Запись пациента к врачу»

Предназначена для создания новой записи (визита) пациента к врачу.

### Task Flow

#### Этап 1. Инициация записи

1. Пользователь нажимает кнопку **Запись пациента к врачу** в Header.
2. Открывается модальное окно создания визита пациента.

#### Этап 2. Поиск пациента

3. Пользователь ищет пациента по:
   - Ф.И.О
   - ID пациента
   - PINFL
   - FaceID
   - QR-код
   - MRZ (если пациент — иностранный гражданин)

#### Этап 3. Обработка активных визитов

4. Система показывает **активные незавершённые визиты** пациента в клинику (если они существуют).

5. **Если выбран активный визит**:
   - Разблокируются формы визита к врачу
   - Разблокируется загрузка файлов

6. **Если активного визита нет или нужен новый**:
   - Визит в клинику формируется **автоматически** на основе данных из первого визита к врачу
   - Разблокируются формы визита к врачу
   - Разблокируется загрузка файлов

#### Этап 4. Заполнение формы визита

Пользователь заполняет **форму визита к врачу** с интеллектуальной фильтрацией:

- **Степень срочности (Триаж)** (обязательно)
  - Выбор из предопределённого списка приоритетов

- **Направление** (опционально)
  - При выборе направления — список врачей автоматически фильтруется под это направление
  - Влияет на доступный список врачей

- **Врач** (обязательно)
  - При выборе врача — направление подставляется автоматически на основе специальности врача
  - Влияет на доступный список услуг

- **Услуга** (обязательно)
  - После выбора врача список услуг фильтруется
  - Содержит только те услуги, которые может предоставить выбранный врач

- **Дата и время** (необязательно)
  - Выбор даты и времени визита к врачу (букинг)
  - Если не указывается система создаёт запись в ближайшее свободное время в графике приёмов

#### Этап 5. Сохранение записи

8. Пользователь сохраняет запись — визит к врачу создаётся в системе
