# 1.12.2. Department Warehouse Page

## Спецификация страницы интерфейса

- Страница: Склад отделения (исследования)
- Модуль: Исследования (лабораторные/инструментальные)
- Позиция в модуле: Вторая страница
- Тип страницы: Мини-склад + заказы на пополнение + списание
- Основные роли: Лаборант, сотрудник кабинета инструментальных исследований
- Статус документа: Draft
- Связанная бэкенд-документация: `WarehouseModule.md` §4.11, §4.15–4.17, §7 (сценарии 1, 3), §8.4, §9, §12.6–12.7; `BookingModule.md` §6.13 (автосписание при завершении услуги); `ServicesModule.md` §4.2 (расходники услуги)

> Модуль «Исследования» ранее содержал одну страницу (`1.12.1. Studies Queue Page`). Страница склада **полностью повторяет** `1.13.2. Department Warehouse Page` модуля «Сестринский персонал» (а через неё — `1.11.3. Department Warehouse Page`): тот же потребительский склад отдела, те же макеты и состояния. Ниже описано только то, что специфично для исследований.

## Назначение страницы и сценарии использования

Сотрудник лаборатории или кабинета инструментальных исследований ведёт внутренний мини-склад своего отдела: видит остатки расходных материалов, оформляет заказы на пополнение, списывает испорченное/просроченное и контролирует, как остаток уменьшается автоматически при выполнении исследований.

Ключевые задачи:

1. Просмотреть остатки склада отдела.
2. Оформить заказ (запрос на пополнение) со склада-источника.
3. Списать товар (код маркировки) вручную с указанием причины.
4. Видеть, что остаток уменьшился автоматически после завершения исследования.

## User Flows / Task Flows для страницы

### Flow 1. Остатки и заказ на пополнение

Идентично `1.11.3`, Flow 1–3: вкладка «Остатки» → «Создать запрос» → выбор товаров и количества → заказ появляется во вкладке «Мои запросы».

### Flow 2. Ручное списание

Идентично `1.13.2`, Flow 2: у строки остатка кнопка «Списать» → модаль (код маркировки/партия, причина) → `POST /warehouse/marking-codes/:id/write-off`.

### Flow 3. Автосписание при реализации услуги

1. В `1.12.1. Studies Queue Page` сотрудник завершает исследование (услуга переходит в `completed`).
2. Backend **автоматически** списывает расходники этой услуги (`service_consumables`) со склада отдела из зарезервированного остатка — пользователь на странице склада ничего не делает.
3. При следующем открытии (или при возврате фокуса на страницу) остатки отображаются уже уменьшенными; изменившиеся строки на 2–3 секунды подсвечиваются.
4. Если по услуге расходников нет (`have_consumables = false`), остаток не меняется.

## Структура: Wireframes

Идентична `1.13.2` («Остатки» с колонкой «Действие → Списать», вкладка «Мои запросы», модали создания запроса и списания). Отличия:

- заголовок страницы «Склад отделения» с подзаголовком — название отдела пользователя (например, «Лаборатория»);
- при подсветке строк после автосписания — бейдж «Автосписание» рядом с изменённой строкой до следующего обновления.

## Визуал: High-Fidelity mockups

Визуальные правила — как в `1.13.2` (кнопка «Списать» — «опасное» действие, приглушённый красный/серый). Дополнительно обязательно отрисовать:

1. Строку остатка с подсветкой и бейджем «Автосписание».
2. Пустое состояние «Склад вашего отделения не найден».

## Состояния и edge cases

Общие состояния — как в `1.11.3` / `1.13.2`. Дополнительно:

| Состояние | Ожидаемое поведение |
|---|---|
| permissions | Без `WAREHOUSE_MARKING_CODE_MANAGE` кнопка «Списать» скрыта; без `WAREHOUSE_STORAGE_REQUEST_CREATE` скрыта «Создать запрос» |

### Edge cases

1. Расходников для исследования не хватило на момент завершения — автосписание выполняется в пределах доступного остатка (поведение задаёт глобальная настройка Management Module, `1.9.1`); остаток не уходит в минус.
2. Остаток обновился автоматически, пока открыто модальное окно списания — список кодов в модали перезапрашивается, количество ограничивается актуальным остатком.
3. Услуга без расходников — склад не затрагивается.

## Interaction & Animation

Как в `1.13.2`; подсветка строк после автосписания — плавное затухание за 2–3 секунды.

## Зависимости и ограничения

### API

Общие с `1.11.3` и `1.13.2`: `GET /warehouse/storages?type=consumer&department_id=`, `GET /warehouse/products`, `POST/GET /warehouse/storage-requests`, `GET /warehouse/marking-codes`, `POST /warehouse/marking-codes/:id/write-off`. Автосписание вызывается Booking Module (`dispenseReservation`) при завершении услуги, отдельного роута для этой страницы нет.

### Роли и права

Те же, что в `1.13.2`: `WAREHOUSE_STORAGE_GET`, `WAREHOUSE_STORAGE_REQUEST_CREATE`, `WAREHOUSE_STORAGE_REQUEST_GET`, `WAREHOUSE_MARKING_CODE_MANAGE`.

## Acceptance criteria

1. Всё, что верно для `1.13.2. Department Warehouse Page`, верно и здесь.
2. Страница доступна из модуля «Исследования» рядом с очередью исследований.
3. После завершения исследования расходники услуги списываются автоматически, остаток склада отдела уменьшается и виден без ручных действий.
4. Заказ на пополнение и ручное списание работают так же, как у сестринского модуля.
5. Действия скрыты/задизейблены без соответствующих прав.
