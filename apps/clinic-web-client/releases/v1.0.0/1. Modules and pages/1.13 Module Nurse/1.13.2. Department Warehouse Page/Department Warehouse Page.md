# 1.13.2. Department Warehouse Page

## Спецификация страницы интерфейса

- Страница: Склад отделения
- Модуль: Сестринский персонал (амбулаторный)
- Позиция в модуле: Вторая страница
- Тип страницы: Мини-склад + запросы на пополнение/списание
- Основные роли: Медицинская сестра/брат (амбулаторный)
- Статус документа: Draft
- Связанная бэкенд-документация: `WarehouseModule.md` §4.11, §4.15–4.17, §7 (сценарии 1, 3), §8.4, §9, §12.6–12.7

> Та же страница по данным, что и `1.11.3. Department Warehouse Page` врачебного модуля (тот же потребительский склад отделения) — здесь описаны только отличия и добавленное действие «Списание». Общая структура (вкладки «Остатки»/«Мои запросы», создание запроса на пополнение) не повторяется, см. `1.11.3`.

## Назначение страницы и сценарии использования

В дополнение к тому, что доступно врачу (просмотр остатков, запрос на пополнение, `1.11.3`), медицинская сестра/брат может **списать** товар/код маркировки со склада отделения — расход материала в ходе процедур, порча, истечение срока годности и т.п. — без создания дополнительного запроса на пополнение как единственного способа уменьшить остаток.

Дополнительная ключевая задача страницы:

1. Списать количество товара (код маркировки) со склада отделения с указанием причины.

## User Flows / Task Flows для страницы

### Flow 1 (общий с `1.11.3`). Просмотр остатков и создание запроса на пополнение

См. `1.11.3. Department Warehouse Page`, Flow 1–3 — идентично.

### Flow 2. Списание

1. На вкладке «Остатки», у строки товара — кнопка **«Списать»** (видна только в сестринском модуле, отсутствует в `1.11.3`).
2. Открывается модаль: выбор конкретного кода маркировки (если товар представлен несколькими кодами/партиями на складе отделения — выбор из списка, с датой поступления/сроком годности для ориентира) либо количества (для агрегатных кодов), поле «Причина списания» (обязательно).
3. Подтверждение → `POST /warehouse/marking-codes/:id/write-off { reason }` (`WarehouseModule.md` §8.4) — статус кода меняется, остаток склада отделения уменьшается.
4. Toast «Списано», строка остатка обновляется точечно.

Общий layout страницы: идентичен `1.11.3` + кнопка «Списать» в таблице остатков.

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Кнопка «Списать» — визуально «опасное» действие (например, приглушённый красный/серый акцент), поскольку необратимо уменьшает остаток без возможности отмены через UI.
2. Остальное — см. `1.11.3`.

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Таблица остатков с кнопкой «Списать» в каждой строке.
2. Модаль списания (с выбором кода маркировки и причиной).
3. Toast после успешного списания.

## Состояния и edge cases

См. общие состояния `1.11.3`. Дополнительно:

| Состояние | Ожидаемое поведение |
|---|---|
| permissions | Кнопка «Списать» скрыта без `WAREHOUSE_MARKING_CODE_MANAGE` — сестра без этого права видит страницу в том же виде, что и врач (`1.11.3`) |

### Edge cases

1. Товар представлен несколькими кодами маркировки с разными сроками годности — модаль списания предлагает выбрать конкретный код, с приоритетом более старого/скоро истекающего в начале списка (FEFO-подсказка, не строгое ограничение).
2. Попытка списать больше, чем есть на складе отделения, — блокируется на клиенте (нельзя ввести количество больше остатка).
3. Списание последней единицы товара — остаток обнуляется, строка не удаляется из таблицы (нулевой остаток — валидное состояние, не повод скрывать позицию).

## Зависимости и ограничения

### API

Все роуты — общие с `1.11.3` (§«Зависимости и ограничения» → «API»), плюс:

1. `POST /warehouse/marking-codes/:id/write-off` — ручное списание кода маркировки (`WarehouseModule.md` §8.4, §4.11).

### Роли и права

Общие с `1.11.3`, плюс:

1. `WAREHOUSE_MARKING_CODE_MANAGE` — доступность кнопки «Списать» (единственное право, которым сестринская роль отличается от врачебной на этой странице).

> ⚠️ Открытый вопрос к бэкенду: `WAREHOUSE_MARKING_CODE_MANAGE` (`WarehouseModule.md` §9, код `8301`) — общее право ручного списания/разделения **любого** кода маркировки в системе, не ограниченное складом отделения. Держатель этого права технически может списать код на главном складе или складе другого отделения, а не только на своём. Аналогично открытым вопросам по кабинетам (`1.12.1`) и складу врача (`1.11.3`) — стоит решить, требуется ли серверное ограничение «только свой склад отделения» для этой роли, или это остаётся ограничением на уровне UI (страница показывает только коды своего склада, но право само по себе шире).

## Acceptance criteria

1. Всё, что верно для `1.11.3. Department Warehouse Page`, верно и здесь (общие данные и функциональность).
2. Кнопка «Списать» доступна у каждой позиции остатка, с обязательным указанием причины.
3. Списание уменьшает остаток склада отделения и видно точечно без перезагрузки страницы.
4. Кнопка «Списать» скрыта у ролей без `WAREHOUSE_MARKING_CODE_MANAGE`.
