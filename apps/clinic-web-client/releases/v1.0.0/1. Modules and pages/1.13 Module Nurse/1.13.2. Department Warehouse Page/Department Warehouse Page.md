# 1.13.2. Department Warehouse Page

## Спецификация страницы интерфейса

- Страница: Склад отделения
- Модуль: Сестринский персонал (амбулаторный)
- Позиция в модуле: Вторая страница
- Тип страницы: Мини-склад + запросы на пополнение/списание
- Основные роли: Медицинская сестра/брат (амбулаторный)
- Статус документа: Draft
- Связанная бэкенд-документация: `WarehouseModule.md` §4.11, §4.15–4.17, §7 (сценарии 1, 3), §8.4, §9, §12.6–12.7

> Та же страница по данным, что и `1.11.3. Department Warehouse Page` врачебного модуля (тот же потребительский склад отделения) — здесь описаны только отличия и добавленное действие «Списание». Общая структура (вкладки «Остатки»/«Мои запросы», создание запроса на пополнение) не повторяется, см. `1.11.3`.

## Назначение страницы и сценарии использования

В дополнение к тому, что доступно врачу (просмотр остатков, запрос на пополнение, `1.11.3`), медицинская сестра/брат может **списать** товар со склада отделения — расход материала в ходе процедур, порча, истечение срока годности и т.п. — без создания дополнительного запроса на пополнение как единственного способа уменьшить остаток.

Дополнительная ключевая задача страницы:

1. Списать количество товара по партии со склада отделения с указанием причины.

## User Flows / Task Flows для страницы

### Flow 1 (общий с `1.11.3`). Просмотр остатков и создание запроса на пополнение

См. `1.11.3. Department Warehouse Page`, Flow 1–3 — идентично.

### Flow 2. Списание

1. На вкладке «Остатки», у строки товара — кнопка **«Списать»** (видна только в сестринском модуле, отсутствует в `1.11.3`).
2. Открывается модаль: выбор партии (если товар представлен несколькими партиями на складе отделения — список по сроку годности: серия, срок, остаток, ближайшая по сроку первой), количество (по умолчанию весь остаток партии), поле «Причина списания» (обязательно).
3. Подтверждение → `POST /warehouse/stock/write-off { productId, storageId, batchId, reason, quantity }` (`WarehouseModule.md` §8.4) — остаток партии склада отделения уменьшается, в ленте движения появляется списание.
4. Toast «Списано», строка остатка обновляется точечно.

Общий layout страницы: идентичен `1.11.3` + кнопка «Списать» в таблице остатков.

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Кнопка «Списать» — визуально «опасное» действие (например, приглушённый красный/серый акцент), поскольку необратимо уменьшает остаток без возможности отмены через UI.
2. Остальное — см. `1.11.3`.

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Таблица остатков с кнопкой «Списать» в каждой строке.
2. Модаль списания (с выбором партии, количеством и причиной).
3. Toast после успешного списания.

## Состояния и edge cases

См. общие состояния `1.11.3`. Дополнительно:

| Состояние | Ожидаемое поведение |
|---|---|
| permissions | Кнопка «Списать» скрыта без `WAREHOUSE_STOCK_MANAGE` — сестра без этого права видит страницу в том же виде, что и врач (`1.11.3`) |

### Edge cases

1. Товар представлен несколькими партиями с разными сроками годности — модаль списания предлагает выбрать партию, ближайшая по сроку годности стоит первой (подсказка, не строгое ограничение).
2. Попытка списать больше, чем есть на складе отделения, — блокируется на клиенте (нельзя ввести количество больше остатка).
3. Списание последней единицы товара — остаток обнуляется, строка не удаляется из таблицы (нулевой остаток — валидное состояние, не повод скрывать позицию).

## Interaction & Animation

См. `1.11.3`. Модаль списания — тот же паттерн fade-in/out, что и модаль создания запроса на пополнение.

## Acceptance criteria

1. Всё, что верно для `1.11.3. Department Warehouse Page`, верно и здесь (общие данные и функциональность).
2. Кнопка «Списать» доступна у каждой позиции остатка, с обязательным указанием причины.
3. Списание уменьшает остаток склада отделения и видно точечно без перезагрузки страницы.
4. Кнопка «Списать» скрыта у ролей без `WAREHOUSE_STOCK_MANAGE`.
