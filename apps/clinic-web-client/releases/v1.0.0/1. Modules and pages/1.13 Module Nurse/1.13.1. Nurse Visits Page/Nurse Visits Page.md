# 1.13.1. Nurse Visits Page

## Спецификация страницы интерфейса

- Страница: Визиты в клинику (по врачам)
- Модуль: Сестринский персонал (амбулаторный)
- Позиция в модуле: Первая страница — точка входа
- Тип страницы: Список, только просмотр
- Основные роли: Медицинская сестра/брат (амбулаторный)
- Статус документа: Draft
- Связанная бэкенд-документация: `BookingModule.md` §4.1–4.2, §12.2–12.3; `HRModule.md` §5.1, §5.4 (справочник врачей отделения); `EMCModule.md` §6.15.3 (политика доступа: визиты видны, карточка ЭМК — нет), §12.4–12.5 (выгрузка медицинских документов)

## Назначение страницы и сценарии использования

Обзор визитов в клинику, сгруппированных/фильтруемых по врачу — медицинская сестра/брат сопровождает приём, готовит кабинет, ассистирует, но не ведёт консультацию, не подписывает медицинские документы и **не открывает карточку ЭМК пациента** (это исключительно врачебная/регистратурная зона, `1.11.2. Consultation Page`, `1.3.2. Patient EMC Card`, `EMCModule.md` §6.15). Страница нужна, чтобы видеть загрузку врачей отделения и то, что происходит в клинике в течение дня, без прав на создание/изменение записи (это зона регистратуры, `1.3.3. Booking`) и без доступа к медицинской карте — единственное действие над завершённым визитом здесь — скачать уже готовые результаты (медицинские документы), не заходя в ЭМК.

Ключевые задачи страницы:

1. Показать визиты в клинику (и вложенные визиты к врачам) на выбранную дату.
2. Дать фильтр по конкретному врачу отделения.
3. Показать статус каждого визита.
4. Дать скачать результаты (медицинские документы) по визиту, у которого они уже есть — без перехода в карточку пациента.

## User Flows / Task Flows для страницы

### Flow 1. Просмотр визитов

1. Медсестра/брат открывает страницу «Визиты в клинику».
2. Фильтр «Врач» по умолчанию — «Все врачи отделения» (справочник — врачи с основной должностью в том же отделе, что и у текущего сотрудника, `HRModule.md` §5.1).
3. Таблица загружает визиты в клинику за выбранную дату: `GET /booking/visits-to-clinic?date_from=&date_to=` (`BookingModule.md` §12.2), с вложенными `service_visits[]`; при выбранном враче — фильтруется по `doctor_id` вложенных записей на клиенте либо через `GET /booking/visits-by-services?doctor_id=` (см. открытый вопрос ниже).
4. Каждая строка (или под-строка визита к врачу) показывает: время, пациента, врача, услугу, статус.

### Flow 2. Фильтр по врачу

1. Выбор конкретного врача в фильтре сужает список до его визитов.
2. Счётчик визитов по врачу виден прямо в выпадающем списке (например, «Ахмедова Д. (5)») — по желанию дизайна, не обязательное требование.

### Flow 3. Скачивание результатов визита

1. У визита, по которому уже есть хотя бы один медицинский документ (визит к врачу в статусе `completed` или близком к нему), в строке доступна иконка/кнопка «Скачать результаты».
2. Клик скачивает ZIP с медицинскими документами (PDF) и их файлами-приложениями по визиту — тот же архив, что доступен из карточки ЭМК (`EMCModule.md` §12.4–12.5), но без перехода в саму карточку: медсестра/брат не видит остальные данные пациента (диагнозы, аллергии, историю), только результат конкретного визита.
3. У визита без документов (ещё не начат/нет результатов) — кнопка отсутствует или неактивна с подсказкой «Результаты ещё не готовы».

Общий layout страницы:

1. Слева: Sidebar в свёрнутом состоянии.
2. Сверху: **Page Header** — «Визиты в клинику», фильтр «Врач», селектор даты.
3. Контентная область: таблица визитов.

## Структура: Wireframes

### Toolbar

- Фильтр «Врач» (справочник врачей отделения, «Все врачи» по умолчанию).
- Селектор даты (по умолчанию — сегодня).

### Таблица визитов

| Колонка | Описание |
|---|---|
| Время | Время визита к врачу |
| Пациент | ФИО, MRN |
| Врач | ФИО врача |
| Услуга | Наименование |
| Статус | Бейдж: `reservation`/`paid`/`processing`/`completed`/`canceled`/`refunded` |
| Действие | «⬇ Скачать результаты» — только если по визиту есть медицинские документы; иначе прочерк/неактивная иконка |

Единственное действие над строкой — скачивание результатов (Flow 3); переход в чужую консультацию или в карточку ЭМК пациента по-прежнему невозможен ни при каких правах (`EMCModule.md` §6.15.3).

## Визуал: High-Fidelity mockups

Визуальные правила:

1. Статус-бейджи — общая палитра системы.
2. Единственный интерактивный элемент в таблице — иконка скачивания в колонке «Действие»; строка сама по себе не кликабельна, никакого перехода/редактирования нет (в отличие, например, от `1.3.3. Booking`, где строки кликабельны и ведут к действиям) — визуально страница по-прежнему читается как read-only реестр с одним точечным действием, а не как полноценный интерактивный список.

Визуальные компоненты, обязательные к отрисовке в mockups:

1. Toolbar с фильтром «Врач» и датой.
2. Таблица визитов с разными статусами и разными врачами, включая строки с активной и неактивной иконкой скачивания.
3. Состояние loading/empty.

## Состояния и edge cases

| Состояние | Ожидаемое поведение |
|---|---|
| loading | Skeleton таблицы |
| empty | Нет визитов на выбранную дату/врача — «Нет визитов» |
| error | Ошибка загрузки — сообщение + «Повторить» |
| offline | Просмотр — только из кэша |
| permissions | Страница скрыта без права на просмотр визитов Booking Module |

### Edge cases

1. В отделении нет ни одного врача (структурная аномалия) — фильтр «Врач» пуст, показывается сообщение вместо таблицы.
2. Визит отменён — остаётся видимым в списке дня со статусом `canceled`, не скрывается; иконка скачивания у такого визита неактивна (документов нет).
3. У медсестры/брата нет права `EMC_MEDICAL_DOCUMENT_GET` — колонка «Действие» пуста для всех строк (не просто неактивна точечно — весь функционал скачивания скрыт).

## Interaction & Animation

1. Смена врача/даты — таблица перезагружается со skeleton-состоянием.
2. Скачивание результатов — индикатор загрузки на самой иконке на время запроса, без блокировки остальной таблицы.

## Acceptance criteria

1. Страница показывает визиты в клинику на выбранную дату.
2. Фильтр «Врач» ограничен врачами отделения текущего сотрудника.
3. Страница read-only в части записи — нет создания/редактирования визитов и нет доступа к карточке ЭМК пациента; единственное действие над строкой — скачивание уже готовых результатов визита (при наличии документов и права `EMC_MEDICAL_DOCUMENT_GET`).
4. Все состояния (loading/empty/error/offline/permissions) реализованы согласно таблице выше.
